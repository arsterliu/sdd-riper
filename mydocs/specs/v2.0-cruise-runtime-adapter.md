## Summary
为 `sdd cruise` 增加真实执行适配的第一层能力：生成 Claude Code Dynamic Workflows 可复用入口，并为巡航过程建立 SDD 自己的 run ledger。该实现不调用模型 API，不把 SDD 做成通用 agent 平台。

## Invocation
用户要求按照“Claude workflow adapter + SDD run ledger，不做全量自研执行器”的建议执行。

## Requirement Review
目标不是自研跨模型 runtime，也不是替 Claude Code 写 workflow script，而是让已有宿主 agent loop 可以更可靠地接入 SDD 控制面。Claude Code 的 Dynamic Workflows 由 Claude Code 自己生成和执行；SDD 只提供 prompt 引导、状态机和 run ledger。

## Findings
当前 `sdd cruise` 已支持 `--engine auto|prompt|local-loop|claude-code|codex|opencode`，但只输出 prompt 级 adapter 信息。项目没有 `runs` 产物目录，也没有 run ledger API。Console 详情页已经展示 gate/cruise/challenge/backtrack，但不能展示巡航轮次和停止原因。

## Open Questions
Claude Code Dynamic Workflows 的公开文档说明 workflow 是 JavaScript script，Claude 会按用户提示或 `ultracode` 生成并交给 runtime 执行。因此 SDD 不应该写 `.claude/workflows/` 文件；更合理的边界是输出一段包含 `ultracode:` 和 SDD loop contract 的 prompt。

## Assumptions
首版不接模型 API。`local-loop` 先作为 ledger-backed prompt loop 补偿，不负责自动调用模型。run ledger 是 SDD 产物投影，不替代 Spec / Design / Plan / Execute Log / Learning。

## Confirmed Requirement
实现 `sdd cruise` 的 workflow/runtime 第一阶段落地：支持 `--emit-claude-prompt` 输出 Claude Code ultracode/workflow prompt；支持 `--record-run` 写入 `<docs-root>/runs/<spec>.cruise.jsonl`；Spec 详情和 Console API 可以读取最新 cruise run 状态；README/GUIDE/SKILL 说明真实能力边界和降级策略。

## Innovate Options
<!-- Lite may skip Innovate only with explicit reason, e.g. Innovate: Skipped, Reason: <Chinese reason>. -->
Option A: 直接实现跨模型 Node runtime。Pros: 自动化程度最高。Cons: 需要模型 API、权限、成本控制和工具授权，偏离 SDD 控制面目标。
Option B: Claude workflow adapter + run ledger。Pros: 复用宿主原生 loop，SDD 保持控制协议和审计链，可观测性增强，风险可控。Cons: 首版仍不自动调用模型。
Selected: Option B。Rejected: Option A 因为复杂度和产品边界不匹配。
