## Summary
当前任务修复审查发现的四个控制面漂移：`resume` 的 Plan Gate 路由、`resume` 的失败 Challenge 路由、`status` 的 Plan Gate 健康检查、`archive` 索引读取旧 Review verdict。
任务采用 lite 模式，因为修改跨多个 CLI 命令但不改变持久化数据结构。
执行策略是先写回归测试复现四个问题，再将状态判断统一到现有 gate 语义，最后跑针对性测试和全量测试。

## Intake
requirement: 修复审查发现的前两个 P1 和前两个 P2：resume 必须遵守完整 Plan Gate；resume 必须把 FAIL_* Challenge 路由回修复而不是 archive；status 必须正确报告 Plan Gate 健康；archive index 必须读取 Challenge Verdict 而不是旧 Review section。

## Requirement Review
该请求是明确的缺陷修复，不扩展功能面。四个问题都属于控制面推导与当前治理语义不一致：`validate`/`next` 已经表达较严格的 Plan Gate 与 Challenge verdict 语义，但 `resume`、`status`、`archive` 仍有旧判断或弱判断。
修复不能引入新的兼容入口，也不能继续读取旧 `Review (Verdict|Summary)` 作为主要 verdict 来源。

## Findings
- 复现一：只填写 `Plan Approved By: agent:codex` 时，`resume` 输出 `PHASE_HINT: execute`，但 `validate --archive-ready` 报告缺少 `Approved At` 和 `Gate Evidence`。
- 复现二：completion-verification DONE 且记录 `Challenge Verdict: FAIL_CODE` 时，`resume` 输出 `PHASE_HINT: archive`，而 `next` 正确输出 `NEXT_ACTION: repair_execute_debug`。
- 复现三：同一个缺少 `Approved At` / `Gate Evidence` 的 Spec，`status` 输出 `Plan: OK`。
- 复现四：`archive` index 仍从 `Review (Verdict|Summary)` 提取 verdict，导致新归档任务的索引列可能为 `—` 或旧占位值。
- 相关 Learning：`v1.6-challenge-required-after-completion` 要求 Challenge 有效性必须检查证据完整性、时间新鲜度和失败 verdict；`v2.2-governance-config-simplification` 要求控制面语义收敛时删除旧入口而不是保留旧协议。
