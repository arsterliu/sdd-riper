## Technical Design

Selected Option / ADR: 选择方案 B（分步改造），先做 Review 合并和 AC Coverage 格式，再做 validate 交叉检查，最后更新文档和 Console。每步可独立验证，降低回归风险。
Requirement Traceability: AC-001 覆盖 AC Coverage 格式；AC-002 覆盖 validate 交叉检查；AC-003 覆盖 SKIPPED 门禁；AC-004 覆盖 Review 合并；AC-005 覆盖 PASS_WITH_CONCERNS 目标修正。
Impact Scope: 影响 validate.js、workflow.js、console.js、三个 spec 模板、SKILL.md、GUIDE.md、tests/commands.test.js。不影响 CLI 命令接口和运行时业务逻辑。
Context / Boundary: 改动限于 SDD 核心门禁逻辑和模板，不涉及宿主 agent 执行逻辑（TDD/BDD 执行纪律由 SKILL.md 指引）。
Domain Model: 无新领域实体。AC Coverage 是 Execute Log Step 的结构化子字段。
Architecture View: validate 作为归档门禁读取 Spec（AC 声明）+ Execute Log（AC Coverage 记录），做交叉检查。workflow 读取 validate issues 做 verdict 路由。
Data Model / Schema: Execute Log Step 新增 AC Coverage 字段（YAML list），格式为 `- AC-###: PASS|FAIL|SKIPPED [Scenarios: ...] [Test: path] [Method: ...]`。Completion Verification Step 为最后一个 Step，包含 Four-Axis Checklist 和 AC Coverage Summary。
Data Migration / Backfill: 旧 Execute Log 无 AC Coverage 字段，validate 渐进式处理——检测到无 Coverage 记录时不报 L1-L4 错误，只跳过交叉检查。
Interface Contract: CLI 接口不变（sdd validate --archive-ready）。validate 输出新增 AC 覆盖相关 issue 消息。
API Protocol: Console API 不变，前端阶段列表和门禁定义由 console.js 硬编码控制。
State / Concurrency: 无状态变更。
Failure Modes: AC Coverage 格式错误（无法解析）→ validate 跳过交叉检查并 warning；Test 路径不存在 → L3 拦截；SKIPPED 缺批准 → L1 拦截。
Security / Permission: 无安全影响。
Observability: Console 阶段列表移除 review，门禁定义增加 completionVerification。
Performance / Capacity: AC Coverage 解析是正则匹配，O(n) 其中 n 为 Execute Log 行数，性能无影响。
Compatibility / Rollback: 旧归档 spec 保留 Review Verdict 字段，新 validate 不检查该字段（渐进式）。回滚方式：恢复旧模板和 validate 逻辑。
Test Strategy: node:test 命令套件，新增 AC-001 到 AC-005 测试用例。
Risks / Trade-offs: 渐进式门禁意味着旧 Execute Log 永远不会触发 AC Coverage 检查——这是刻意设计，不是缺陷。后续可考虑在 discover 时提示 agent 填写 AC Coverage。
