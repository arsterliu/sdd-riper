# Design Note

## Design Note

Selected Option / ADR: 新建 src/core/ai-config-rules.js 作为生成块规则文本的单一数据源（19 条 canonical 规则 + 能力路由附录），_gen-ai-configs.js 改为消费组装；SKILL.md 保持手写，由新增 parity 测试强制与生成块一致。相比"内联 45 条规则"或"生成 SKILL.md"：消除双源漂移且不引入构建步骤。

Approach:
1. 新建 `src/core/ai-config-rules.js` 作为生成块规则文本的单一数据源，导出：
   - `CORE_RULES`（Hard rules，≤20 行）：16 条可读规则，合并重复语义；每条同时满足其钉住的测试正则；
   - `CAPABILITY_ROUTING`（能力路由附录，约 4 行）：承载被 visual-evidence-guidance / autonomy-guidance 测试钉住的视觉/Profile/Quality 细则（`ui-impact`、`visual-context-intent`、`visual discover`、`Figma.*URL`、不联网、不自动批准、不运行浏览器/截图 diff、`project-profile-revision`、exact reviewed digest 等）；
   - `ENTRY_POINTS`、`PROJECT_CONFIG`、各目标后缀提示（Claude/Cursor/Copilot reminder）。
2. `src/commands/_gen-ai-configs.js` 改为消费该模块：`sddBlock()` 组装 CORE_RULES + CAPABILITY_ROUTING + ENTRY_POINTS + PROJECT_CONFIG + 目标后缀。`reviewer-guidance.js` 的字符串继续经 ai-config-rules.js 或直接内联流入，保持生成块含 reviewer 授权指引。
3. 合并/保留要点（对照钉住契约）：
   - 生命周期行、`This project uses SDD-RIPER`、`AUTONOMY_MODE`、`Cruise Driver`、`Independent Review`、`Do not manually fill Challenge Evidence fields`、`- Mode: <mode>` 全部原样保留；
   - 4 条 "In every autonomy mode, X must stop" 合并为 1 条，一次性满足 autonomy-guidance 对 irreversible/scope expansion/new risk/platform permissions 的四条正则；
   - 3 条归档授权句合并为 1 条但保留三句钉住短语（request explicit archive authorization / must not construct archive authorization / audit declaration, not identity authentication）；
   - 能力路由细则收敛进 CAPABILITY_ROUTING 附录，从 Hard rules 里移除。
4. SKILL.md 保持手写；扩展/新增 parity 测试：断言 `CORE_RULES` 每条（及关键钉住短语）出现在 SKILL.md，防止 SKILL.md 与生成块漂移。SKILL.md 的 Non-Negotiable Rules 措辞如有不匹配处同步微调。

Impact Scope:
- 新增：`src/core/ai-config-rules.js`；`tests/ai-config-parity.test.js`（SKILL.md 与共享常量 parity）。
- 修改：`src/commands/_gen-ai-configs.js`（改为消费共享常量，块内容瘦身）；`tests/commands.test.js`、`tests/autonomy-guidance.test.js`、`tests/visual-evidence-guidance.test.js` 中针对 `src/commands/_gen-ai-configs.js` 源码做内容断言的 file list 加入 `src/core/ai-config-rules.js`；`SKILL.md` Non-Negotiable Rules 措辞对齐。
- 不改：根目录手写前言、REFERENCE.md、运行时门禁逻辑、已生成项目的旧托管块。

Interface / Data Impact:
- 模块接口：`ai-config-rules.js` 导出 `{ CORE_RULES, CAPABILITY_ROUTING, ENTRY_POINTS, PROJECT_CONFIG, suffixes }`，均为字符串数组；`_gen-ai-configs.js` 用它们拼 block。对外 CLI 无变化。
- 生成块对外形态：`Hard rules` 段 ≤20 行 + `Capability routing` 附录 + Entry points + Project configuration；字段标签仍英文、内容规则句英文（与现有一致）。

Compatibility:
- 测试契约兼容：所有被钉住的字符串均保留（合并行内含原短语），现有正则继续通过；仅"断言对象从 _gen-ai-configs.js 改为 ai-config-rules.js"的 file list 更新。
- 已生成项目兼容：旧托管块不受影响，下次 `sdd init` 刷新为瘦身版；upsert/幂等机制不动。
- 消费项目兼容：生成块仍自包含核心门禁，不依赖 REFERENCE.md（已在 Findings 确认其不可达）；引用仍指向 skill/CLI。

Risks:
1. 合并行需同时满足多条正则，措辞脆弱 → 以现有测试为唯一仲裁，改措辞后跑全量 jest；Design 已逐条核对（见 Approach）。
2. 4 个测试文件 file list 漏改会直接红 → 执行时逐处修改并跑 `npx jest tests/commands.test.js tests/autonomy-guidance.test.js tests/visual-evidence-guidance.test.js tests/governance-contract.test.js` 验证。
3. SKILL.md 若与合并后规范行不完全一致，parity 测试会要求微调 SKILL.md 措辞 → 属本任务范围内预期，执行时同步。
4. 既有的 reviewer-guidance.js 字符串路径：需确保生成块仍包含 `fresh task/plan authorization`、`Plan Approval alone is insufficient`、`subagent:<id>` 等（由 ai-config-rules.js 内联或 continue 从 reviewer-guidance 注入）。
5. ≤20 行的口径只约束 Hard rules 段；含附录后总块行数会多于 20，已在 AC 中明确定义口径。

Test Strategy:
- 回归：全量 `npx jest`。
- 定向：`tests/commands.test.js`（init/生成块/幂等）、`tests/governance-contract.test.js`（托管块刷新/字节幂等）、`tests/autonomy-guidance.test.js`、`tests/visual-evidence-guidance.test.js`。
- 新增：`tests/ai-config-parity.test.js`——遍历 `ai-config-rules.js` 的 CORE_RULES 与关键钉住短语，断言出现在 SKILL.md；断言生成块 Hard rules 行数 ≤20。
- 手动：临时目录 `sdd init --mode lite`，检查 4 个生成文件内容、块唯一性、`- Mode: lite`。
