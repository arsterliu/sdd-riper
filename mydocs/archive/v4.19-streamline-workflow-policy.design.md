## Technical Design

Selected Option / ADR: 采用版本化策略评估层。旧 Spec 走既有门禁和摘要解释；新 Spec 由统一策略对象输出风险等级、必需制品和审查节点，再映射到现有 RIPER gate/nextAction。避免修改历史授权事件无法还原的内容。
Requirement Traceability: AC-001 对应摘要；AC-002 对应风险；AC-003 至 AC-005 对应分层门禁；AC-006 对应旧任务兼容；AC-007 对应生成和安装入口。
Impact Scope: 修改任务生成、摘要与授权解析、风险判定、状态评估、验证和审查记录、技能安装包以及使用文档。现有 CLI 主命令、mode 与归档授权保留。
Context / Boundary: Spec 始终是控制面；独立 Design 与 Execute Log 在策略要求时才成为门禁。新策略不得调用旧的 mode 专属必填检查，旧策略不得调用新策略的宽松规则。
Domain Model: `workflow-policy` 缺失或为 `legacy-v1` 时解释为旧策略；`streamlined-v1` 使用声明式 Risk Signals。风险等级取声明信号与 mode 最低等级的较高者：micro=low、lite=medium、standard=high。高风险信号任一出现即 high；其余范围、方案取舍、多场景信号任一出现即 medium；`multi-step` 只强制独立 Execute Log。缺失、未知或与其他值并列的 `none` 阻塞 Plan。
Architecture View: 新建共享策略模块从 Spec 内容与 mode 生成 `{version,tier,signals,requiresDesign,requiresLog,requiresDesignReview,requiresCompletionReview}`；状态评估、validate、workflow 风险路由、discover 和 CLI 输出消费这一结果。策略分流置于现有各自入口，旧实现保持原状。新策略仍投影为 research/innovate/design/acceptance/plan/execute/completion/challenge/learning 九个 gate，未要求的 gate 标记通过。
Data Model / Schema: 新 Spec frontmatter 写 `workflow-policy: streamlined-v1`；`## Intake` 写必填 `Risk Signals:`，允许逗号分隔的固定枚举及独占的 `none`，枚举全集见 Spec 的 Risk Signal Catalog。低风险 Spec 必填需求与范围、Risk Signals、Acceptance、Verification、非空 Plan 和批准字段；`## Completion Verification` 用 Result、Verification、Verified At 记录新鲜结果。高风险的 Design Review 在 Spec 记录 Reviewed By、Reviewed At、Review Digest、Review Summary，摘要绑定独立 Design 正文及当时的 Intake、Research、Acceptance 输入；这些内容改变会使审查失效。中高风险或多步骤任务的 Execute Log 仅要求正式 Step、有效 Status、Verification、Timestamp 和最终 Result，未解决的 BLOCKED/BUGFIX_ESCALATED 与未经后续人工授权的 DEVIATED_MAJOR 均阻塞；若声明 AC-###，仍须逐项 Coverage。
Interface Contract: `discover` 默认使用 streamlined-v1，新增 `--workflow-policy legacy-v1` 供显式兼容创建；mode 与现有 CLI 命令名称保留。`next` / `status` / `autonomy inspect` 输出 RISK_TIER、必需制品和 Design Digest 以便审查。Challenge 继续用现有命令记录中高风险完成审查；低风险可以没有 Challenge。高风险 Design 审查者使用可审计身份和新鲜授权，Digest 变化使审查失效。
API Protocol: 无网络接口变化。CLI 参数和文本输出只做向后兼容增加；无策略字段时输出及门禁保持旧逻辑。
State / Concurrency: 授权事件仍在原 Spec 控制块；新摘要按策略版本选择，排除控制块和审查标签，规范化空白。新策略 scope 覆盖 Intake 与实际 Confirmed Requirement；risk 覆盖风险正文和 Risk Signals；Research 按 micro/lite/standard 真实章节组合。旧事件按旧摘要解释，不能声称具备新摘要强绑定。
Failure Modes: 风险声明缺失或非法、要求的制品缺失、Design 审查摘要过期、完成验证失败、独立审查缺失均形成结构化 blocker。低风险验证失败不能进入归档授权。用户后续改变范围或风险信号使授权变旧；Plan 改动继续要求重新激活。
Security / Permission: 新策略只读显式风险信号，避免否定句关键词误报；不可回滚信号仍触发专用人工停机。自动 reviewer 必须有当前 Spec 的新鲜授权；归档、Profile exact digest、E2E SKIPPED 和平台权限停机继续独立执行。
Observability: `next` 与 Console 消费同一 gate 和 tier，展示缺失制品、审查摘要与下一动作；Execute Log 记录本次改造的执行事实。
Performance / Capacity: 策略评估只读取当前 Spec 及已引用制品，单次线性解析；不遍历历史归档。
Compatibility / Rollback: 缺少策略字段按 legacy-v1 解释，旧授权摘要和旧制品不迁移、不重写。回退时停止新 Spec 的 streamlined-v1 创建并恢复旧默认；已创建的新 Spec 仍由其策略字段识别，不降级套用旧门禁。
Test Strategy: 先做纯函数和状态矩阵，再做 discover、next、validate、challenge、archive 与安装回归；覆盖空白归一、否定说明、三种 mode、低中高风险、旧事件持续有效及高风险 Design Digest 失效；最后运行全量 npm test。
Risks / Trade-offs: 一版内保留两套策略会增加少量分支，但把兼容边界固定在字段解析处；之后可依据真实使用量决定是否退役旧路径。
