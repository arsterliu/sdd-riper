## Learning Record

Source Spec:
Source Spec: mydocs/specs/v3.9-visual-verification-provider.md
Trigger: Execute 阶段的真实 Chromium 截图与浏览器缺失路径均暴露了仅靠协议单测无法发现的格式和分类偏差；Challenge 回退修复后也暴露出历史完成自检与最终完成自检并存时的审计阅读歧义。
Observed Problem: 初版 PNG 编码器写入了错误 chunk 布局；Playwright 实际截图使用 8-bit RGB 而非假定的 RGBA；浏览器缺失时缺截图校验一度先于浏览器分类触发；无效 PNG 一度没有落盘 BLOCKED Run。Challenge 回退后，早期完成自检仍作为历史事实保留，若未明确说明会被误读为重复的最终结论。
Root Cause: 把截图格式和错误优先级当作实现细节，以 synthetic 合同测试替代真实浏览器产物验证；比较阶段的异常边界没有与不可变 Run 提交边界对齐；同时没有将“回退后的新 completion-verification 覆盖旧结论”写成明确的审计规则。
Decision Rule: 新增视觉/二进制证据 Provider 时，必须在单元/合同测试之外保留最小真实运行时 fixture，至少覆盖 PASS、阈值 FAIL、可识别依赖缺失 BLOCKED 与损坏证据 BLOCKED；可识别的环境依赖错误优先于后续缺失产物错误；所有比较异常均须留下不伪造 PASS 的可审计 Run。若 Challenge 导致回退，保留旧 completion-verification 作为历史事实，在修复步骤之后追加一条新的 completion-verification，并明确它是唯一有效的最终自检；读取方以最后一条完成自检为准，绝不删除或改写旧执行事实。
Applies When: Playwright、浏览器、图片/PDF/压缩包、Reporter 附件或任何外部工具产物进入受控验证和不可变证据链时；以及任一 SDD Spec 在 Challenge 后回退到 Execute。
Does Not Apply When: 纯文本解析、无外部运行时产物的本地静态规则，或不产生审计结论的只读发现命令。
Recommended Action: 先用真实 fixture 观察格式、退出码和附件路径；将观察到的稳定格式写成 parser/normalizer 测试；把运行时异常在提交 Run 前转换为明确 BLOCKED/FAIL，并对基线、配置、合同和代码状态做 freshness 投影。Challenge 回退时，先追加修复 Step，再追加新的完成自检，并在 Learning Record 中记录 supersession 原则。
Evidence: tests/visual-verification-playwright.test.js；tests/visual-verification-readiness.test.js；mydocs/logs/v3.9-visual-verification-provider.execute.md Step 4、Step 6、Step 7 与最新 completion-verification；subagent:visual_context_task5_spec_review 的 PASS_WITH_CONCERNS 复核。
