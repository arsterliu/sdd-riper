# Technical Design

## Technical Design

Selected Option / ADR: Option C — 分组 Section 方案。将新增可观测性数据分为"状态概览"和"方法论 & Learning"两组 section，插入详情页现有 section 之间。

Requirement Traceability: CR-1 Risk Flags → AC-001, CR-2 Design Method → AC-002, CR-3 Learning Triggers → AC-003, CR-4 Blockers → AC-004, CR-5 Challenge Summary → AC-005

Impact Scope: 仅前端渲染层（`src/web/`），不涉及后端 API、数据模型、CLI 命令

Architecture View:
```
┌──────────────────────────────────────────────────┐
│  Spec Detail Page                                │
│                                                  │
│  ┌─ Status Strip (现有) ──────────────────────┐  │
│  │  Mode / Status / Phase / Updated           │  │
│  └────────────────────────────────────────────┘  │
│                                                  │
│  ┌─ Next Blocker (现有，增强) ───────────────┐  │
│  │  + Challenge Summary                       │  │
│  └────────────────────────────────────────────┘  │
│                                                  │
│  ┌─ 状态概览 (新增) ────────────────────────┐  │
│  │  Risk Flags 标签                           │  │
│  │  Blockers 列表                             │  │
│  └────────────────────────────────────────────┘  │
│                                                  │
│  ┌─ Phase Progress (现有) ──────────────────┐  │
│  │  Gate 列表                                 │  │
│  └────────────────────────────────────────────┘  │
│                                                  │
│  ┌─ Artifacts (现有) ───────────────────────┐  │
│  │  Spec / Design / Execute Log / Learning   │  │

│  │  Validate 按钮 + 结果                      │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

Context / Boundary: Console 前端是纯浏览器端 JS，数据从 `/api/specs/:id` 获取，所有新增字段已在后端 `parseSpec` 返回的对象中

Data Model / Schema:
- `spec.workflow.riskFlags: string[]` — 已有，如 `['security', 'migration']`
- `spec.workflow.designMethod: { applies: boolean, adr: boolean, methods: string[], focusFields: string[], notes: string[] }` — 已有
- `spec.workflow.blockers: string[]` — 已有
- `spec.workflow.challengeSummary: string` — 已有
- `spec.completion.learningArtifact.triggers: string[]` — 已有，如 `['BUGFIX in Execute Log', 'PASS_WITH_CONCERNS review verdict']`
- `spec.completion.learningRequired: boolean` — 已有

Interface Contract:
- 无新 API 端点
- 无新 URL 路由
- 前端从现有 `state.detail` 对象直接读取字段

Compatibility / Rollback:
- 新增 HTML section 默认 `hidden`，由 JS 按数据有无控制显示——回滚只需删除渲染函数和 HTML 容器
- CSS 新增 class 不影响现有样式
- 无 breaking change

Test Strategy:
- 单元测试：验证 `renderRiskFlags()`、`renderDesignMethod()`、`renderBlockers()`、`renderLearningTriggers()` 对空数据和非空数据的渲染
- 集成测试：Console server 返回的 spec 对象包含完整 workflow + completion 字段（已有测试覆盖）
- 手动验证：启动 Console 查看详情页新增 section 的展示效果

Risks / Trade-offs:
- 信息过载：详情页 section 从 4 增到 6，但每组信息密度低（标签/列表），整体可接受
- 前端 JS 体积增加：新增约 80 行渲染逻辑，可忽略
