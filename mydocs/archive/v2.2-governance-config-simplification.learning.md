## Learning Record

Source Spec:
mydocs/specs/v2.2-governance-config-simplification.md
Trigger:
用户在快速迭代阶段明确要求不保留历史兼容，并优先保持 SDD 控制面干净。
Observed Problem:
第一次实现把新语义加在旧语义旁边，导致配置读取、模板、CLI help、AI config、Console 和文档仍持续暴露旧入口。即使主路径推荐新字段，旧入口仍会被用户复制并继续污染控制面。
Root Cause:
控制面语义不是单点逻辑，而是横跨读取、校验、生成、提示、测试、文档和审计制品的协议。只改运行时行为会留下旧字段、旧参数或旧身份格式继续作为事实上的二级协议。
Decision Rule:
当用户确认当前阶段不需要历史兼容时，控制面改名或语义收敛必须删除旧入口，而不是保留 fallback、alias 或“兼容说明”。删除范围必须覆盖：配置读取默认值、CLI 参数、validate 规则、run ledger 字段、Console API/UI、模板、AI config、帮助文案、测试和当前任务制品。
Applies When:
修改 SDD 的 approval、gate、reviewer、cruise、mode、archive、learning 等控制面语义，并且项目处于快速迭代或尚未承诺外部兼容。
Does Not Apply When:
已有公开版本或用户明确要求兼容历史项目；这时需要单独设计迁移策略、弃用窗口和兼容测试。
Recommended Action:
实现前列出“读取入口、写入入口、生成入口、提示入口、测试夹具、文档入口、审计入口”清单；先写旧入口被拒绝或忽略的红灯测试；实现后用全文扫描确认旧名只剩负向测试或历史归档记录。
Evidence:
本任务最终将 `APPROVAL_POLICY`、`CRUISE_ENABLED`、`--driver` 作为唯一控制面；删除旧 policy fallback、旧 CLI alias、旧 run ledger 字段和旧 reviewer/approval 格式；`node --test tests\common.test.js tests\commands.test.js` 通过 145/145。
