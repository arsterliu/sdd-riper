## Summary
本任务为 SDD independent reviewer 提示补齐“授权衔接”表达，但不改变核心流程、不新增 reviewer 类型、不绑定特定 agent 平台。目标是让 CLI、生成的 AI 指令和项目文档明确：standard/lite 的 Research / Challenge 仍需要可审计 reviewer；可用身份保持 `subagent:<id>`、`external-agent:<id>`、`human:<name>`，micro Challenge 可用 `inline`；当使用 subagent、external-agent、review bot 或其他需要授权的自动化 reviewer 时，必须暂停并主动请求用户显式授权，不得跳过 gate 或伪造 reviewer。

## Intake
requirement: 为 SDD 的 independent reviewer 提示补齐授权衔接机制，但保持平台通用：不绑定 Codex；明确可审计 reviewer 类型为 subagent:<id>、external-agent:<id>、human:<name>，micro Challenge 可 inline；若使用 subagent、external-agent、review bot 或其他需要授权的自动化 reviewer，必须先取得用户显式授权；不得跳过 gate 或伪造 reviewer。

## Requirement Review
用户已经明确指出提示不能只支持 Codex，必须支持不同 agent 平台。因此本次不是新增平台适配层，也不是让 SDD 直接调度任何模型，而是把 reviewer evidence 的既有类型与“自动化 reviewer 工具可能需要授权”的执行约束接起来。`subagent` 代表同一宿主或同一工作流中的子代理；`external-agent` 覆盖第三方 agent、review bot、CI reviewer、其他 AI 工具或外部审核系统；`human` 覆盖人工审核。现有类型足够通用，新增 `review-bot:<id>` 等类型会造成 schema 膨胀，不纳入本次范围。

## Findings
- 代码已有 reviewer 类型定义：`src/commands/validate.js` 的 `isAuditableReviewer()` 和 `src/commands/challenge.js` 的 `isAuditableExecutedBy()` 均接受 `subagent:<id>`、`external-agent:<id>`、`human:<name>`，micro 额外允许 `inline`。
- `sdd challenge` 当前输出独立审核 prompt，但最终记录提示只给出 `--executed-by "subagent:<id>|external-agent:<id>|human:<name>|inline"`，没有说明自动化 reviewer 在某些宿主平台上需要显式授权。
- `sdd next` 当前只输出 validation blockers。缺 Challenge 时 blocker 会提示如何记录结果，但同样没有提示“若 reviewer 工具需要授权，必须先取得用户显式授权”。
- `AGENTS.md` / `SKILL.md` / 生成 AI config 已说明 reviewer 类型，但缺少“授权前置、不得伪造”的平台无关硬规则。

## Open Questions
无。用户已确认采用最小改造方案，并要求表达支持不同 agent 平台。

## 目标摘要
本任务为 SDD independent reviewer 提示补齐“授权衔接”表达，但不改变核心流程、不新增 reviewer 类型、不绑定特定 agent 平台。目标是让 CLI、生成的 AI 指令和项目文档明确：standard/lite 的 Research / Challenge 仍需要可审计 reviewer；可用身份保持 `subagent:<id>`、`external-agent:<id>`、`human:<name>`，micro Challenge 可用 `inline`；当使用 subagent、external-agent、review bot 或其他需要授权的自动化 reviewer 时，必须暂停并主动请求用户显式授权，不得跳过 gate 或伪造 reviewer。

## 最终方案
采用提示层最小改造：保留现有 reviewer 类型和校验语义，仅在 CLI、validation guidance、生成的 AI 指令与项目文档中补充平台无关的显式授权衔接规则。

## 关键约束
必须保持平台中立，覆盖 Codex、Claude、opencode、CI review bot、第三方 AI reviewer 等不同执行环境；必须保留现有 `subagent` / `external-agent` / `human` / micro `inline` 语义。

## 坑点与风险
当为门禁、授权、审计或 reviewer 证据新增统一提示时，必须先列出所有产生该门禁 blocker 的分支，包括 missing、empty、invalid、partial、stale 和 cross-command routing；每个分支都必须复用同一 shared guidance 或通过测试证明不会漂移。不能只覆盖主路径或已有失败路径。
