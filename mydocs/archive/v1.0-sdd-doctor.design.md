## Design Note

Approach: 新增 `src/commands/doctor.js`，由 `bin/cli.js` 注册为 `sdd doctor [project-dir]`。检查器静态读取仓库根的 `SKILL.md`、`INTEGRATIONS.md` 和 `src/commands/install-skill.js`，用明确前缀正则提取 `vendored/superpowers/...`、`protocols/...` 引用路径和 INTEGRATIONS 触点表的 vendored 路径，逐项做三类检查：(1) 引用路径是否在文件系统存在；(2) INTEGRATIONS 每个 skill 名是否在 SKILL.md 出现；(3) 被引用的顶层目录（protocols、vendored）是否都在 install-skill 的 `COPY_ENTRIES` 内。汇总结果逐项打印 OK/FAIL，存在 FAIL 时 `process.exit(1)`。
Impact Scope: 新增 `src/commands/doctor.js`；`bin/cli.js` 增加一条命令注册；`tests/commands.test.js` 增加用例。不改动任何现有命令、产物模板或核心逻辑。
Interface / Data Impact: 新增只读 CLI 子命令 `sdd doctor [project-dir]`，默认检查包根；无任何文件写入、无产物或配置变更、不访问网络。
Compatibility: 纯新增，向后兼容；不依赖 `.sdd-config`，不改变现有命令行为；无新增第三方依赖。
Risks: 正则提取引用可能漏报（路径写法不在预期前缀）或误报（SKILL 中提到但非真实引用）。缓解：只匹配明确的 `vendored/superpowers/<name>/` 与 `protocols/<file>` 前缀；用 PASS + FAIL 双向测试锁定行为；首版范围只覆盖三类高价值检查，README/GUIDE 链接检查留待后续。
Test Strategy: 单元 + e2e（execSync CLI）。PASS 场景：当前仓库运行 `sdd doctor` 退出 0、输出含 OK。FAIL 场景：在临时副本里删除一个被引用的 vendored/protocols 路径，运行后断言输出含 FAIL 且退出码非零。两个方向都覆盖即满足 AC-001/002/003。
