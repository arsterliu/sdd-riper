## Learning Record

Source Spec: mydocs/specs/v4.10-visual-target-guidance.md
Trigger: Skill 安装质量审查发现静态指南链接缺失；最终全量验证又发现旧测试仍按过时的文档职责要求 README 展示 CLI。
Observed Problem: 安装器 fingerprint 在未复制 REFERENCE.md 时仍可显示一致；README/GUIDE 已采用 AI-first 分层后，聚合测试仍要求两份文档逐字重复 Quality CLI 合同，导致全量红灯和一次 FAIL_PLAN。
Root Cause: 静态安装清单只验证已列白名单，没有验证已安装文档的相对链接闭包；文档测试按跨文件相同关键词设计，没有按 README、GUIDE、REFERENCE、TEAM-GUIDE 的职责分别建模。最终修复该陈旧测试时，Plan 又未先把该持久化 hunk 纳入边界。
Decision Rule: 发布静态文档包时，安装合同必须覆盖所有已发布相对链接目标，并让目标内容参与 fingerprint；测试多层指南时应使用按文件职责划分的矩阵，公共语义与 CLI/精确合同分别落在对应层。若全量验证需要持久修改一个被 Plan 明确排除的既有测试，必须先修订 Scope/Plan并重新取得授权，不能仅记作范围内 BUGFIX。
Applies When: 安装 Skill、插件或文档包中存在相对链接；同一事实分别投影到快速入口、场景指南、精确参考和团队指南；最终验证暴露任务前遗留测试与新文档分层冲突。
Does Not Apply When: 链接目标由宿主明确提供且安装合同验证其存在；测试只针对单一权威文档；失败仅来自临时环境且无需持久化仓库变更。
Recommended Action: 在安装器测试中从临时安装目录解析相对链接、检查 containment/存在性并篡改目标验证 fingerprint；在指南测试中建立 per-file responsibility matrix；执行前冻结 dirty-worktree 边界，遇到排除文件的必要持久修复先走范围扩展门禁。
Evidence: tests/commands.test.js 覆盖安装后 README/GUIDE 到 REFERENCE 的链接解析与 fingerprint 漂移；tests/quality-cli.test.js 覆盖 README 的 AI 导航职责和 GUIDE 的可选 CLI 自查职责；Execute Log Step 6、6A、7、8 记录 BLOCKED、TDD 修复、FAIL_PLAN 与重新授权。
