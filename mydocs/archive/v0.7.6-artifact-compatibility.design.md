## Technical Design

Selected Option / ADR: 采用“集中式兼容读取与顺序门禁”。在共享层定义历史 Markdown 的窄兼容范围和最后 formal Step，再让 gate facts、Validate、Workflow 与 Spec State 消费同一事实；不通过改写旧制品解决校验问题。
Requirement Traceability: Confirmed Requirement 的历史 Lite 读取对应 AC-001；completion 内旧 Summary 的可读兼容且不得形成正式 Coverage 对应 AC-002；completion 必须为最后 formal Step 对应 AC-003；standard/micro、新模板、archive 只读边界和 Console 文案对应 AC-004。
Impact Scope: `lib/common.js`、`src/core/workflow-gate-facts.js`、`src/core/spec-state.js`、`src/commands/validate.js`、`src/core/workflow.js`、`src/web/console.js` 及其 common/gate/workflow/state/command/governance 回归测试。
Context / Boundary: 输入是项目内的 Spec 和 Execute Log Markdown；输出是状态投影、校验结果和 Console 的完成门禁说明。兼容只接受 Lite 的明确历史嵌套结构及 completion 内精确的 `AC Coverage Summary:` 字段，不扫描或改写 archive。
Domain Model: formal Execute Step 是由 `scanExecuteLog()` 识别并按文件顺序排列的步骤；completion 是其中特定 header 的终态步骤；正式 AC Coverage 仅来自 `AC Coverage:` 结构。Lite Confirmed Requirement 有当前顶层和历史嵌套两种布局，选择结果是单一的字段内容视图。
Architecture View: `common` 解析 Markdown 并暴露最后 formal Step；`workflow-gate-facts` 使用共享解析形成 Research、completion 与 coverage 事实；`spec-state` 和 `validate` 基于这些事实决定归档门禁；`workflow` 使用同一 Confirmed Requirement 视图计算风险；Console 仅展示语义一致的说明。
Data Model / Schema: 不新增文件格式、数据库或 frontmatter 字段。新模板保持不含 `AC Coverage Summary:`；历史 Summary 仅作为 completion 内可忽略的展示块，不能被转换为 AC Coverage record。
Data Migration / Backfill: 不迁移、不回写、不修改任何 `mydocs/archive/` 制品。主动任务若 completion 后新增 formal Step，必须由执行者追加新的 completion-verification，而非自动修正日志。
Interface Contract: `scanExecuteLog()` 对 completion 内旧 Summary 具备窄兼容；共享“最后 formal Step”访问器决定 completion done；Lite Confirmed Requirement 优先顶层 `##`，仅在其为空时回退到 `## Research > ###`。standard 只读嵌套布局，micro 不参与 Research，普通 Execute Step 中的 Summary 保持非法边界。
API Protocol: 无网络 API 或 CLI 参数变化；`sdd validate --archive-ready`、`sdd next` 和状态查询将对 completion 后有 formal Step 返回阻断，而不是将旧 completion 视为完成。
State / Concurrency: 文件按单次读取快照解析，无共享可变状态；“最后”只由扫描顺序决定，不由 Timestamp 的最大值决定。Challenge 的时间顺序检查继续独立使用其既有 timestamp 规则。
Failure Modes: 缺少 completion、completion 后存在 Step、completion 缺少四轴字段、Lite 两种布局均缺字段，都必须给出阻断诊断。旧 Summary 位于普通 Step、无关标题或未知字段时仍按现有严格边界关闭步骤，不能扩大兼容。
Security / Permission: 不扩大路径、文件写入、自治或 reviewer 权限。旧 Markdown 的读取兼容不允许把任意内容升级为验证证据；archive 继续只读。
Observability: 通过稳定的 `completion-verification must be the last formal Execute Step` 类诊断、现有 `sdd next` 状态和测试断言展示门禁原因；不新增遥测。
Performance / Capacity: 仅对小型 Markdown 文件执行一次现有线性扫描；共享扫描结果/辅助函数避免每个消费者定义不同且更昂贵的回溯逻辑。
Compatibility / Rollback: 支持当前 Lite 顶层格式和限定的历史嵌套格式；支持 completion 内旧 Summary 的读取但不生成它。回滚代码即可恢复旧行为，不需要还原制品；不会兼容不在两个明确布局内的孤立三级标题。
Test Strategy: 先在 common/gate facts 中建立 RED 用例，再实现最小解析与顺序逻辑；覆盖 Lite 双布局、顶部优先、Summary 只读、普通 Step 严格性、completion 后 Step 阻断、standard/micro 不回归、CLI archive-ready/next 状态和 Console 文案；最终运行相关分组、`npm test` 与 `git diff --check`。
Risks / Trade-offs: 兼容范围过宽会让无关文本伪装成证据，过窄会继续阻断真实历史制品；因此只按 mode、固定标题层级和 completion header 启用兼容。新增“最后 Step”门禁会暴露旧主动日志的流程缺口，但这是防止陈旧完成证明被错误复用所必需的收紧。
