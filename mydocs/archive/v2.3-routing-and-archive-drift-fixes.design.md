## Design Note

Approach:
采用最小一致性修复：在 `resume` 与 `status` 内实现同等 Plan Gate 判断规则，避免继续使用“字段非空”作为 gate；`resume` 在 Challenge Evidence 完整且新鲜后，还必须读取 `Challenge Verdict`，若为 `FAIL_*` 则返回 challenge/修复路径而不是 archive；`archive` 索引优先读取新格式 `Challenge Verdict`，只有缺失时才 fallback 到旧 `Review (Verdict|Summary)`，用于历史归档。

不新增公共 CLI 参数，不改变 Spec 模板字段，不迁移历史 archive index。
Impact Scope:
影响三个 CLI 命令：`sdd resume` 的阶段提示、`sdd status` 的 Plan 健康提示、`sdd archive` 追加 index 行时的 Verdict 列。测试文件 `tests/commands.test.js` 增加回归覆盖。
Interface / Data Impact:
命令输入不变，输出语义更严格：无效 Plan Gate 将停留在 `research_or_plan`/WARN；失败 Challenge 将阻止 archive 路由。归档 index 的 Verdict 列会从 `Challenge Verdict` 字段读取 `PASS` / `PASS_WITH_CONCERNS` / `FAIL_*`。
Compatibility:
旧 Spec 仍可被读取。`archive` 对旧 Review section 保留 fallback，避免历史格式完全无法显示 verdict；但新格式始终优先。`resume/status` 会比之前更严格，可能暴露原本被误判为 OK 的未完成任务，这是预期修复。
Risks:
如果 Plan Gate 判断在多个文件中重复，未来仍可能漂移。当前为最小改动；若后续继续扩展，应抽取共享 helper。失败 Challenge 的 `resume` 阶段命名保持现有粗粒度 `challenge`，不引入新 `repair_*` phase，避免改动更多消费者。
Test Strategy:
使用 TDD：先在 `tests/commands.test.js` 写四个失败回归测试，再修改实现。针对性测试覆盖 `resume`、`status`、`archive` 三个命令；最后运行 `node --test tests/*.test.js` 和 `node bin/cli.js doctor D:\workspace\personal\sdd-riper`。
