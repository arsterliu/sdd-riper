## Design Note

Approach: 在 `src/commands/challenge.js` 增加只服务 Challenge 的 selector resolver。它先拒绝同时传入 `--spec` 与 `--name`；随后按优先级解析显式路径、版本化/裸名称或默认最新项。显式路径须存在，且其规范化词法路径与 `fs.realpathSync()` 的真实路径均在当前项目 docs root 的 `specs/` 下；所有候选都必须是未归档 Spec。resolver 返回唯一的绝对路径和相对项目路径。生成分支以该绝对路径调用现有 `workflow.analyzeSpec()`；记录分支复用同一结果；生成的回写示例固定附带规范化 `--spec` 相对路径，禁止再按 latest 选择。

Impact Scope: 仅修改 Challenge 命令、其 CLI 帮助/使用说明及命令级测试。`validate`、`next`、`cruise`、archive/reopen 和 `autonomy-store` 不改动。Spec 内容格式、Challenge verdict、backtrack 映射和 reviewer 证据字段保持现有契约。

Interface / Data Impact: `sdd challenge <project-dir> --spec <path>` 与 `--name <slug|versioned-slug>` 成为互斥 selector；未提供 selector 时保持当前默认最新活动 Spec 行为。任何 selector 错误、归档、缺失或项目外/真实路径逃逸均以错误退出且不写入文件。生成 prompt 的回写命令新增规范化 `--spec`，不新增制品格式或持久化数据字段。

Compatibility: 裸 `--name` 延续“同名任务的最高活动版本”语义；版本化 `--name` 和有效 `--spec` 精确定位。无 selector 的正常多活动选择保持 `common.findLatestSpec()` 的顺序。以前对归档或项目外 `--spec` 的宽松行为不作为兼容契约，将明确拒绝以修复误写缺陷。

Risks: 路径校验若只检查字符串会被 symlink 绕过，因此词法和 realpath 都必须检查。若生成和记录仍分别解析，最新 Spec 变化时会产生串写，所以必须只解析一次并传入 `analyzeSpec`。失败分支必须在读取或替换 Challenge 标签之前返回，保证零写入。

Test Strategy: 在 `tests/commands.test.js` 用多活动 fixture 覆盖版本化名称、裸名称、相对/绝对路径、生成/记录同目标、默认选择和未选中 Spec 不变；覆盖 selector 互斥、缺失、归档、目录逃逸与 symlink 逃逸的零写入。先运行目标命令测试，再运行完整 `npm test`；用临时 fixture 手动核验生成 prompt 中的回写命令带有精确目标。
