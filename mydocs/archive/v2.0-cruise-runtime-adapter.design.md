## Design Note

Approach: 在现有 `sdd cruise` 命令上增加两个可组合能力。`--emit-claude-prompt` 根据当前 workflow state 输出可直接交给 Claude Code 的 `ultracode:` prompt，引导 Claude Code 自己生成并执行 Dynamic Workflows；`--record-run` 把当前状态快照追加到 `<docs-root>/runs/<spec>.cruise.jsonl`。核心读写逻辑放入 `src/core/cruise-run.js`，CLI 只负责状态投影和用户输出。
Impact Scope: 影响 CLI `cruise` 命令、Spec index detail、Console API 返回体、文档和测试。不改变 validate/archive/review 的既有门禁，不修改已有 Spec/Design/Execute Log 格式。
Interface / Data Impact: 新增 CLI 参数 `--emit-claude-prompt`、`--record-run`、`--iteration <n>`。新增可选产物目录 `<docs-root>/runs/`，文件格式为 JSONL，每行一条 cruise iteration 记录。Spec detail 增加 `cruiseRun` 摘要字段。
Compatibility: 旧项目没有 runs 目录时按需创建；没有 ledger 时 `cruiseRun.count` 为 0，已有命令不受影响。不再写 `.claude/workflows/`，避免把 SDD prompt contract 误认为 Claude workflow script。
Risks: Claude Code Dynamic Workflows 的实际 script 生成和 runtime 执行归 Claude Code 负责；SDD 只输出触发提示和控制协议。ledger 只记录状态快照，不代表执行成功。
Test Strategy: 使用 node:test 通过临时项目验证 workflow 文件生成、JSONL ledger 写入、Spec detail 暴露最新 run 状态，并运行全量 `npm.cmd test` 回归。
