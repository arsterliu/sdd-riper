Observed Problem: 1) CJK 字符与正则 \b 词边界语义不兼容：混合交替式 /\b(public|external|公开|外部|api)\b/ 中中文分支永不匹配。2) specs 目录枚举只按 .md 过滤，vN.M-task.design.md/.execute.md 等附属制品被当 Spec 统计出幽灵条目并干扰 latest-spec 选择。另发现排查类任务的 Intake 缺陷定位可能不准：本次 Intake 声称缺陷在 Phase 2 中文正则，执行时经 git 历史核实真实缺陷在 Phase 1 Impact Radius（Phase 2 从未带 \b）。
Root Cause: \b 基于 ASCII 词字符定义，中文字符两侧不构成词边界；目录枚举谓词在各调用点各自实现、缺乏单一权威判定函数。
Decision Rule: 正则里 CJK 备选词永远不与 \b 共用——英文走 \b 分支、CJK 走独立无边界分支（双字词起步防单字误报）。目录枚举过滤统一收敛到 lib/common.js 的单一谓词（isAuxiliarySpecName），新枚举点必须复用而非内联照抄。排查类任务 Execute 时先用 git 历史/最小复现验证 Intake 的缺陷定位，不符时在 Step 1 披露实际位置再修。
Applies When: 给关键词扫描加中文支持时；新增任何遍历 specs/archive 目录的代码时；写「修复某缺陷」的 Spec 且缺陷定位来自静态阅读而非复现时。
Does Not Apply When: 纯英文文本的正则；已有统一谓词的调用点。
Recommended Action: 残留关注可开后续任务：spec-index.js active 列表的内联正则改为 path.basename + common.isAuxiliarySpecName，消除与 status/findLatestSpec 的双实现漂移（当前对非 v 前缀杂散文件如 scratch.design.md 两处行为不一致）。
