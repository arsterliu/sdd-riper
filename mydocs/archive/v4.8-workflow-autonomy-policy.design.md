## Technical Design

Selected Option / ADR:
采用单一三档自治模式 `AUTONOMY_MODE=auto|supervised|human`，取代 `APPROVAL_POLICY` 与 `CRUISE_ENABLED` 的组合。项目配置只提供新 Spec 的默认值；每个 Spec 冻结 effective mode，并通过 Spec 内受控、追加式 Autonomy Events 记录任务授权、Plan 激活、人工 Gate、模式切换和失效事实。CLI 只维护确定性状态与审计事实，宿主 AI 根据这些事实执行连续编排和子 Agent 调度。

拒绝继续组合旧开关，因为它无法表达任务级 reviewer/worker 授权，且会保留“agent 但仍不断暂停”的根因。拒绝只在 Spec 内设置模式，因为项目默认协作方式仍有价值，但项目配置不能单独充当当前用户授权。

Requirement Traceability:
- 三档场景：由 `autonomy-mode`、任务/Plan 授权事件和 human gate 事件表达。
- 自动子 Agent：由 authorization projection 输出允许的 actor types；宿主 AI 负责实际调度，Research/Challenge reviewer 保持只读与可审计。
- AI 引导：`next/resume/challenge/cruise/console` 输出统一结构化事实，生成 Agent 指令与人类文档沿用当前自然语言引导风格；创建 Spec 前，未显式指定自治模式时主动展示三档并推荐 supervised，已指定时只复述确认，项目默认值不得静默代选。
- 严格移除旧策略：配置读取、状态对象、新 ledger、API 和文档不再产生或消费 `APPROVAL_POLICY/approvalPolicy/CRUISE_ENABLED`；旧字段只触发迁移诊断。
- 安全边界：归档、Profile exact digest、E2E SKIPPED、不可逆动作、范围扩张、新风险与平台权限继续独立 fail-closed。

Impact Scope:
- 配置与初始化：`.sdd-config`、`lib/common.js`、`src/core/governance-contract.js`、`src/commands/init.js`。
- Spec 与策略核心：模板、discover、artifact snapshot、workflow gate facts、spec-state、workflow，以及新增 autonomy contract/state 模块。
- 命令与投影：新增 `sdd autonomy inspect|migrate|select|authorize|approve-gate`，调整 next/resume/validate/challenge/cruise/console、Console API、Web Console 和新 Run ledger 字段。
- Agent/人类说明：生成配置、SKILL、protocols、README、GUIDE、REFERENCE、TEAM-GUIDE。
- 回归：配置、CLI、状态矩阵、Gate facts、Console、归档/Profile/Verification/Challenge 防伪、文档分层和全量测试。

Context / Boundary:
SDD 是工作流控制面，不是模型执行器。它判断模式、授权有效性、下一动作和停机原因，并记录证据；宿主 AI 决定如何连续运行主 Agent、worker 与只读 reviewer。项目配置表达默认偏好，Spec 表达当前任务事实，用户原始授权表达许可，三者不得相互替代。

Domain Model:
- Project Autonomy Default：新 Spec 的默认模式，默认 `supervised`。
- Effective Autonomy Mode：冻结在 Spec 的 `auto|supervised|human`。
- Authorization Event：受控命令追加的授权、批准、激活、切换或失效事实。
- Scope Snapshot：由 task identity、Intake Requirement、Constraints、Scope 与 Risks 的规范化文本计算的 sha256；授权后这些输入变化会使授权 stale。
- Risk Snapshot：授权时已展示并接受的结构化风险集合；新增风险触发失效。
- Plan Snapshot：Plan 完成后计算的 digest；有界修订可在 Scope/Risk 未变化时追加 rebind 事件。
- Stop Reason：迁移、授权、Gate、范围、风险、重大偏差、预算、平台、Profile、Verification skip、Archive 等精确原因。

Architecture View:
```text
AI / User
   |
   v
CLI Commands -----> Autonomy Contract (config/schema/digest)
   |                         |
   v                         v
Spec Autonomy Events --> Autonomy State Resolver
                              |
               +--------------+--------------+
               v                             v
      Workflow / Gate Facts          Projection / Guidance
               |                    CLI / Console / Ledger
               v
      Host AI orchestration
      main / worker / read-only reviewer
```

Data Model / Schema:
`.sdd-config` 新合同：
```ini
AUTONOMY_MODE="supervised"
CRUISE_MAX_ITERATIONS="5"
```

Spec frontmatter 新增：
```yaml
autonomy-mode: "auto"
autonomy-mode-source: "project-default" # project-default | discover-override | active-switch
```

Spec 新增受控区块 `## Autonomy Control`。区块包含 `Autonomy Schema: 1` 与追加式事件；事件使用稳定英文标签：
```text
Event ID:
Event Type: task_authorization | plan_activation | gate_approval | mode_change | invalidation
Mode:
Gate:
Decision:
Scope Digest:
Risk Snapshot:
Plan Digest:
Authorized Actors:
Authorized By:
Authorized At:
Authorization Evidence:
Invalidated At:
Invalidation Reason:
```
auto 的 task authorization 允许 `main,worker,research-reviewer,challenge-reviewer`，其中 reviewer 始终只读；supervised 的 Plan Approval 与 autonomy authorization 是同次交互中的两个独立事件；human 为 Research、Innovate、Plan、Completion、Challenge/Repair 分别追加 gate 事件。Archive 继续使用既有独立字段和命令，不写入通用 autonomy event。

Data Migration / Backfill:
- 新 `sdd init` 写 `AUTONOMY_MODE=supervised`，不再写旧策略字段。
- 活动项目发现缺失/非法 `AUTONOMY_MODE`，或存在 `APPROVAL_POLICY/CRUISE_ENABLED` 时，返回 `SDD_AUTONOMY_MIGRATION_REQUIRED`。
- `sdd autonomy migrate --mode ...` 只按当前用户明确选择原子删除两个旧字段并写入新字段，不做值映射。
- 不复活 `GATE_POLICY/CRUISE_POLICY`，不迁移 archived Spec 或旧 JSONL。历史投影只展示原始历史字段，不参与新状态计算。

Interface Contract:
- `sdd init <dir> [--autonomy-mode auto|supervised|human]`
- `sdd discover ... [--autonomy-mode auto|supervised|human]`
- `sdd autonomy inspect <dir> --spec <path>`：只读输出 effective mode/source、Scope/Risk/Plan digest、authorization state、authorized actors、stop reason。
- `sdd autonomy migrate <dir> --mode <mode>`：严格迁移项目配置。
- `sdd autonomy select <dir> --spec <path> --mode <mode> ...authorization args...`：受控切换 active Spec；archive 拒绝。
- `sdd autonomy authorize <dir> --spec <path> --expected-scope-digest <digest> --authorized-by human:<name> --authorization-evidence <text>`：写 task 或 Plan 后持续授权，模式决定允许阶段。
- `sdd autonomy approve-gate <dir> --spec <path> --gate <gate> --expected-digest <digest> --authorized-by human:<name> --authorization-evidence <text>`：human Gate 事件。
- `next/resume/challenge/cruise/console` 统一投影 `AUTONOMY_MODE`、`AUTONOMY_MODE_SOURCE`、`AUTHORIZATION_STATE`、`AUTHORIZED_SCOPE_DIGEST`、`AUTHORIZED_RISK_SNAPSHOT`、`ACTIVE_PLAN_DIGEST`、`STOP_REASON`、`NEXT_ACTION`。

API Protocol:
Console JSON 的新 workflow 形状使用 camelCase：`autonomyMode`、`autonomyModeSource`、`authorizationState`、`authorizedScopeDigest`、`authorizedRiskSnapshot`、`activePlanDigest`、`authorizedActors`、`stopReason`。新响应和新 ledger 不再输出 `approvalPolicy` 或 `cruiseEnabled`。历史 ledger 读取器不得将旧字段合成为新模式。

State / Concurrency:
- inspect 计算当前 digest；写命令必须携带 expected digest，并在写锁内重新计算，避免确认后 Spec 变化造成 TOCTOU。
- 事件追加前校验 mode、active Spec location、身份、单行 evidence、event transition 和 digest；任何失败零写入。
- mode switch、Scope/Risk 变化、重大偏差会追加 invalidation；收紧模式立即停止持续权限，扩大为 auto 必须取得新任务授权。
- Plan 的有界修订只有在 Scope/Risk 未变化且未标记重大偏差时可追加 plan_activation/rebind；`FAIL_*` 名称本身不决定授权失效。
- 达到 `CRUISE_MAX_ITERATIONS` 输出 `budget_exhausted`，不再继续调度。

Failure Modes:
- 配置缺失/非法/含旧字段：`SDD_AUTONOMY_MIGRATION_REQUIRED` 或 `SDD_AUTONOMY_MODE_INVALID`。
- 无授权、Gate 缺失或 digest 过期：`SDD_AUTONOMY_AUTHORIZATION_REQUIRED`、`SDD_AUTONOMY_GATE_REQUIRED`、`SDD_AUTONOMY_AUTHORIZATION_STALE`。
- Scope/Risk 变化：`SDD_AUTONOMY_SCOPE_CHANGED`、`SDD_AUTONOMY_RISK_CHANGED`。
- 归档 Spec 切换模式、非法身份、空/多行 evidence、未知 Gate/Event：明确错误且零写入。
- 平台权限无法由 SDD 预授权；状态输出 `platform_permission_required`，由宿主处理。

Security / Permission:
- `.sdd-config` 不是当前用户授权；只有绑定 active Spec、digest、时间和原始 evidence 的 human event 才是授权事实。
- 普通 Plan Approval 不得推导 supervised autonomy authorization；必须分别记录。
- reviewer 身份 grammar、时间戳、只读职责和 `challenge --record-result` 防伪路径保持不变。
- auto 已授权风险不会重复打断；新增风险、Scope 扩张或不可逆动作 fail-closed。
- Archive、Profile exact digest、E2E SKIPPED、平台权限保持各自一次性门禁，不能被 autonomy event 覆盖。

Observability:
CLI、Console 和 ledger 输出相同 resolved mode/source、授权状态、actor allowlist、digest 与精确 stop reason。AI 指令要求先读取这些事实，再用现有自然语言风格说明“为什么停、确认什么、确认后到哪里”。不得把多个原因压成泛化 `human_required`。

Performance / Capacity:
配置和 Spec 文本规模很小，digest 与事件解析为线性文件扫描。仅在 workflow 状态计算时读取当前 active Spec；历史归档不做新 readiness。保留有界迭代预算，禁止无限自动循环。

Compatibility / Rollback:
- 活动项目采用严格断点迁移，不提供旧字段运行兼容；回滚代码前可从版本控制恢复旧配置。
- 已归档制品和旧 ledger 原样可读，不回填新字段、不重写引用、不重算门禁。
- 新字段删除的是未来投影合同；发布说明必须明确 Console/ledger 消费方的 breaking change。
- 实现分阶段落地时，先加入新合同与测试，再切换所有消费者，最后删除旧路径；任一步失败均保持旧历史文件不变。

Test Strategy:
- 单元：config/mode 合法性、digest 规范化、事件解析/transition、授权失效、stop reason。
- CLI 集成：init/discover/migrate/inspect/select/authorize/approve-gate、原子写入和错误码。
- 状态矩阵：三档从 Research 到 Archive 的路由、Plan Approval 与 autonomy authorization 分离、FAIL/backtrack、预算和硬停。
- 投影：next/resume/challenge/cruise、Console API/Web Console、新 ledger 字段一致。
- 安全回归：archive 零写入、Profile exact digest、E2E SKIPPED、reviewer grammar/Challenge 防伪、AC Coverage、Provider/path/symlink。
- 文档：AI 导航、人类文档中文可读性、创建 Spec 前主动选择自治模式、Agent 精确协议、新旧字段删除断言。
- 最终运行定向测试、workflow/state matrix、安全回归、`npm test`、`git diff --check`；Windows CRLF 环境按既有 Learning 记录仅测试进程的 LF 归一化前置条件。

Risks / Trade-offs:
- 新事件模型和三档矩阵增加实现量，但换来单一、可解释且可审计的协作合同。
- 严格迁移会中断升级项目；这是用户明确选择，用显式 AI 指引和原子 migrate 降低成本。
- 宿主 AI 才能真正启动子 Agent，SDD 只能提供授权事实与指引；验收验证协议输出和允许行为，不能伪造宿主运行结果。
- 公开投影删除旧字段属于 breaking change，必须通过发布说明和完整消费者回归控制。
