## Learning Record

Source Spec:
mydocs/specs/v2.4-reviewer-authorization-hints.md
Trigger:
Challenge 返回 PASS_WITH_CONCERNS，且 Execute Log 出现 BUGFIX。
Observed Problem:
平台无关 reviewer 授权提示最初只覆盖了 Challenge 缺失、invalid reviewer 和生成配置/文档路径；Research reviewer 为空的早退 blocker 仍输出裸消息，导致用户在缺 Research gate reviewer 时看不到可审计 reviewer 类型、暂停并主动请求授权、不得伪造 reviewer 的规则。
Root Cause:
实现只在共享 helper 和部分 blocker 分支追加 guidance，但没有按“同一规则的所有出口”枚举早退分支；测试也只覆盖缺 Challenge 与 invalid reviewer，没有覆盖 Research Reviewed By 为空。
Decision Rule:
当为门禁、授权、审计或 reviewer 证据新增统一提示时，必须先列出所有产生该门禁 blocker 的分支，包括 missing、empty、invalid、partial、stale 和 cross-command routing；每个分支都必须复用同一 shared guidance 或通过测试证明不会漂移。不能只覆盖主路径或已有失败路径。
Applies When:
适用于 SDD Research Gate、Challenge Gate、Plan Gate、archive-ready validation、`next` routing、AI config 生成和任何跨命令复用的审计/授权提示。
Does Not Apply When:
不适用于纯格式调整、只改变内部变量名、或不会影响用户可见 blocker / prompt / generated docs 的代码重构。
Recommended Action:
为 shared guidance 增加或修改规则时，同步补齐至少三类回归：直接 validate blocker、`next` 路由提示、生成/文档一致性。对每个 gate 使用 grep 查找所有 `issues.push`、early return 和正则触发条件，确保空值分支与非法值分支一致。
Evidence:
v2.4 Challenge 首轮返回 FAIL_CODE，指出 `validateResearchGate()` 的 `Research Reviewed By` 空值早退缺少 shared guidance，且 `next` 未识别 `Research Reviewed By is empty.`。修复后新增测试 `validate and next surface reviewer guidance when research reviewer is missing`，相关测试 5/5 通过，全量测试 169/169 通过，复查 Challenge 返回 PASS_WITH_CONCERNS 并进入 Learning Check。
