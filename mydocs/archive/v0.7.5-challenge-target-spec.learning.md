## Learning Record

Source Spec: mydocs/specs/v0.7.5-challenge-target-spec.md
Trigger: 同一 Challenge selector 边界在独立审查中连续暴露路径、文件类型、版本化目录和辅助制品混淆问题。
Observed Problem: 生成 Challenge prompt 与记录结果虽已共享 selector，但候选发现初期仍把目录或辅助制品误当作候选，或在无效版本化目录上抛出 EISDIR，存在目标漂移和错误写入风险。
Root Cause: 复用了为通用兼容场景设计的 Spec 查找函数，却没有在 Challenge 的写入边界内先统一验证常规文件、合法非辅助名称、活动状态及 lexical/realpath 项目内包含关系。
Decision Rule: 对任何会生成写入命令或直接改写 Spec 的 selector，先在命令私有 resolver 中建立唯一、已验证的目标；不可将“文件名看似版本化”视为可写 Spec。
Applies When: 命令支持默认、名称、路径等多种选择器，并会对所选文档或配置产生写入时。
Does Not Apply When: 纯只读列表或历史浏览命令仍应按各自既有兼容语义处理，除非其自身合同要求收紧。
Recommended Action: 枚举候选时先确认 regular file；排除辅助制品；对默认选择遇到版本化非辅助无效条目失败关闭；对显式目标再次检查名称、活动状态、词法路径与 realpath；生成和记录必须复用同一已验证路径，并为每类边界补零写入回归。
Evidence: `tests/commands.test.js` 覆盖冲突 selector、归档/项目外/junction 逃逸、非 Spec、目录、版本化目录、Design/Execute/Learning 辅助制品及辅助目录；最终 `npm test` 通过，独立 Challenge 记录为 PASS。
