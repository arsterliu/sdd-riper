## Technical Design

Selected Option / ADR: ADR-001 采用“窄横向基础层”。仅新增纯测试 I/O 与受控 Node CLI 调用 helper，并按文件迁移完全等价的样板；不建立完整合法项目/Spec/Run/Provider 生成器。该决定来自用户选择 Option A，并直接落实 v4.0 F-009 的 P2 收敛目标。
Requirement Traceability: v4.0 F-009 允许复用无业务 fixture builders 和 temp-project factory，同时要求保留状态机错误矩阵、安全/symlink、Challenge 防伪、AC Coverage 与 Provider fail-closed 回归。v4.1-v4.5 冻结的历史制品、路由、双 Run、allowlist、static mapping、realpath、baseline 与失败关闭语义均作为本期不可回归约束。
Impact Scope: 预计新增 `tests/helpers/test-fs.js`、`tests/helpers/test-cli.js` 及其单测；仅修改使用完全等价写入、临时目录或 Node CLI 输出整形样板的测试文件。不得修改 `src/`、`bin/`、模板、公开 CLI、Spec/Run schema、历史制品、状态矩阵或真实 Playwright 项目。
Context / Boundary: 共享层只处理“如何创建测试临时目录、如何显式写入文件、如何序列化 JSON、如何调用固定 Node CLI 并捕获结果”。测试域仍决定被写入的业务文件、argv、cwd、env、Provider、Spec、Run、失败注入和断言。共享层不认识 Challenge、AC Coverage、archive-ready、realpath、安全策略或领域状态。
Domain Model: `TestFilesystem` 是无状态的本地测试文件操作；`CliInvocation` 是固定 Node 可执行文件的一次受控调用与 `{ status, output }` 结果。它们不拥有项目合法性、可信路径、制品形状、Provider 资格或状态机结论。
Architecture View: `测试文件 → test-fs/test-cli → Node fs 或 process.execFile → 测试本地临时目录/项目 CLI`。Profile、Quality、Commands、workflow、Verification、Visual 测试分别保留各自的 fixture 组装与领域断言；共享 helper 不流入生产运行时，也不连接任一 Provider/Run/Visual 合同。
Data Model / Schema: 不新增或修改生产、Spec、Run、Provider 或历史制品 schema。测试 helper 只处理 `TempDir(prefix) -> absolute directory`、`TextWrite(path,text)`、`BufferWrite(path,buffer)`、`JsonWrite(path,value)` 与 `CliResult({ status, output })` 等进程内测试值；不持久化全局状态或缓存。
Data Migration / Backfill: 不迁移数据、不回填、不改写历史测试制品。所谓迁移仅指把测试文件中与 helper 完全等价的目录创建、写入和 CLI 输出捕获调用改接到 helper；每次接线可单独撤回。
Interface Contract: `test-fs` 导出 `makeTempDir(prefix)`、`writeText(filePath,text)`、`writeBuffer(filePath,buffer)`、`writeJson(filePath,value)`。每个写入函数创建父目录、使用调用方提供的值和显式编码；不 canonicalize 路径、不 cleanup、不捕获并翻译错误。`test-cli` 只使用固定的 Node 可执行文件和本仓库 CLI，接收调用方显式传入的 argv、cwd、env，返回稳定的 `{ status, output }`；不接受 shell 字符串或任意 executable。
API Protocol: 不新增 HTTP、CLI 参数、Provider capability、配置或运行时入口。helper 只能从测试文件 `require`，不允许生产 `src/` 或 `bin/` 引用。
State / Concurrency: helper 无模块级可变状态。每次 `makeTempDir` 创建唯一目录；写入调用同步完成或原样失败。测试继续由调用方管理环境变量、Git/XDG 隔离、并发与资源清理。
Failure Modes: 非法路径、权限、序列化或子进程失败保持 Node/现有测试的原始可观察错误与退出状态；helper 不将失败转换为成功、不提供默认 Provider/Spec/Run，也不吞掉 symlink/realpath 异常。
Security / Permission: helper 不解释路径是否可信，不执行任意命令，不自动 realpath 或删除路径，不构造 Challenge Evidence、AC Coverage 或 archive-ready 状态。路径 containment、symlink、Provider fail-closed、allowlist、static mapping、baseline 与双 Run 安全策略仍由原测试和生产模块验证。
Observability: 保持每个测试现有的断言文本、错误码、退出状态和 skip 条件。新增 helper 单测直接证明写入与 CLI 结果形状；Execute Log 记录迁移文件、定向回归和全量测试结果。
Performance / Capacity: helper 仅取代重复同步 I/O 样板，不增加全局扫描、缓存、网络或后台任务。临时目录和 fixture 大小仍由各测试控制。
Compatibility / Rollback: 生产行为与公开接口不变，历史制品不变。若单个迁移改变断言可见性，只需恢复该测试文件的本地样板；若 helper 合同本身不成立，删除其接线即可，无数据回滚。
Test Strategy: 先为 `test-fs` 和 `test-cli` 写红灯单测，覆盖唯一临时目录、嵌套 text/buffer/JSON 写入、显式编码、固定 Node CLI、argv/cwd/env 透传和非零 status。随后分批迁移完全等价的 Visual/Verification/Console 样板并逐文件回归。最后运行状态矩阵、Challenge 防伪、AC Coverage、profile-security、Provider/Verification/Visual path/symlink/Run/Playwright 回归与全量测试；生产源代码差异须为空。
Risks / Trade-offs: Option A 保留部分 SDD 项目与领域 fixture 重复，换取不把“默认合法项目”引入测试基础层。最大风险是 helper 逐步膨胀为隐含业务状态或安全策略；通过小接口、负向单测、禁止生产引用和逐文件迁移约束该风险。
