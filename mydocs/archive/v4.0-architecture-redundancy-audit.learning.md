## Learning Record

Source Spec: mydocs/specs/v4.0-architecture-redundancy-audit.md
Trigger: Execute Log 出现 `DEVIATED_MAJOR`；原 AC-008 把 Challenge 通过后的 archive-ready 状态定义为 Execute 完成前必须覆盖的验收条件。
Observed Problem: 状态机要求所有 AC 已有 Coverage 且 Completion Verification 完成后才能进入 Challenge；原 AC-008 又要求 Challenge 已通过后 `validate --archive-ready` 才算 PASS。二者形成循环：不完成 AC-008 无法 Challenge，不完成 Challenge 又无法完成 AC-008。若不回退修订，只能伪造 Coverage、跳过 Challenge 或永久阻塞。
Root Cause: Acceptance Criteria 混入了后置治理门禁的最终状态，没有按阶段区分“产品/交付行为验收”和“验收完成后才可执行的审查、Learning、Archive 门禁”。Plan 也把 post-Challenge 校验当作 Challenge 前的 Execute 证据，造成时序依赖反转。
Decision Rule: 定义 SDD Acceptance Criteria 时，AC 的证明必须在 Completion Verification 之前或紧随其后、且不依赖尚未执行的 Challenge/Learning/Archive 门禁。Challenge、Learning Check 和 archive-ready 属于验收后的治理流程，不得作为进入 Challenge 前必须已有 Coverage 的 AC。若需要观察工作流衔接，应把 AC 定义为 `NEXT_ACTION: run_challenge`；Challenge 后的 `validate --archive-ready` 保留为独立门禁步骤，不计入 Challenge 前 AC Coverage。
Applies When: 任一任务把 reviewer verdict、Learning 创建、archive-ready、archive authorization、部署审批或其他位于验收之后的治理状态写入 AC，且该治理状态本身依赖 Completion Verification 或全部 AC Coverage 时。
Does Not Apply When: AC 验证的是 Execute 阶段可直接观察的产品行为、制品结构、测试结果，或验证命令不依赖 Challenge/Learning/Archive；也不适用于仅在 Plan 中列出的 post-Challenge 操作步骤。
Recommended Action: 编写 AC/Plan 时画出 `Execute → Completion Verification → Challenge → Learning → archive-ready → authorization` 依赖链；逐条检查 AC 的证明点是否位于 Challenge 之前。发现环时先运行 `sdd debug`，记录 `DEVIATED_MAJOR`，回退 Acceptance/Plan，清空旧审批并取得新审批；保留旧执行事实，不伪造 PASS 或人工改写 Challenge Evidence。
Evidence: 原 AC-008 要求 `node bin/cli.js validate . --archive-ready`；执行 `sdd next` 报 AC-008 无 Coverage，无法进入 Challenge。修订为 completion 后运行 `node bin/cli.js next .` 后，实际输出 `NEXT_ACTION: run_challenge`、`BACKTRACK_TARGET: Challenge`，且剩余 blocker 仅为 Challenge Evidence 和 `DEVIATED_MAJOR` 触发的 Learning。
Related ADR: ADR-001 — Contract-First Phased Simplification；本 Learning 约束后续 Specs 的 Acceptance/Plan 时序。
