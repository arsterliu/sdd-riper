## Intake

### Constraints
constraints: 保留 Spec、Design、Execute Log 三类独立制品及 RIPER 阶段名称；不自动迁移或改写旧任务；保护当前工作区未提交内容；不使用任何 skill。

新任务使用 streamlined-v1；无策略字段的任务按现有规则继续运行。

### Risks
修改授权和独立审查判定可能错误放行或误阻塞任务；需要新旧策略及三种 mode 的回归矩阵。
低风险任务改用 Spec 内验证证据后，必须仍能追溯结果、发现失败并遵守归档授权。

### Initial Acceptance Hints

按低、中、高风险分别验证制品与审查要求；旧任务无迁移且行为保持不变。

SKILL.md 与 INTEGRATIONS.md 已把本地 clarification 设为默认，但 install-skill 仍递归复制整个 vendored/，宿主可能把其中的上游 SKILL.md 发现为独立入口；只改映射文字不足，需同时检查安装清单和宿主发现行为。

## Innovate Options
方案 A（采用）：增加版本化的策略评估层。旧 Spec 继续旧解析及摘要；新 Spec 用显式风险信号计算最低门禁，并由状态评估和验证命令共享这一结果。优点是兼容边界清楚、可逐项测试；代价是短期保留两套规则。
方案 B（放弃）：直接修改现有 mode 分支和摘要算法。文件较少，但旧授权事件无法还原缺失的需求快照，改算法会使旧任务停机或继续保留漏洞，且多个验证入口容易分叉。
方案 C（放弃）：只缩短模板与技能文案。无法修复摘要失效、门禁硬编码和安装目录的上游技能入口。
Decision Rule: 优先保持历史任务可继续读取，以新策略为清晰隔离边界；新策略内让风险声明、制品、审查和验证使用同一个判定结果。
