# Technical Design

## Technical Design

Selected Option / ADR: Option B — Challenge verdict + Backtrack 放 Status Overview section，Cruise run 独立 section

Requirement Traceability: CR-1 Challenge verdict 颜色 → AC-001, CR-2 Backtrack target → AC-002, CR-3 Cruise run 结构化 → AC-003, CR-4 stopReason 颜色 → AC-004, CR-5 blocker 卡片去重 → AC-005

Impact Scope: 仅前端渲染层（src/web/），不涉及后端

Architecture View:
```
┌─ Status Overview section ──────────────────┐
│  Risk Flags (已有)                          │
│  Challenge Verdict (新增，颜色标签)          │
│  Backtrack Target (新增，仅 FAIL_* 时显示)   │
│  Blockers (已有)                            │
└────────────────────────────────────────────┘

┌─ Cruise Run section (新增) ────────────────┐
│  Policy / Max Iterations                    │
│  Latest Run: iteration / engine / verdict   │
│  Stop Reason (颜色标签)                     │
│  Run Count                                 │
└────────────────────────────────────────────┘
```

Data Model / Schema:
- `spec.workflow.challengeVerdict: string` — PASS | PASS_WITH_CONCERNS | FAIL_*
- `spec.workflow.backtrackTarget: string` — Research | Design | Acceptance | Plan | Execute / Debug | Execute Log | Learning Check | Ready
- `spec.workflow.cruisePolicy: string` — off | assisted | autonomous
- `spec.workflow.maxIterations: number`
- `spec.cruiseRun.count: number`
- `spec.cruiseRun.latest: { iteration, engine, challengeVerdict, backtrackTarget, stopReason, riskFlags, ... }`

Interface Contract: 无新 API 端点，前端从现有 spec 对象直接读取

Compatibility / Rollback:
- blocker 卡片移除 challenge/backtrack 文本行 → 信息不丢失（升级到结构化区域）
- 新增 HTML section 默认有内容
- CSS 新增 class 不影响现有

Test Strategy:
- 单元测试：验证 renderChallengeVerdict()、renderCruiseRun() 对各种 verdict/stopReason 的渲染
- 现有测试不退化

Risks / Trade-offs:
- blocker 卡片移除 challenge/backtrack 文本行是 breaking change for 习惯看 blocker 卡片的用户 → 但信息升级到更醒目的位置，净收益为正
