## Learning Record

Source Spec: mydocs/specs/v3.3-fix-vendored-execution-skill-references.md
Trigger: Execute Log 出现 `DEVIATED_MINOR`，且 Challenge 返回 `PASS_WITH_CONCERNS`；调查同时确认精选 vendoring 的上游技能包含未打包兄弟技能的强制交接引用。
Observed Problem: SDD-RIPER 只 vendoring 六个执行质量技能，但上游 `writing-plans` 和 `subagent-driven-development` 仍要求或路由到 `executing-plans`。如果 Agent 把被引用技能的全部工作流文本都当成 SDD 契约，就会提示安装不存在的技能、停止执行或绕过 SDD Execute Phase；直接修改 vendored 文件又会破坏上游字节一致性和后续同步能力。
Root Cause: 集成映射只声明了“使用哪个上游技能”，没有同时声明“只复用哪些方法论片段、哪些上游工作流交接必须被 SDD 覆盖”。精选 vendoring 的能力边界与上游技能内部跨技能引用之间缺少显式适配契约和同步后回归检查。
Decision Rule: 精选 vendoring 外部技能时，必须审计所有 `REQUIRED SUB-SKILL`、下一阶段、交接和替代路由引用。若引用目标不在本项目声明的能力集合内，先判断宿主或项目是否已有等价能力；有等价能力时，在项目自有控制层写明复用范围、覆盖优先级和替代路由，并增加同步后契约测试。不得为了消除文本告警而静默新增重复能力，也不得直接补丁上游只读副本。
Applies When: 项目只 vendoring 上游技能集合的一部分，或只借用外部技能的局部方法论，而上游文档仍包含完整套件的阶段跳转、必需技能、脚本、插件或跨会话执行约定时。
Does Not Apply When: 项目明确完整继承上游工作流并打包其全部必需能力；或 vendored 文件本身就是允许维护的 fork，已有独立版本、许可证归属和同步策略。
Recommended Action: 每次新增或同步 vendored 技能后，全文扫描必需技能和交接引用；将结果与 `SKILL.md` / `INTEGRATIONS.md` 声明的能力集合比对。对故意不集成的引用，在自有适配层记录“上游原文、SDD 替代路径、优先级”，并运行能够在覆盖规则丢失时失败的自动测试，同时用 `git diff --exit-code` 确认上游副本未被修改。
Evidence: `tests/commands.test.js` 的 `SDD integration overrides upstream executing-plans handoffs` 先在缺少 SDD 覆盖语句时失败，修复后通过；`rg -n "executing-plans"` 显示六处上游引用和对应 SDD 覆盖；两个 vendored `SKILL.md` 的 `git diff --exit-code` 为 0；全量测试 266 PASS、0 FAIL、1 权限相关 SKIP，doctor `RESULT: OK`。
Related ADR: 不适用（micro 模式无独立 Design/ADR）。
