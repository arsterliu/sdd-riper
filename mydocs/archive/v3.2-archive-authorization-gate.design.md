## Technical Design

Selected Option / ADR:
ADR-3.2：采用 archive 调用时一次性授权。`archive` 必须同时收到 `--authorized-by human:<name>` 与 `--authorization-evidence <single-line-text>`；不增加持久化 authorize 命令，不把授权写入 active Spec。完成后由 CLI 生成授权时间并把授权记录写入归档 Spec。
Requirement Traceability:
ARCH-AUTH-ROUTING → 中央状态/next/resume/cruise；ARCH-AUTH-GATE 与 ARCH-AUTH-AUDIT → archive CLI；ARCH-AUTH-CONSOLE → index/API/Web；ARCH-AUTH-PROTOCOL → 文档、protocols 与生成 Agent 配置。
Impact Scope:
修改 `bin/cli.js`、`src/core/spec-state.js`、`src/core/workflow.js`、`src/core/spec-index.js`、`src/core/project-indexer.js`、`src/core/cruise-run.js`、`src/commands/{next,resume,cruise,archive,console,_gen-ai-configs}.js`、`src/web/console.js`，以及相关测试、README/GUIDE/TEAM-GUIDE/protocols。若实际 diff 证明某包装层无需代码变化，只记录验证证据，不做机械编辑。
Context / Boundary:
系统边界是本地 CLI 与 Markdown 制品。中央 evaluator 只计算完成条件和等待状态；`archive` 是唯一执行归档副作用的入口。Console 保持只读。CLI 不接入身份提供方，无法证明真实人类身份，只能验证并记录结构化声明。
Domain Model:
“Completion Readiness”表示 Research 至 Learning 的质量门禁全部通过；“Archive Authorization”表示用户对本次不可逆归档调用的明确许可；“Archived”表示副作用已经完成。Completion Readiness 不是 Archive Authorization，任何 PASS/Ready/Plan/Challenge 都不能推导后者。
Architecture View:
`ArtifactSnapshot → spec-state.evaluate → completionReady + phase/action → workflow/spec-index → next/resume/cruise/Console`。写路径为 `archive CLI args → authorization validator → completion validator → archive mutation → archived Spec authorization record`。授权 validator 必须位于所有 `mkdir/write/unlink/append` 之前。
Data Model / Schema:
WorkflowState 的 canonical 末态为 `{ phase: 'archive_authorization', nextAction: 'request_archive_authorization', backtrackTarget: 'Ready', completionReady: true }`。不再用 `archiveReady` 同时表达事实与动作。归档 Spec 追加固定 section：`## Archive Authorization`，包含 `Archive Authorized By: human:<name>`、`Archive Authorized At: <ISO-8601>`、`Archive Authorization Evidence: <single-line-text>`。archive index 保持现有 schema，归档 Spec 是授权审计 source of truth。
Data Migration / Backfill:
不改写历史 archive。历史记录没有 Archive Authorization section 时按 legacy 只读展示，不推断授权。active Spec 不新增授权字段。现有 API/测试若消费 `phase=ready`、`nextAction=archive_ready` 或 `archiveReady`，必须迁移到新契约；这是有意的 fail-closed 破坏性变化。
Interface Contract:
`specState.evaluate()` 在完成条件通过时输出 `completionReady=true`、`phase=archive_authorization`、`nextAction=request_archive_authorization`。`validate --archive-ready` 继续验证完成条件，但输出须明确它不授予归档许可。`archive` 只有授权参数校验与 completionReady 均通过才可进入写路径。授权记录由 CLI 生成，不从 active Spec 读取。
API Protocol:
命令：`sdd archive <dir> <spec-name> --authorized-by "human:<name>" --authorization-evidence "<text>" [--force]`。缺失参数、身份格式非法、证据 trim 后为空、证据含 CR/LF 或控制字符时输出 `SDD_ARCHIVE_AUTHORIZATION_REQUIRED` 或 `SDD_ARCHIVE_AUTHORIZATION_INVALID` 并 exit 2。`next` 输出 `NEXT_ACTION: request_archive_authorization`；`resume` 输出 `PHASE_HINT: await_archive_authorization`；Cruise 输出相同 action 并以 `human_required` 停止。Console API phase 使用 `archive_authorization`，UI 标签为 “Awaiting Archive Authorization”。
State / Concurrency:
授权只对当前同步 archive 调用有效，不持久化、不重试、不跨进程复用。命令在参数授权通过后重新读取并校验当前 Spec 完成状态，再执行既有归档写路径，因此授权与所见当前状态位于同一次调用。当前 archive 的多文件原子性不在本任务扩展范围内；授权失败必须严格零写入。
Failure Modes:
缺授权/非法授权 → exit 2、稳定 code、零写入；完成条件未通过 → 保持既有 not-ready 失败并零归档写入；目标冲突且无 force → 保持既有失败；`--force` 只允许覆盖目标，不能放宽授权；授权通过后归档摘要无法生成 → 保持 active 制品，授权不会被持久化；归档中途 I/O 错误沿用既有诊断，本任务不承诺跨文件事务原子性。
Security / Permission:
授权身份只接受 `human:<name>`，不接受 agent/subagent/inline；证据必须单行、非空，并拒绝控制字符以避免 Markdown 字段注入。CLI 声明不是身份认证，Agent 协议必须规定：未从当前用户获得明确授权时停止；禁止自行构造参数，禁止复用历史授权，禁止由任何门禁结果推导授权。
Observability:
失败输出稳定错误 code 与“先请求用户明确授权”的修复指引；成功归档 Spec 固定记录授权人、CLI 时间和证据。`validate --archive-ready` 输出完成条件通过但归档授权仍需在 archive 调用时提供。Console 明确展示等待授权，不提供授权按钮。
Performance / Capacity:
只增加常数级参数校验、状态字段和少量 Markdown 写入；不增加额外文件扫描、网络调用或后台状态。
Compatibility / Rollback:
无授权 archive 调用将从成功变为 exit 2；`NEXT_ACTION`、`PHASE_HINT`、active phase 和 WorkflowState 末态字段发生有意变化。历史 archive 兼容只读。回滚代码不会删除已经写入的 Archive Authorization section，旧版本会把它当普通 Markdown 内容保留。
Test Strategy:
先写 RED：中央 evaluator/命令路由一致性；missing/partial/invalid/multiline/agent 授权及 force 绕过；授权失败前后目录树与文件内容不变；有效授权成功并记录三字段；not-ready 即使有授权也失败；Console API/UI 字符串与 phase/counts；Cruise stopReason；文档和生成 Agent 指令一致性。GREEN 后运行目标测试 `node --test tests/state-matrix.test.js tests/commands.test.js`，再运行全量 `node --test tests/*.test.js`（PowerShell 下按仓库可用展开方式执行）。
Risks / Trade-offs:
参数可被恶意 Agent 伪造，这是无身份系统的固有限制；通过稳定门禁、不可伪装为自动推导的协议措辞和归档审计记录降低风险。一次性授权避免陈旧许可，但调用者每次重试都必须重新确认其仍持有当前用户授权。改变 phase/action 是破坏性接口变更，但比保留歧义 alias 更纯粹、可审计。
