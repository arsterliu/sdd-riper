## Technical Design

Selected Option / ADR: 采用 Option A“旅程驱动的整体重构”。以四份人类指南的受众职责为主轴，配套同步 Agent 权威指令、托管生成源、当前 protocol、治理测试和已安装 Skill 投影；不新增通用文档生成框架，也不修改底层工作流行为。
Requirement Traceability: README 对应“自然语言开始”；GUIDE 对应“AI 动作、用户确认点和完成标志”；REFERENCE 对应“完整 CLI 与精确合同”；TEAM-GUIDE 对应“团队治理与观察”；SKILL、生成源、protocol 和安装投影对应“AI 实际能够按指南主动路由”。四类能力只补齐指令层的 Profile/Quality 主动判断，复用现有 Visual/E2E 规则。
Impact Scope: 修改 `README.md`、`GUIDE.md`、`REFERENCE.md`、`TEAM-GUIDE.md`、`SKILL.md`、`src/commands/_gen-ai-configs.js`、必要的 `protocols/sdd-riper-one*.md`、项目根托管 AI 配置受控区块，以及相关文档/治理测试。通过现有 installer 刷新本机 Codex Skill。CLI 状态机、Provider/Profile/Quality/Visual 实现、schema、历史 archive/ledger 不变。
Context / Boundary: SDD-RIPER 是 AI 交付控制协议，CLI 提供确定性状态与写入入口，宿主 AI 负责解释、路由和执行。人类指南不能承担 Agent 硬规则，Agent 指令也不应复制完整人类教程；两者通过可测试的语义合同保持一致。
Domain Model: 文档域包含 Human Journey、Agent Routing、Precise Contract、Team Governance 四个角色；投影域包含 Source Skill、Managed Agent Block、Installed Skill。能力路由包含 Trigger Fact、Agent Action、Human Gate、CLI Escape Hatch 四个要素。
Architecture View: `用户目标 → README 自然语言入口 → GUIDE 任务旅程 → REFERENCE 精确合同`；TEAM-GUIDE 从侧面约束团队默认值与责任。`仓库 SKILL/current protocols → _gen-ai-configs → AGENTS/CLAUDE/Cursor/Copilot 受控区块 → install-skill → 本机 Codex Skill` 构成 Agent 投影链。测试分别验证人类分层语义、Agent 路由语义、受控生成幂等和安装指纹。
Data Model / Schema: 不新增或修改业务数据结构、配置 schema 或 SDD 制品字段。文档只引用现有 `AUTONOMY_MODE`、AC Verification、Provider、Profile revision/digest、ui-impact 和 visual intent 合同。
Data Migration / Backfill: 不迁移历史 Spec、archive、ledger 或用户内容。已安装 Skill 的旧副本通过既有 `install-skill --target codex --clean` 做可重复的受控投影刷新，并用 `--check` 核对指纹；这不是业务数据迁移。
Interface Contract: README 首屏必须以自然语言协作定位并提供可复制任务描述；GUIDE 每个场景统一表达“用户输入、AI 动作、人工确认、完成标志、可选自查”；四类能力不得作为用户手选菜单。REFERENCE 每个主要能力先给 Trigger Fact → Agent Action → Human Gate → CLI 导航，再保存完整公开命令组、参数、状态、错误和安全规则。TEAM-GUIDE 仅说明团队默认、风险升级、角色分离、审查、例外和观察事实。Agent 指令明确：Visual/E2E 沿用现有自动判断；Profile 在缺少可靠工程事实或 Spec 绑定 revision 时主动读取/建议；Quality 在 Design/Acceptance/Plan 需要测试路由时主动生成只读建议；所有专用人工门禁保持独立。
API Protocol: 不改变 CLI/API。文档中的命令必须与 `bin/cli.js` 当前公开命令保持一致；托管配置只更新 `<!-- sdd-riper:start -->` 与 `<!-- sdd-riper:end -->` 之间的内容，保留区块外项目文本。
State / Concurrency: 文档编辑不引入运行时并发。AI 配置沿用现有幂等生成；安装 Skill 由 installer 负责复制与 clean/check，不并发手改源和目标。活动 Spec 的 `supervised` 状态和授权规则不因文档改造改变。
Failure Modes: 链接断开、命令索引漏项、旧标题测试阻挡新结构、生成结果与源不一致、安装投影漂移、自然语言承诺超过实际 Agent 规则、误删精确安全合同。失败时修正权威源或分层断言；禁止手改生成结果、放宽门禁或扩大到 CLI 业务实现。若兑现承诺确需行为变更，记录重大偏差并回到 Design/Plan。
Security / Permission: 不弱化归档、Profile exact digest、E2E SKIPPED、严格视觉合同/方向/基线、独立 reviewer、不可逆操作、范围扩大、新风险和平台权限门禁。Profile `commandRefs` 不自动执行；能力识别不得自动安装依赖或创建/批准 Provider、baseline。安装到项目外目录时遵守平台权限并使用现有 installer。
Observability: 以文档链接检查、治理语义测试、托管区块幂等测试、`install-skill --check` 指纹、`doctor`、发布文件清单和全量测试作为可观察证据。Execute Log 记录每层变更、定向验证和最终四轴自检。
Performance / Capacity: 运行时性能不受影响。文档与静态测试只增加可忽略的测试时间；不引入新的生成系统或网络依赖。
Compatibility / Rollback: 保持全部公开 CLI、状态值、配置和历史读取兼容。仓库改动可由版本控制回退；安装 Skill 可再次从任一已知版本受控覆盖。历史文档中的旧术语作为审计事实保留，不纳入当前文档清理。
Test Strategy: 先修改/新增治理断言形成红灯：README/GUIDE 的 AI-first 分层、四能力非菜单化、REFERENCE 全公开命令组与有效锚点、TEAM-GUIDE 陈旧概念清理、SKILL/生成源的主动路由与硬门禁、受控区块幂等。随后完成最小文档/指令修改并运行 `tests/autonomy-guidance.test.js`、`tests/governance-contract.test.js`、`tests/commands.test.js`；再运行链接/静态旧术语检查、`install-skill --check`、`doctor`、`npm pack --dry-run` 和全量测试。
Risks / Trade-offs: 整体重构审阅面较大，但比局部修补更能消除责任倒置。REFERENCE 会保持较长，这是精确合同层的有意取舍；通过章节导航提高可读性而非删减规则。Agent 指令只做窄补齐，避免把文档任务扩张为运行时功能改造。
