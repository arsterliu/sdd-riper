## Design Note

Approach:
三层 advisory，复用既有信号语汇、不引入强制逻辑：
- **rubric 文档** `protocols/mode-selection.md`：默认 micro；升级信号表（blast radius / reversibility / interface contract / design latitude / risk class / verification depth）；micro/lite/standard 选择规则——standard 须具名信号或 3+ 信号叠加；附反模式。
- **discover 提示** `_spec-creator.js` 新增 `modeAdvisory(mode, explicit)`，在 spec 创建输出处打印 `[MODE] <mode> … rubric: protocols/mode-selection.md`；mode=standard 追加"standard is the heaviest…"确认行。与既有 `shouldSuggestCodeMap` advisory 并列。
- **SKILL.md 引导**：Mode Policy 增 rubric 指针并把"default to standard"改为"default micro 按信号升级"；Setup 第 2 步同步。

Impact Scope:
新增 `protocols/mode-selection.md`；改 `src/commands/_spec-creator.js`（仅输出层，新增纯函数 + 一行打印）、`SKILL.md`（措辞/指针）、`tests/commands.test.js`（新增用例）。不动 `init.js`、`discover.js` 入口、`--mode` 解析与默认值、spec 模板、其余命令。

Interface / Data Impact:
CLI 签名不变；discover 仅多出 `[MODE]` advisory 行（stdout）。无持久化/schema/frontmatter 变化（生成的 `mode` 字段仍来自传入/项目默认）。

Compatibility:
纯增量 advisory，向后兼容；旧脚本解析 discover 输出若按段落锚点（`## SPEC CREATION PROMPT`）取值不受影响（advisory 在其之前、与 codemap 提示同区）。回滚=删 rubric 文档 + 还原 `_spec-creator.js`/SKILL.md 三处改动。doctor 因新增 SKILL→protocols 引用会校验该文件存在。

Risks:
- 代码默认仍 standard 与 rubric"默认 micro"存在张力 → 本期 advisory 容忍，记为后续可选项（改 init 默认值属行为变更，受本 spec 约束排除）。
- advisory 行增加 discover 输出噪音 → 控制在 1~2 行，且指向单一文档。

Test Strategy:
`tests/commands.test.js`：新增用例断言 discover lite 输出含 `[MODE] lite`+rubric 路径且无 standard 重提示、discover standard 含重提示（AC-002/003）；AC-001 由现有 "doctor passes on the real repo" 用例覆盖（新 SKILL→protocols 引用纳入校验）；AC-004 由现有 discover/spec 生成用例保证 `--mode` 行为不变。`node --test` 全绿。
