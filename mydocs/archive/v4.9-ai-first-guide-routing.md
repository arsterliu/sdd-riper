## Summary
<!-- 3-5 lines in Chinese: current phase, goal, key constraints, latest progress. -->
当前处于 Research Gate 复核阶段，目标是把人类指南从“用户先理解模块和命令”重构为“AI 先识别场景、解释下一步并仅在真实门禁停下”。
本任务保留 README / GUIDE / REFERENCE / TEAM-GUIDE 的分层职责，同时同步 Agent 权威规则、生成配置与安装投影，避免文案与实际引导再次漂移。
不改变 v4.8 三档自治状态机和安全门禁，不改写历史制品；CLI 继续作为确定性控制面，只在场景中少量出现，完整契约集中于 REFERENCE。

## Intake

### Requirement
requirement: 全面重构指南文件的信息架构，以 AI 主动识别、引导和执行为主，命令行为辅；README 提供对话式入口，GUIDE 按真实场景说明 AI 动作与用户确认点，REFERENCE 集中保存完整命令和精确合同，TEAM-GUIDE 改为团队治理与观察；Project Profile、Quality Plan、Verification、Visual 由 Agent 自动识别是否需要，只有受控操作才请求用户确认；同步清理过时术语、断链和已安装 Skill 投影不一致风险。
goal: 让普通用户无需理解内部模块或记忆命令即可由 AI 带领完成任务，同时为高级用户和维护者保留准确、集中、可验证的 CLI 参考。

### Constraints
constraints: 不弱化归档、Profile digest、E2E SKIPPED、严格视觉合同、不可逆操作、范围扩大、新风险与平台权限门禁；不改写历史归档；命令完整契约集中到 REFERENCE；保留少量场景化自助检查命令。

### Scope

- In Scope：重构 README、GUIDE、REFERENCE、TEAM-GUIDE 的信息架构和中文表达；将 Project Profile、Quality Plan、Verification、Visual 改为由 Agent 根据任务事实自动识别和路由；清理 ProjectMap、旧 Approval/Cruise 策略、虚构门禁、过期 Completion Verification 等表述。
- In Scope：同步仓库 `SKILL.md`、`src/commands/_gen-ai-configs.js` 的托管 Agent 指令、仍被当前流程引用且表述过时的 protocol，以及文档/治理测试；使用受控安装入口刷新本机已安装 Skill，并验证源与投影一致。
- In Scope：README / GUIDE 仅在用户想自行检查或排障的具体场景穿插少量命令；REFERENCE 完整保留字段、状态、命令、错误和安全合同，并增加“触发事实 → Agent 动作 → 人工门禁 → CLI”的导航层。
- Out of Scope：不重写 v4.8 自治状态机、CLI 运行行为、Profile/Quality/Verification/Visual 领域实现或 schema；不创建新的独立 CLI 文档；不改写历史 archive、旧 ledger 或用户目录中的非 SDD 内容。

### Risks

- 只修改人类文档会让 Agent 继续执行旧协议；只修改 Agent 协议又会让普通用户看不懂，必须把源、生成投影、安装投影和测试作为一条一致性链验证。
- 把“Agent 自动识别”写得过宽可能误导用户，以为 Agent 能旁路 Profile exact digest、严格视觉合同、E2E SKIPPED、归档或平台权限；必须逐项保留真实人工门禁。
- 把全部命令移出 README / GUIDE 会损害排障与高级用户自助能力；反之保留完整命令表会再次把指南变成 CLI 手册。
- TEAM-GUIDE 中存在无依据收益比例、已删除的 ProjectMap、持久维护 CodeMap、虚构 Mode Recommendation Gate 和固定 TL 审批等陈旧内容；局部改词不足以恢复正确团队治理模型。
- 安装 Skill 位于项目外，刷新必须走 `sdd install-skill` 的受控复制与 `--check`，不得直接手改；刷新失败时不能宣称 Agent 投影已更新。

### Initial Acceptance Hints

- 新用户从 README 能直接用自然语言启动任务；版本、任务名、参考资料、自治模式等由 AI 主动收集并解释，不要求先学模块或记命令。
- GUIDE 以真实旅程说明“你提供什么、AI 会做什么、何时必须确认、怎样算完成”；Profile、Quality、Verification、Visual 嵌入相关场景，由 AI 自动判断，不再作为用户自行开启的功能菜单。
- REFERENCE 保留完整精确合同，但主要章节先说明触发事实、Agent 动作与不可委托门禁，再给 CLI；所有目录锚点有效，不出现当前运行合同已删除的旧治理字段。
- TEAM-GUIDE 只描述团队默认值、职责、例外审批、审查独立性和可观察事实，不按人员资历绑定 mode，不要求维护已删除或按需计算的产物，不保留无证据效率承诺。
- 仓库 Skill、托管 AI 配置生成源和当前 protocol 明确要求 Agent 主动路由四类能力；治理测试验证分层与路由语义，而不是固定旧章节标题。
- 受控安装后，本机 Skill 与仓库源无漂移；归档、Profile exact digest、E2E SKIPPED、严格视觉证据、不可逆动作、范围扩大、新风险和平台权限仍明确要求人工确认。

## Research

### Requirement Review

用户不是要求删掉 CLI，而是要求改变指南的默认叙事：普通用户先描述目标，由 AI 识别需要哪些内部能力、主动推进并解释停机原因；只有希望自行检查、排障或集成时才接触命令。此前已经确认采用“README/GUIDE 场景中少量穿插，REFERENCE 集中完整命令”的分层方式，并要求保持现有自然语言引导风格。

这项改造必须同时处理人类可读层和 Agent 执行层。当前 v4.8 已建立三档自治和 AI 导航合同，因此 v4.9 的职责是消除指南、protocol、生成配置、安装 Skill 与该合同之间的漂移，而不是重新设计自治机制。

### Findings

1. README 的开头仍把产品定性为“本地命令行工具”，AI 快速入口后很快进入完整 CLI 路径与命令表，并让用户自行选择任务大小及“按需打开” Project Profile、Quality Plan、Verification、Visual；这与 AI 主动识别目标相反。另有把五项输入误称“四项”的文字错误（`README.md:5,34,45,47-70,83-95,110-133`）。
2. GUIDE 已具备“你要提供 / AI 会做 / 你确认 / 完成标志”的正确场景骨架，但仍有含糊的旧 Plan 审批表述、失效锚点，以及把四类能力组织为用户功能菜单；Quality Plan 甚至直接要求用户运行命令（`GUIDE.md:22,70-82,105-128,229-273`）。
3. REFERENCE 作为精确合同层的定位正确，但快速索引仍指向旧标题，后部仍展示已移除的 Approval/Cruise 配置，Profile、Quality、Verification 等章节以手工命令开场，缺少 Agent 路由导航（`REFERENCE.md:3-28,1025,1058-1063,1083-1133`）。
4. TEAM-GUIDE 漂移最严重：包含无依据的 10%–20% / 50% 收益声明、已删除的 ProjectMap、错误的持久维护 CodeMap、旧 Completion Verification Pass、虚构 Mode Recommendation Gate、固定 TL 审批和按人员资历绑定 mode；Cruise 仍引用已合并/变化的 review 流程（`TEAM-GUIDE.md:13,25-34,61-76,99-110,202-218`；`tests/commands.test.js:1725-1731`）。
5. 仓库 `SKILL.md` 已正确采用 `auto|supervised|human` 和 v4.8 安全边界，但只对 Visual 写了主动判定，尚未形成 Profile、Quality、Verification、Visual 的统一自动路由；AI 配置生成源也存在相同缺口（`SKILL.md:32,40,137-160,194-204`；`src/commands/_gen-ai-configs.js:22-34`）。
6. 当前 protocol 仍出现 ProjectMap，Visual 指引也落后于“每个 Spec 先确定 ui-impact”的现行规则，因此不能只改顶层指南（`protocols/sdd-riper-one.md:28,51`）。
7. 本机 Codex 安装的 Skill 与仓库源发生实质漂移：仓库 SHA-256 为 `D93075...`, 安装副本为 `42B382...`，安装副本仍包含 `APPROVAL_POLICY` / `CRUISE_ENABLED`。必须通过 `sdd install-skill --target codex` 的受控路径刷新，并以 `--check` 验证，不能直接编辑用户目录。
8. 现有治理测试主要断言标题或关键词存在，甚至固定旧标题“按需使用的高级能力”，容易阻止正确的信息架构改造，却不能证明 Agent 自动路由与 CLI 分层（`tests/commands.test.js:2491-2569`；`tests/autonomy-guidance.test.js:8-18`）。
9. 历史决策支持本次方向：v4.8 已要求 AI 导航、三层文档和托管指令一致；v4.7 Learning 明确 README 回答“怎么开始”、GUIDE 回答场景分工、REFERENCE 回答精确规则；v3.8 Learning 要求由权威元数据推导 UI 影响；v4.0 Learning 要求 AC 不依赖 Challenge/Archive 等后置门禁。历史文件仅作证据，不修改。

### Open Questions

无。用户已确认文档分层、CLI 放置方式、`v4.9-ai-first-guide-routing`、`supervised`、无 UI 影响、沿用现有 AI 引导风格，以及四类能力由 Agent 自动识别。具体信息架构方案在 Innovate 阶段比较后确认。

### Assumptions

- “Agent 自动识别”表示读取当前 Spec、Profile/affected-units、AC verification 类型、context 和现有配置后决定是否进入相应流程；不表示自动安装依赖、执行 Profile commandRefs、初始化 Provider、批准视觉基线或跳过专用授权。
- README / GUIDE 面向普通使用者，以自然语言和场景为主；REFERENCE 面向高级用户、维护者和 Agent，允许完整 CLI 与协议细节；TEAM-GUIDE 面向团队治理，不重复个人教程。
- 仓库 `SKILL.md` 和生成源是 Agent 行为的权威源，项目根 AGENTS/CLAUDE 等只更新受控区块；本机安装 Skill 是发布投影，必须通过既有安装命令刷新。
- 若审查发现文档声称的自动识别缺少 Agent 硬规则，只补齐指令和测试，不扩张为新的生产运行时或 schema 改造。

## Innovate Options
<!-- Compare at least two options. Write the option analysis in Chinese. -->

### Option A: 旅程驱动的整体重构（Selected）

- Summary: 按用户旅程重新划分四份人类指南：README 提供自然语言入口，GUIDE 按任务阶段说明 AI 与用户分工，REFERENCE 集中精确合同，TEAM-GUIDE 聚焦团队治理；同时同步 Agent 权威源、生成投影、protocol、测试和安装 Skill。
- Pros: 从信息架构上消除“先学模块、再选命令”的负担；人类说明与 Agent 实际行为可以形成同一条可验证链；未来新增能力有明确落点。
- Cons: 涉及文档较多，需要系统核对链接、命令索引、发布清单和托管投影。
- Risks: 若迁移时只删不重组，可能丢失高级用户需要的精确规则；通过 REFERENCE 完整命令清单和治理回归约束。
- Requirement Fit: 完整满足 AI 主导、CLI 辅助、四类能力自动识别及指南分层要求。

### Option B: 保留结构的渐进修补

- Summary: 保留现有章节顺序，只修复旧术语、断链和明显的手动选择表述。
- Pros: 改动较小，短期审阅成本低。
- Cons: README/GUIDE 仍保留命令手册式骨架，用户仍需理解内部模块，难以根治责任倒置。
- Risks: 新旧叙事并存，后续继续漂移。
- Requirement Fit: 只能部分改善可读性，不满足“描述重心都是 AI 引导为主”的整体目标，因此不选。

### Option C: 建立统一结构化内容源并生成所有指南

- Summary: 新建文档 schema 或生成器，由同一内容源生成四份指南和 Agent 指令。
- Pros: 理论上一致性最强，重复内容最少。
- Cons: 引入新的生成系统、维护规则和迁移成本；人类指南的受众差异很难完全模板化。
- Risks: 为解决表达问题增加新的生产机制，范围和复杂度显著扩大。
- Requirement Fit: 超出当前必要范围，不符合简化目标，因此不选。

## 目标摘要
当前处于 Research Gate 复核阶段，目标是把人类指南从“用户先理解模块和命令”重构为“AI 先识别场景、解释下一步并仅在真实门禁停下”。

## 最终方案
采用 Option A“旅程驱动的整体重构”。以四份人类指南的受众职责为主轴，配套同步 Agent 权威指令、托管生成源、当前 protocol、治理测试和已安装 Skill 投影；不新增通用文档生成框架，也不修改底层工作流行为。

## 关键约束
以 v4.8 三档自治合同、当前 CLI 行为、v4.7/v3.8/v4.0 Learning 和生成配置的受控区块为权威事实；保留 Challenge 独立性和防伪、AC Coverage、历史只读、路径安全，以及归档、Profile exact digest、E2E SKIPPED、严格视觉合同、不可逆/范围/风险/平台权限门禁。安装投影必须走 `sdd install-skill` 并验证无漂移。

## 坑点与风险
整体重构审阅面较大，但比局部修补更能消除责任倒置。REFERENCE 会保持较长，这是精确合同层的有意取舍；通过章节导航提高可读性而非删减规则。Agent 指令只做窄补齐，避免把文档任务扩张为运行时功能改造。
