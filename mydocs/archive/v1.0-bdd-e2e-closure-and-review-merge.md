## Summary
当前 BDD/E2E 在 SDD 中只是声明，没有执行路径和证据闭环；Review 阶段与 Challenge 职责重叠。本任务实现：1) Execute Log 增加 AC Coverage 结构化记录；2) BDD Scenario→Test→Coverage 可审计映射链；3) validate AC 覆盖交叉检查(L1-L4)；4) E2E 环境不可用时 BLOCKED→人工决定；5) Review 合并进 Execute Completion Verification Gate；6) 去掉 FAIL_E2E_ENVIRONMENT。

## Intake

### Requirement
requirement: 实现 BDD/E2E 端到端闭环和 Review 合并进 Execute：1) Execute Log 增加 AC Coverage 结构化记录和 Completion Verification Step；2) BDD Scenario→Test→Coverage 可审计映射链；3) validate 增加 AC 覆盖交叉检查(L1-L4)；4) E2E 环境不可用时 BLOCKED→人工决定重试或跳过；5) Review 合并进 Execute Completion Verification Gate，Challenge 成为唯一门禁；6) 去掉 FAIL_E2E_ENVIRONMENT 裁决

### Constraints
- 向后兼容：现有 Spec 模板中 Review Verdict/Summary 字段在旧归档 spec 中保留，新 spec 不再生成
- validate 对没有 AC Coverage 的旧 Execute Log 不报错（渐进式门禁）
- Console 阶段显示需同步调整

### Scope
- validate.js: AC Coverage 交叉检查、Review Verdict 门禁替换为 Completion Verification 检查
- workflow.js: classifyIssue 更新、VERDICT_TO_TARGET 更新、PASS_WITH_CONCERNS 目标修正
- templates/spec-*.md: Review Verdict/Summary 替换为 Completion Verification + Challenge Verdict
- console.js: 阶段列表和门禁定义更新
- SKILL.md / GUIDE.md: 文档更新
- tests/commands.test.js: 新增测试

### Risks
- 旧归档 spec 中的 Review Verdict 字段不再被新 validate 检查，需确保不误报
- AC Coverage 交叉检查需要解析 Execute Log 中的结构化记录，格式设计需稳定

### Initial Acceptance Hints
- validate --archive-ready 对有 AC Coverage 的 Execute Log 做交叉检查
- 无 AC Coverage 的旧 Execute Log 不受影响
- Review 阶段从流程和 Console 中移除，Challenge 成为唯一门禁

## Research

### Requirement Review
- 当前 Execute Log 的 Step 格式没有 AC Coverage 字段，无法交叉验证
- validate 只检查 Review Verdict/Summary 有 PASS 行，不检查 AC 是否有执行证据
- Challenge 是 Review 的严格超集，Review 作为独立阶段价值有限
- E2E 环境问题没有处理路径，要么假装通过，要么整个任务卡住
- Console 阶段列表硬编码了 review 阶段

### Findings
- validate.js:374-380 检查 Review Verdict/Summary 有 PASS 行
- workflow.js:69 classifyIssue 中 Review Verdict 映射为 FAIL_CODE
- console.js:24 phases 数组包含 review
- console.js:30-39 gateDefinitions 包含 review 和 reviewPass
- templates 中 Review Verdict/Summary 紧接 Challenge Verdict

### Open Questions

### Assumptions
- 旧 Execute Log 没有 AC Coverage 记录是正常的，validate 对此渐进式处理
- Completion Verification Step 在 Execute Log 中是最后一个 Step
- SKIPPED AC 需要人工批准三要素（Reason + Approved By + Approved At）

### Confirmed Requirement
1. Execute Log 增加 AC Coverage 结构化字段（每 Step 增量 + Completion Verification 全量汇总 + 四轴自查清单）
2. validate 增加 AC 覆盖交叉检查：L1 每个 AC 有 Coverage、L2 结果 PASS、L3 Test 路径文件存在、L4 Scenario 名称 warning
3. E2E 环境不可用 → BLOCKED → 人工决定重试或跳过；SKIPPED 需人工批准三要素
4. Review 合并进 Execute Completion Verification Gate；Challenge 成为唯一门禁
5. 去掉 FAIL_E2E_ENVIRONMENT 裁决
6. Console 阶段列表和门禁定义同步更新

## Innovate Options
Option A: 一次性全部改造。Pros: 一步到位。Cons: 改动面大，测试回归风险高。
Option B: 分步改造——先做 Review 合并和 AC Coverage 格式，再做 validate 交叉检查，最后更新文档和 Console。Pros: 每步可独立验证。Cons: 中间状态需要兼容处理。
Selected: 方案 B，分步推进，每步可验证。
