## Design Note

Approach:
在 `review-execute.js` 拆分两条 diff 路径：
- **分支模型（opt-in）**：仅当 CLI 显式传 `--diff-base <ref>`（且 `isSafeGitRef` 通过）时启用，行为同现状 `git diff <ref> HEAD`，Diff source 标 `<ref>..HEAD`。
- **工作区模型（默认）**：未传 `--diff-base` 时，组合
  1. 已跟踪改动：`git diff HEAD`
  2. 未跟踪文件：`git ls-files --others --exclude-standard` 列出，对每个文件 `git diff --no-index -- /dev/null <file>`（捕获退出码 1），拼到 diff 末尾。
  Diff source 标 `working tree`。
非侵入：全程只读，不执行 `git add` / `git add -N`，不改 index 或工作区。
分支模型仅由**显式 CLI `--diff-base`** 触发；frontmatter `diff-base` 不再被消费（模型 B 下 discover 自动盖的该字段会让默认退回 base..HEAD，故弃用，视为 deprecated）。默认工作区路径不调用 `resolveDiffBase()`。无 git / git 失败 → 维持 `(no git diff)`；500 行截断逻辑在合并后的 diff 文本上照常生效。

Impact Scope:
仅 `src/commands/review-execute.js`（diff 解析与 Diff source 标签）。不动 prompt 结构、其余 4 轴、Learning Brief、`validate`、`archive`、`discover`。`resolveDiffBase` 保留但只在分支模型路径调用。

Interface / Data Impact:
CLI 仍是 `sdd review-execute <dir> [--spec ...] [--diff-base <ref>]`；`--diff-base` 语义从"覆盖自动基准"收窄为"切换到分支模型"。无持久化/数据结构变化。输出仅 `> Diff source:` 一行的取值变化（`working tree` | `<ref>..HEAD` | `unavailable`）。

Compatibility:
review prompt 各 `<!-- AXIS ... -->` 锚点与 Finding 行全部不变，下游解析（spec-index/console/validate 对 verdict 的处理）不受影响。原来依赖自动基准的用户改为显式传 `--diff-base` 即可恢复旧行为；回滚=还原本文件单文件改动。

Risks:
- `git diff --no-index /dev/null` 在个别 git 版本/路径含空格时行为差异 → 用 execFileSync 参数数组传参、逐文件 try/catch，单个失败不影响整体。
- 未跟踪文件很多/很大 → 已有 500 行截断兜底；必要时未跟踪部分可只附文件名（本期先附内容，留观察）。
- 二进制未跟踪文件 → `git diff --no-index` 输出 "Binary files differ"，可接受。

Test Strategy:
`tests/commands.test.js` 新增用例，用 `execSync('git init')` 建临时 repo 并初始提交基线，然后：
- 改一个已跟踪文件 + 新建一个未跟踪文件，跑 `review-execute`，断言 Axis 2 同时含两者、`Diff source: working tree`（AC-001/002/004）。
- 传 `--diff-base <初始commit>`，断言 `Diff source: <ref>..HEAD` 且走分支模型（AC-003）。
- 非 git 目录跑 review-execute 仍输出 `(no git diff)` 不崩（AC-005，复用现有 demo）。
