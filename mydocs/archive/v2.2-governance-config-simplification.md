## Summary
本任务收敛 SDD 的治理配置和门禁语义，目标是减少全局配置项，改为约定优先的阶段退出标准。
核心决策：Approval 只管 Plan Gate；Independent Review 只管 Research Gate 和 Challenge；Cruise 默认开启，仅作为有界修复循环契约。
本任务已进入 Execute 后调整阶段。用户确认当前仍在快速迭代，历史兼容不用保留，因此目标从“新语义优先、旧入口兼容”收敛为“只保留干净的新控制面”。

## Intake

### Requirement
收敛 SDD 治理配置与门禁语义：以 Phase Exit Criteria 替代“每阶段 Approval”；只保留 `APPROVAL_POLICY=agent|human`，删除旧 `GATE_POLICY` / `auto-gate` 兼容；将 Independent Review 与 Approval 拆开，standard/lite reviewer 使用 `subagent:<id>|external-agent:<id>|human:<name>`，micro Challenge 可 `inline`，不接受裸 `subagent`；Cruise 默认开启，只保留 `CRUISE_ENABLED=true|false` 与 `CRUISE_MAX_ITERATIONS`，删除旧 `CRUISE_POLICY`；只保留 `sdd cruise --driver`，删除 `--engine` 别名；`MODE` 从项目级配置中移除，新任务无 `--mode` 时默认 micro。

### Constraints
- 不保留历史兼容路径；当前仍在快速迭代，优先保持 SDD 控制面干净。
- `GATE_POLICY`、`CRUISE_POLICY`、`--engine`、`auto-gate`、裸 `subagent`、项目级 `MODE` 不再作为有效输入或推荐输出。
- 先用 TDD 覆盖行为，再实现。
- README、GUIDE、SKILL、TEAM-GUIDE、模板、Console、测试需要同步。

### Scope
本任务覆盖配置读取、validate 门禁、challenge 记录、cruise 参数和输出、init 默认配置、Console 展示、模板说明、文档协议说明和测试。不会改动 Spec 文件命名、归档目录结构、AC Coverage 格式或核心 RIPER 阶段顺序。

### Risks
- 迁移风险：旧项目仍使用 `GATE_POLICY=auto|manual|advisory`、`CRUISE_POLICY=off|assisted|autonomous`、`--engine` 或 `auto-gate` 时会被新规则拒绝；这是用户确认接受的快速迭代取舍。
- 语义风险：如果 Independent Review 继续被解释成 Approval，会重新造成字段混乱。
- 文档风险：README/GUIDE/SKILL/TEAM-GUIDE 任一处未同步都会误导 agent。

### Initial Acceptance Hints
- 新项目 `.sdd-config` 默认只写必要配置，不再主动写 `MODE`、`GATE_POLICY`、`CRUISE_POLICY`。
- `common` 层提供 `getApprovalPolicy()` 和 `getCruiseEnabled()`，只读取新字段。
- `validate` 能区分 Plan approval 和 independent reviewer evidence。
- `sdd cruise --driver auto` 可用，`--engine` 不再是有效参数。

## Research

### Requirement Review
当前问题不是缺少某个配置项，而是配置项承担了错误责任。`GATE_POLICY` 名义上控制门禁，实际只应控制 Plan Approval；`CRUISE_POLICY` 名义上控制巡航，实际混合了是否启用、是否人协助、是否宿主原生循环三层含义；`MODE` 作为项目级默认值又和“每个任务默认 micro，按风险升级”的模式选择规则冲突。

正确的模型应将“批准权”“独立审查”“修复循环驱动”拆开。批准权只决定谁能让 Plan 进入 Execute。独立审查只记录谁以独立角色审查 Research/Challenge。Cruise 只是在 Challenge FAIL 后生成有界修复循环契约，默认开启，驱动方式由命令参数和宿主能力决定。

### Findings
- `lib/common.js` 当前仍有 `GATE_POLICY`、`CRUISE_POLICY` 和项目级 `MODE` 读取路径，需要删除以避免旧语义继续生效。
- `src/commands/validate.js` 当前只有 Plan Gate 是明确 approval；Research Gate 检查 `Research Reviewed By/At`，Challenge 检查 `Challenge Executed By/At/Evidence`。
- `src/commands/validate.js` 当前 standard/lite 的 Challenge 只允许包含 `subagent`，但 Research Gate 没有同等独立 reviewer 校验。
- `src/commands/cruise.js` 的 `--engine` 只影响 prompt 输出和 run ledger，不是真正执行引擎；该名称会误导使用者，需要删除。
- `src/commands/init.js` 当前默认写入 `MODE`、`GATE_POLICY`、`CRUISE_POLICY` 和 `CRUISE_MAX_ITERATIONS`，配置显得比实际协议更重。
- Console 当前展示 `gatePolicy`、`cruisePolicy` 和 `maxIterations`，需要迁移为 approval / cruise enabled / max iterations / driver 语义。

### Open Questions
无。用户已确认：采用约定优先模型，Cruise 默认开启，Independent Review 的具体执行者由宿主按约定选择，SDD CLI 只校验可审计声明。

### Assumptions
- `APPROVAL_POLICY=agent` 是默认值，表示 agent 可批准 Plan，但必须写 `Gate Evidence`。
- `APPROVAL_POLICY=human` 表示 Plan Gate 必须由 `human:<name>` 批准。
- 旧 `GATE_POLICY` 不再读取；缺少 `APPROVAL_POLICY` 时默认 `agent`。
- 旧 `CRUISE_POLICY` 不再读取；缺少 `CRUISE_ENABLED` 时默认开启。
- `auto-gate` 不再是有效 Plan approval；agent approval 必须写 `agent:<id>`。
- 裸 `subagent` 不再是有效 reviewer；必须写 `subagent:<id>`。

## Innovate Options

Option A: 最小兼容改名（已废弃）
- 做法：只新增 `APPROVAL_POLICY`、`CRUISE_ENABLED`、`--driver`，旧字段继续读，文档改为推荐新字段。
- 优点：风险低，迁移简单，测试范围清晰。
- 缺点：短期仍保留旧字段兼容逻辑。
- Requirement Fit：高。

Option B: 强制清理旧字段（当前选择）
- 做法：删除 `GATE_POLICY`、`CRUISE_POLICY`、`--engine` 和 `auto-gate`。
- 优点：模型最干净。
- 缺点：破坏旧项目和旧测试。
- Requirement Fit：高。用户已确认历史不用兼容，当前快速迭代优先保持 SDD 干净。

Option C: 增加完整执行者追踪
- 做法：新增 `Research Produced By`、`Implementation Executed By` 等字段，严格证明 reviewer 与 producer 不同。
- 优点：审计最严密。
- 缺点：字段显著增加，违背减少配置和约定优先目标。
- Requirement Fit：中。

Selected Option: 选择 Option B。因为用户确认历史不用兼容，保留旧入口反而会污染控制面。执行者追踪先不扩展为强制字段，只强制 reviewer/approval 值使用可审计的新格式。
