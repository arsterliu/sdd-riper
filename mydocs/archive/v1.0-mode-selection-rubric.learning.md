## Learning Record

Source Spec: mydocs/specs/v1.0-mode-selection-rubric.md
Trigger: PASS_WITH_CONCERNS review verdict — 自动驾驶 cruise 在本 spec 上触发安全停车（human_required），经查为风险误报。
Observed Problem: cruise 自动驾驶迭代 2 报 RISK_FLAGS=security,billing,migration,irreversible 并 stopReason=human_required，但本次改动只是新增 advisory 文档与一行打印，实际零风险。原因是这个 spec/rubric 文本本身在"列举"这些风险关键词。
Root Cause: `workflow.js::riskFlags()` 用纯关键词正则扫描整篇 spec 文本判定风险，无法区分"这段代码做高风险操作"与"这段文字在谈论风险"。meta-spec（讲 SDD/风险分类本身的 spec）必然误命中。次生问题：正则 `/\bsecurity|auth|permission|credential|secret\b/` 的 `\b` 只锚定首尾两项，中间 `auth|permission|credential` 无词界，会子串误匹配（如 "author"→auth）。
Decision Rule: 写"关于风险/安全主题"的 meta-spec 时，预期 riskFlags 会误报、自动驾驶会安全停车；由人确认实际改动面后 override，并把误报记成 learning，而不是为绕过检测而删改 spec 里的术语。长期应让 riskFlags 基于"改动/Plan 的动作"而非整篇文本叙述来判定。
Applies When: spec 或 rubric 文本大量出现 security/auth/billing/migration/schema/irreversible 等词，但实际 Impact Scope 仅文档或 advisory；或在 SDD 自身上做 dogfood。
Does Not Apply When: 改动真的触及鉴权/计费/数据迁移/不可逆操作——此时风险 flag 是真阳性，必须按契约停车并补对应 Design 字段。
Recommended Action: 1) 人工核对 Impact Scope 确认真实风险面；2) 误报则在 Review 记 PASS_WITH_CONCERNS 并沉淀本条；3) 后续可选改进——riskFlags 改为只扫 Plan/Design 的"动作"区或代码 diff，并修正 security 正则的 `\b` 词界。
