# Technical Design

## Technical Design

Selected Option / ADR: Option B — 复用 GATE_POLICY，Challenge 证据门禁与 Plan 门禁策略一致

Requirement Traceability: CR-1 证据三要素 → AC-001, CR-2 auto 模式 → AC-002, CR-3 manual 模式 → AC-003, CR-4 standard/lite subagent → AC-004, CR-5 micro inline → AC-005

Impact Scope: validate.js（校验逻辑）、spec 模板（新增字段）、SKILL.md/GUIDE.md（文档）

Architecture View:
```
validatePlanGate(content, gatePolicy, archiveReady, issues)
  ├── Plan Approved By / Approved At / Gate Evidence

validateChallengeEvidence(content, mode, gatePolicy, archiveReady, issues)  ← 新增
  ├── Challenge Executed By / Challenge Executed At / Challenge Evidence
  ├── standard/lite → Executed By 必须含 subagent
  └── micro → Executed By 可以是 inline
```

Data Model / Schema:
- Spec Review Verdict 区域新增三个字段：
  - `Challenge Executed By: <subagent|inline|auto-gate|<agent-id>>`
  - `Challenge Executed At: <ISO-8601>`
  - `Challenge Evidence: <verdict + summary from independent agent>`

Interface Contract: validate --archive-ready 新增校验逻辑，返回的 issues 数组可能包含新的 Challenge 证据相关 issue

Compatibility / Rollback:
- 归档 spec 不受影响（validate 只在 archiveReady 时检查）
- 现有 active spec 缺少证据字段 → validate 会新增 issue，这是预期行为（门禁生效）
- 模板新增字段是向后兼容的（新增空字段不破坏已有 spec）

Test Strategy:
- 单元测试：validateSpec 对各种 gate policy + mode 组合的 Challenge 证据校验
- 现有测试不退化

Risks / Trade-offs:
- 现有 active spec 缺少 Challenge 证据字段 → validate 会报新 issue，需要人工补充 → 这是门禁生效的预期行为，不是 bug
