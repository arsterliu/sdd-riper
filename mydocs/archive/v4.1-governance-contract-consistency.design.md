## Technical Design

Selected Option / ADR: ADR-001 — 采用最小运行时 Governance Contract Registry 加投影一致性测试。Registry 只拥有稳定、离散且会影响治理行为的事实；运行时消费者直接引用，文字投影保留独立可读性但受合同测试约束。拒绝仅靠测试的 Option B，因为它不能消除运行时重复事实；拒绝外部 JSON/YAML 生成系统的 Option C，因为它扩大了解析、发布和兼容风险。

Requirement Traceability:
- R-001 mode 字段及 required/recommended：Registry 定义每种 mode 的字段集合与严格度。micro 当前既有的五个必填 Plan 字段保持必填；Scope、Touched Files、Change、Blast Radius 保留为推荐字段；Provider 仅在 E2E 条件成立时必填。
- R-002 E2E Provider：Registry 定义 Verification 为 e2e 时必须有命名 Provider，同时保留现有 Test 或 Manual Evidence 规则。活动制品缺失 Provider 维持 fail-closed。
- R-003 默认值：Registry 定义默认 mode、Plan approval policy、Cruise enabled 与默认 iteration budget；common/init/文字投影引用或验证这些事实。本仓 20 是 .sdd-config 的项目覆盖，不改写为默认值。
- R-004 verdict/reviewer grammar：Registry 定义允许 verdict、verdict 到 backtrack target 映射、可审计 reviewer grammar 和 micro inline 例外；Challenge Evidence 仍仅由 challenge record-result 命令写入。
- R-005 投影漂移：模板、SKILL、README、GUIDE、package、AI 生成器和根 AI 文件通过合同测试保持当前术语与强制规则一致。

Impact Scope:
- 新增 src/core/governance-contract.js，作为纯数据和纯谓词模块。
- 修改 lib/common.js、src/commands/init.js、src/commands/challenge.js、src/commands/validate.js、src/core/spec-state.js、src/verification/readiness.js，使其只消费相关合同事实。
- 修改 templates/spec-standard.md、templates/spec-lite.md、templates/spec-micro.md、SKILL.md、README.md、GUIDE.md、package.json、src/commands/_gen-ai-configs.js、AGENTS.md、CLAUDE.md 的合同投影。
- 新增 tests/governance-contract.test.js，并在 commands/state-matrix 的既有回归中补充消费者行为。
- 不修改 bin/cli.js 的公开命令表、Run schema/store、Visual/Verification provider、Quality/Console projection、path containment 或完整 workflow gate evaluator。

Context / Boundary: Registry 不读取文件、不解析 Markdown、不执行命令、不产生 CLI 输出，也不保存可变状态。它只提供治理常量、mode/verification 条件判断、reviewer/verdict 谓词和投影测试所需的语义标识。artifact-snapshot、spec-state 继续负责制品解析与工作流路由；validate 继续负责诊断与 CLI 呈现；readiness 继续负责 Provider 配置与证据新鲜度。

Domain Model:
- Governance Contract：一个版本内稳定的治理事实集合。
- Runtime Consumer：根据合同判断活动制品、路由或 CLI 输入是否合法的模块。
- Projection：面向人或特定 agent 的模板、Skill、文档、package 描述和受控 AI 区块，不是新的运行时权威。
- Project Override：.sdd-config 中显式声明的项目策略；例如 Cruise budget 为 20，优先于默认 5。
- Legacy Artifact：已有归档 Spec/Design/Log；必须可读取，不能通过本任务重写或迁移。

Architecture View:
Governance Contract Registry -> Runtime Consumers: common, init, challenge, validate, spec-state, readiness。
Governance Contract Registry -> Contract Tests -> Static Projections: templates, Skill, docs, package, AI generator。
AI Generator -> Managed Blocks -> Root AGENTS.md and CLAUDE.md; block 外的项目专属指令保持原样。
Project Override (.sdd-config) -> common config reader -> Runtime Consumers; 覆盖默认值但不改变 Registry 中的全局默认定义。

Data Model / Schema:
- defaults：mode=micro、approvalPolicy=agent、cruiseEnabled=true、cruiseMaxIterations=5。
- planFields.micro：required=[Impact Scope, Data Impact, Interface Impact, Acceptance, Verification]；recommended=[Scope, Touched Files, Change, Blast Radius]；conditional=[Provider when Verification=e2e]。
- acceptanceRules：e2e 要求 Provider 与现有 Test 或 Manual Evidence；manual 要求 Manual Evidence；Automated=yes 要求 Test。
- challenge：verdicts=[PASS, PASS_WITH_CONCERNS, FAIL_SPEC, FAIL_DESIGN, FAIL_ACCEPTANCE, FAIL_PLAN, FAIL_CODE, FAIL_LOG, FAIL_LEARNING]；passingVerdicts=[PASS, PASS_WITH_CONCERNS]；每个 verdict 有既有 backtrack target；reviewer 身份为 subagent、external-agent、human，micro 额外允许 inline。
- projectionSemantics：仅保存被测试的稳定语义标识和术语，不存放整篇文档文本或用户自定义内容。

Data Migration / Backfill: 无。不会批量修改历史 Spec、Design、Execute Log、Learning、Run 或已有 .sdd-config。对活动制品施加的新增诊断只使用现有标签；历史/归档制品在读取、索引和展示路径上保持宽容。

Interface Contract:
- Registry 导出只读常量和纯函数，例如默认值、modeFields(mode)、requiresProvider(verification)、isAuditableReviewer(mode, value)、verdicts、isKnownVerdict(value)、isPassingVerdict(value)、backtrackTarget(verdict)。未知 verdict 的 backtrackTarget 返回空字符串，保持现有 expectedTarget 无路由语义并 fail-closed。
- 现有 public CLI 参数、标签、成功文本和 error code 不改变。消费者可改变其内部来源，但保留现有错误措辞；新增的 Provider 诊断采用 readiness 已有的 fail-closed 表述。
- AI 生成器继续使用现有 start/end 标记；首次融合仅追加或替换标记内的受控规则，绝不覆盖标记外文本。

API Protocol: 不新增外部 API、网络协议、CLI 子命令或配置文件格式。

State / Concurrency: Registry 是进程内不可变数据，无 I/O、缓存或并发写入。每次 CLI 调用读取当前 .sdd-config 覆盖；不得跨请求缓存 Provider evidence 或项目配置。

Failure Modes:
- 未知 mode、verdict 或 reviewer：继续由既有 CLI/validator 拒绝，使用 Registry 谓词但保持错误语义。
- 活动 E2E AC 缺 Provider：validate/spec-state/readiness 产生一致的 fail-closed 诊断；不能因 Test/Manual Evidence 存在而绕过。
- 受控 AI 区块不存在或损坏：生成器仅追加新的完整区块；存在成对标记时才原位刷新；不删除用户文本。
- 文档投影漏改：合同测试失败，阻止合并；运行时不在用户命令期间读取文档。
- 历史制品缺少新字段：读取、状态索引和展示不崩溃；严格活动制品验证与归档兼容路径由测试分别覆盖。

Security / Permission: 保留 reviewer evidence 的严格身份 grammar 与 Challenge Evidence 的命令写入边界；Registry 不接受外部输入来执行命令或加载模块。AI 配置融合只写确定性的本地字符串，不读取或执行 Profile commandRefs，也不初始化 Provider。

Observability: 合同测试失败信息必须指出合同事实、投影文件和缺失/冲突语义；CLI 继续输出既有错误代码和人类可读诊断。执行阶段将记录每个消费者迁移、受控区块融合和全量测试结果。

Performance / Capacity: 合同为常量与少量纯函数；相对现有多处正则和数组查找不会增加可感知启动或验证成本。投影检查只在测试中运行，不进入日常 CLI 热路径。

Compatibility / Rollback:
- 不变项：CLI 命令、标签、error codes、Markdown 基本格式、既有 Challenge record-result 路径、Provider/Run schema、安全 containment 和历史制品文件内容。
- 兼容策略：严格合同应用于新建或活动制品；归档制品保持可读，且不得要求迁移。推荐字段不得被升级为新的 blocker。
- 回滚策略：Registry 是内部模块；若任一消费者回归，可恢复其原有局部实现，同时保留合同测试作为定位证据。受控 AI 区块可以以一次普通 init 刷新到上一个已验证版本；不得使用 init --force 重写本仓 .sdd-config。

Test Strategy:
- Method: tdd。先在 tests/governance-contract.test.js 写失败测试，定义 Registry 的 defaults、micro required/recommended、E2E Provider、verdict/target 和 reviewer grammar。
- Contract projection tests：断言三种模板、SKILL、README/GUIDE、package、AI generator 和根 AI 受控区块携带正确的语义及现行术语；同时断言自定义根配置文本在 init 融合后保留。
- Consumer regression tests：在 commands/state-matrix/readiness 测试中验证活动 E2E 缺 Provider 仍 fail-closed、micro 五项必填保持、推荐字段不新增 blocker、CLI 文案/error code 不变。
- Compatibility tests：使用归档/legacy 样例验证读取与索引不因新合同崩溃；不对归档文件做写入。
- Verification commands：先运行聚焦的 node --test 测试文件，再运行 npm test 和 git diff --check；若失败，先运行 sdd debug 再重试。

Risks / Trade-offs:
- 共享的合同模块会使消费者有共同依赖，但这正是稳定离散事实应有的依赖；通过禁止 Registry 承担解析、路由和 I/O，避免形成新的大一统 evaluator。
- 文本投影不能完全自动生成，否则会损害面向不同读者的说明与项目自定义内容；以受控区块和一致性测试换取可读性与防漂移。
- Provider 规则在部分 validator 路径变得更早可见，但这是把既有 readiness fail-closed 语义统一到所有活动制品诊断，不改变其安全方向。
