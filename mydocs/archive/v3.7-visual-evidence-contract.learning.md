## Learning Record

Source Spec: mydocs/specs/v3.7-visual-evidence-contract.md
Trigger: 独立 Challenge 在 BUGFIX 后发现视觉合同仍可能因不完整的 direction 基线或表面合法的时间而错误进入 ready。
Observed Problem: 可选 Context 清单一旦参与 Plan 门禁，就同时是状态与安全边界输入；仅验证字段外形或只覆盖 fidelity 分支不足以保证方向模式的就绪结论可信。
Root Cause: 初始实现将 direction 基线视为展示性信息，未把已批准基线的状态、路径、realpath 和批准时间与 fidelity 一样当作合同完整性条件；对 `next` 的门禁归类也缺少显式映射。
Decision Rule: 任何会影响工作流就绪度的本地 Context 合同，必须在所有模式上校验允许枚举、完整字段、真实可解析时间和 lexical/realpath containment；其诊断必须映射到拥有该前置条件的门禁，并以正常路径和链接逃逸路径分别回归。
Applies When: 新增或扩展由 Spec 引用、会影响 Plan/Execute/Archive 路由的 JSON、YAML 或其他本地证据合同。
Does Not Apply When: 仅供展示、完全不影响任何工作流决策且不读取本地路径的自由文本说明。
Recommended Action: 先列出每个模式的状态转移与路径输入，再为无效枚举、缺失/越界/链接逃逸路径、非法时间和门禁路由写失败测试；通过后再接入 `validate`、`next` 或其他投影层。
