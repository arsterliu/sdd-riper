## Summary
提升 workflow 引擎两类 advisory 信号的可信度：(1) Learning 召回从"按 mtime 取最近 5 条"升级为基于 `Applies When`/`Decision Rule` 与当前 spec 的词法相关性排序，并新增 `sdd learnings` 项目级聚合视图；(2) `riskFlags` 从扫整篇 spec 叙述改为扫"动作区"(Plan/Design)，并修 security 正则词界 bug。两者同属"让引擎的 advisory 信号反映真实信号而非文字噪音"。纯 Node、确定性、无新依赖。

## Intake

### Requirement
requirement: Learning 召回从 mtime-recency 升级为相关性排序；新增项目级 learning 聚合视图(sdd learnings)；并把 riskFlags 从扫全文叙述改为扫动作区(Plan/Design)并修 security 正则词界
goal: review 召回到真正相关的历史教训；可一览全项目 learning；riskFlags 不再被 meta 叙述误报

### Constraints
constraints: 纯 Node、确定性、无模型/无新依赖；无词法信号时回落 recency 保持向后兼容；不破坏现有命令与测试

### Scope
- 改：`src/core/learning.js`（召回排序 + 聚合）、`src/commands/review-execute.js`（learningBrief 用相关性召回）、`src/core/workflow.js`（riskFlags 扫描区 + 正则）、新增 `src/commands/learnings.js` + `bin/cli.js` 注册、测试。
- 不改：learning 沉淀格式（8 字段不变）、archive 流程、spec/design 模板。

### Risks
- riskFlags 扫描区收窄可能漏掉只在 Research 叙述、未落到 Plan/Design 的真风险 → 用"动作区为空时回落全文"兜底。
- 相关性召回若实现不当可能比 recency 更差 → 无词法重叠时回落 recency，保证不劣化。

### Initial Acceptance Hints
召回结果按相关性排序且可回落；`sdd learnings` 输出项目级清单；riskFlags 在 meta-spec 上不再误报、对真实迁移类 spec 仍报警；security 正则不再子串误匹配。

## Research

### Requirement Review
三条诉求同源——引擎对外输出的 advisory 信号（Learning Brief、RISK_FLAGS）当前由"全文/时间"驱动，与任务真实语义脱节：召回按 mtime 取最近 5 条（`learning.js:112-128`），与当前任务无关；riskFlags 扫整篇 spec（`workflow.js:83-96`），meta-spec 必误报；security 正则 `\b` 词界 precedence bug 致子串误匹配。

### Findings
- 召回唯一相关消费方是 `review-execute.js::learningBrief`（`listLearningFiles(projectDir,5)`）；`resume.js` 仅用它数总数(limit 10000)，不关心顺序。故升级排序不影响 resume。
- 每条 learning 已有结构化字段 `Applies When`/`Decision Rule`/`Observed Problem`，天然是相关性匹配面，无需新增元数据。
- riskFlags 输入是整篇 spec content（analyzeSpec 传入）。改为传"动作区"文本（Plan + Design 章节）即可收窄，无需改 riskFlags 签名语义太多。
- SDD 哲学要求确定性、纯 Node、引擎内不调模型 → 召回必须用**词法重叠**评分，不能用 embedding。
- 已有 dogfood 证据：v1.0-mode-selection-rubric 的 cruise 账本显示 riskFlags 在 meta-spec 上误报（迭代2 human_required）。

### Open Questions
- 无（匹配面=已有字段；评分=词法重叠；回落策略=recency / 全文；命令形态=stdout 视图均已定）。

### Assumptions
- 词法重叠（去停用词后 token 交集，`Applies When` 加权）足以把相关教训排到前面，无需语义模型。
- 项目级视图用 `sdd learnings` stdout 聚合即可满足"全项目一览"，不必新增一个会与 per-spec 记录漂移的手工 PROJECT.md。

### Confirmed Requirement
1. `learning.js` 新增 `recallLearnings(projectDir, queryText, limit)`：按 `Applies When`+`Decision Rule`+`Observed Problem`+标题 与 query 的词法重叠打分，降序取 top-N，零重叠时回落 mtime recency；`listLearningFiles` 保留不变。
2. `review-execute.js::learningBrief` 改用 `recallLearnings`，query 取当前 spec 的 Intake/Confirmed Requirement/Plan 文本，并标注每条相关度。
3. 新增 `sdd learnings [dir] [--for <spec>]`：无 `--for` 输出项目级聚合清单（全部 learning 的 Applies When/Decision Rule 摘要）；带 `--for`（或默认活跃 spec）输出相关性召回 top-N。
4. `riskFlags` 改为扫"动作区"（Plan + Design 章节文本），动作区为空时回落全文；修正五类正则为带词界的 `/\b(...)\b/`。
5. 全程纯 Node、确定性、无新依赖；现有命令与测试不破坏；新增行为有测试覆盖。

## Innovate Options
<!-- Compare at least two options. Write the option analysis in Chinese. -->

### 选项 1（选定）：复用 per-spec 记录做词法相关性召回 + stdout 聚合视图
- 召回：以现有 `.learning.md` 为唯一真相源，`recallLearnings` 按字段词法重叠打分排序，零重叠回落 recency。
- 项目级：`sdd learnings` 实时聚合所有 learning 输出，不落新文件。
- 优点：无新真相源/无漂移、确定性、向后兼容、不引依赖；契合 SDD 哲学。
- 缺点：词法匹配弱于语义，靠 `Applies When` 写得好坏。

### 选项 2：新增手工维护的项目级规则文件 `learnings/PROJECT.md`
- 把提炼规则手工汇总到一个文件，召回直接读它。
- 优点：项目级视图集中、可人工润色。
- 缺点：与 per-spec 记录双真相源、易漂移过期；增加人工负担；与"沉淀已结构化"重复。否决。

### 选项 3：语义/embedding 召回
- 用向量相似度做召回。
- 优点：相关性最强。
- 缺点：需模型/依赖、非确定性，违反 SDD"引擎内不调模型、纯 Node、确定性"原则。否决。

Selected: 选项 1。
