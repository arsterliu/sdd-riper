## Summary
当前任务处于 Plan approved，准备进入 Execute。目标是把 SDD-RIPER 初始化生成 AI agent 配置的策略，从“文件级创建/force 覆盖”调整为“SDD-RIPER managed block 追加/更新”。核心约束是保护已有项目规则，生成内容保持 thin bootstrap，由 `sdd-riper` skill/CLI 驱动详细流程。验收将覆盖新文件创建、已有文件追加、已有 marker 更新、`--force` 不覆盖用户内容等场景。

## Intake

### Requirement
requirement: 初始化 SDD-RIPER 时，已有 AGENTS.md/CLAUDE.md/.cursorrules/Copilot 指令不应被覆盖，而应追加或更新 SDD-RIPER managed block；--force 也只刷新该区块，除非未来提供显式危险覆盖选项。
goal: 保护项目已有 agent 配置，同时让 SDD-RIPER guardrails 可见且可更新。

### Constraints
constraints: 生成内容保持 thin bootstrap，不复制完整 skill；必须保留制品标题/字段英文、内容中文。

### Scope
本次只调整 `sdd init` 调用的 AI 配置生成行为，覆盖 `AGENTS.md`、`CLAUDE.md`、`.cursorrules`、`.github/copilot-instructions.md`。不改变 Spec/Design/Execute Log 目录初始化，不新增危险覆盖选项，不重写完整 skill 内容。

### Risks
已有文件可能包含团队自定义规则；如果继续 force 覆盖会丢失用户内容。无 marker 的追加必须避免重复追加；有 marker 的更新必须只替换 SDD-RIPER 区块。不同配置文件格式不同，但都可以用 HTML 注释 marker 承载 managed block。

### Initial Acceptance Hints
- 已存在 `AGENTS.md` 时，`sdd init` 不应丢失原内容。
- 已存在 SDD-RIPER marker block 时，重复初始化应刷新该 block 而非追加重复内容。
- `--force` 不应成为覆盖用户 agent 配置文件的隐式危险开关。

## Research

### Requirement Review
用户确认初始化 SDD-RIPER 时不应覆盖已有 `AGENTS.md` 这类文件，而应追加/合并。结合上一轮讨论，agent 配置应是 thin bootstrap + hard guardrails，完整流程由 `sdd-riper` skill 和 CLI 驱动。

### Findings
当前 `src/commands/init.js` 将 `force` 传给 `src/commands/_gen-ai-configs.js`。生成器的 `writeConfig` 在文件存在且无 force 时跳过；在 force 时直接 `fs.writeFileSync` 覆盖整个文件。测试目前只断言初始化会创建 `AGENTS.md` 且包含若干关键词，没有覆盖已有文件保护或 marker 更新行为。

### Open Questions
是否需要新增显式危险覆盖选项本次不处理；当前需求只要求不覆盖、改为追加/更新。

### Assumptions
使用 HTML 注释 marker 可兼容 Markdown、Cursor rules 和 Copilot instructions。`--force` 的语义调整为强制刷新 SDD-RIPER managed block 与 `.sdd-config`，不再全量覆盖 AI 配置文件。

### Confirmed Requirement
将 AI 配置生成改为 managed block upsert：文件不存在时创建 thin bootstrap；文件存在无 SDD-RIPER block 时保留原文并追加 block；文件存在已有 block 时只替换 block 内容；`--force` 也不得删除用户原有内容。

## Innovate Options
Option A: 继续当前 skip/force overwrite。Pros: 实现简单，行为稳定。Cons: `--force` 会破坏已有项目规则，不符合用户要求。
Option B: 无脑 append SDD-RIPER 段落。Pros: 不覆盖用户内容。Cons: 重复初始化会产生重复、冲突和过期说明。
Option C: managed block upsert。Pros: 首次追加、后续只更新 SDD-RIPER 自有区块，保护用户内容且保持可维护。Cons: 需要 marker 解析和测试覆盖。
Selected: Option C。Rejected: Option A 会覆盖用户内容；Option B 会累积重复内容。
