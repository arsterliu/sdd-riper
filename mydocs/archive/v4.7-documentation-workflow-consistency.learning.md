## Learning Record

Source Spec:
mydocs/specs/v4.7-documentation-workflow-consistency.md
Trigger:
Plan 批准后，用户明确追加“当前任务自动推进至归档”授权，使 Cruise 开关成为实际变更的一部分；初始 Plan 却将配置排除在范围外。随后 archive 在摘要生成时发现微型 Spec 缺少 `Selected Option`，而微型模板与指南未要求该字段。最后，用户连续指出 README、GUIDE 和 REFERENCE 的可读性问题：入口文档堆协议、场景指南像手册、精确参考缺少导航。
Observed Problem:
即使新增操作有明确用户授权，若其没有同步反映到 Plan 的范围、受影响文件和爆炸半径，执行日志与代码差异审查会出现“已授权但计划外”的审计不一致。若一个模式缺少独立 Design，而归档器又依赖选择记录生成摘要，未在该模式的模板和指南中公开该字段会导致 archive-ready 通过后仍在实际 archive 失败。若人类文档被测试要求逐字复制 agent 协议，就会在“易读”与“测试通过”之间形成假冲突；即使 README 已经简化，只要 GUIDE 同时承担上手教学和精确协议参考，它仍会以授权原文、内部字段和超长流程图开场，普通使用者无法顺着任务场景阅读。
Root Cause:
将用户在 Plan 通过后追加的操作授权视为执行细节，而没有立即把会留下持久化项目配置的变更作为计划范围勘误处理；同时，归档摘要的输入契约没有与微型任务的 Plan 字段清单同步；文档回归没有区分“快速入口”“场景指南”和“精确协议参考”的不同职责。此前只把协议从 README 下沉到 GUIDE，实际只是移动了信息负担，没有为普通用户建立独立的任务旅程层。
Decision Rule:
1. Plan 批准后收到会改变受控文件的明确用户指令时，先判断它是否持久化或影响后续任务；若是，必须在执行前或紧随执行后补充 Plan 的 Impact Scope、Touched Files、Change、Blast Radius 与相应验收/验证边界，并在 Execute Log 追加新 Step 和新的最后 Completion Verification。用户的明确追加授权可以作为该窄范围勘误的 Gate Evidence，但不能被静默当作原 Plan 已包含。
2. 当 archive 读取某一决策字段生成摘要时，所有没有独立 Design 的模式都必须在其 Plan 模板、Skill 和指南中显式要求该字段；archive-ready 校验与实际 archive 都要用最小实例验证这一输入契约。
3. 人类 README、深度指南和 agent 协议应各自有可测试的受众契约：README 验证上手路径、自然语言入口和深度文档链接；GUIDE / SKILL / protocols 验证完整门禁与精确术语。不得为通过协议断言而把内部字段或英文规则堆回 README。
4. 面向 AI 协作的命令行工具应在快速开始中优先展示 AI 引导路径：先说明一次性安装与 Skill 登记，再提供可复制的自然语言模板，明确列出版本、任务名、目标和参考资料；直接 CLI 命令保留为备选，并用顺序回归防止入口再次倒置。
5. 当一份 GUIDE 同时承担上手教学和精确协议参考、导致普通用户必须先理解内部字段时，应拆成三层：README 提供最短入口，GUIDE 按真实场景说明用户输入、AI 动作、确认点和完成标志，REFERENCE 完整保留字段、门禁、安全边界与调度契约。迁移精确内容时优先整体保留而非摘要改写，并分别测试人类入口契约、协议保留契约、相互导航和发布清单。
6. 精确 REFERENCE 不必改写成第二份教程，但仍应提供独立的阅读导航层：用途说明、按问题分类的索引、核心术语的人话解释，以及每个主要章节的一句“本章回答”。导航层必须明确自己不替代规范正文；精确授权原文、字段、状态、命令和安全规则只移动或保留，不用摘要替换。回归同时断言导航位于协议正文之前和关键规范标记仍存在。
7. “精确协议”不等于所有受众都必须复制同一段英文。面向人类的 README、GUIDE、REFERENCE 和 TEAM-GUIDE 应用目标语言完整表达规则，并保留必要的字段、状态值和命令；供 Agent 直接加载的 SKILL、protocols 与生成配置保存英文硬契约。测试分别验证人类文档的完整语义与 Agent 文档的精确原文，避免为了逐字一致牺牲可读性。
Applies When:
任何 Plan 批准后新增的配置、文档、脚本、运行账本或其他受控文件变更；尤其是“仅当前任务”的运行策略可能落到项目级配置时；micro 等内嵌设计模式需要被下游 archive 读取决策字段时；同一项目同时维护快速入口、人类使用指南和 agent/维护者协议文档时；以及产品主要通过 AI 对话驱动、CLI 只是底层控制面时。
Does Not Apply When:
不落盘的临时命令参数、只读检查结果，或原 Plan 已清楚列出的文件内的同类实现细节；有独立 Design 且下游字段已由该 Design 强制提供的 standard/lite 路径；只有一种受众、无需渐进披露的短文档。
Recommended Action:
在修改前重读 Plan；若用户新增授权涉及受控文件，先更新 Plan 或立即追加范围勘误 Step。完成后运行范围审查，保留旧 Completion Verification 为历史事实，并在勘误后追加新的最终 Completion Verification。对模板字段还要用最小实例验证 archive-ready 与 archive。重构文档时先定义每层受众：README 回答“怎么开始”，GUIDE 回答“这个场景下我和 AI 各做什么”，REFERENCE 回答“精确规则是什么”；先写分层失败断言，再整体迁移协议内容、重写场景层，并验证链接、npm 发布清单与权威协议标记。
