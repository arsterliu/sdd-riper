## Summary

当前阶段：Research。目标：将 Console 详情页中 Challenge（对抗评审）和 Cruise（自主巡航）的展示从 blocker 卡片文本行升级为结构化独立区域，覆盖完整生命周期（触发、裁决、回跳、修复循环、终止）。关键约束：Console 只读，不改后端，不改数据模型。

## Intake

### Requirement
Console 详情页对 Challenge 和 Cruise 的展示不充分——信息挤在 blocker 卡片一行文本中，缺少结构化展示、颜色区分、完整生命周期可见性。

### Constraints
- Console 只读投影，不驱动流程
- 后端数据已通过 parseSpec 完整传到前端，无需修改
- 不新增 API 端点

### Scope
- `src/web/console.js`：新增/修改渲染函数
- `src/web/console.css`：新增样式
- `src/web/index.html`：新增 section 容器
- 不修改后端

### Risks
- Challenge/Cruise 信息与现有 Status Overview section 有重叠（blockers、challengeVerdict、backtrackTarget 已在 Status Overview 中展示）→ 需要明确分区，避免重复

### Initial Acceptance Hints
- Challenge verdict 有颜色区分（PASS=绿、PASS_WITH_CONCERNS=橙、FAIL_*=红）
- Cruise run 有结构化展示（引擎、策略、迭代历史）
- Challenge 和 Cruise 生命周期可见

## Research

### Requirement Review
1. **歧义**：Challenge/Cruise 信息是放在现有 Status Overview section 还是新建独立 section？
2. **隐含假设**：cruiseRun.readLedger() 返回完整历史（count + latest），但前端只用了 latest
3. **风险**：信息分区重叠——blockers 已在 Status Overview，challengeVerdict/backtrackTarget 也在 blocker 卡片文本行

### Findings
1. `renderBlocker()` 中的 controlText 行包含 `challenge:` 和 `backtrack:` 文本，但无颜色、无结构
2. `cruiseRun` 对象包含 `count`、`latest`（iteration/engine/stopReason/gatePolicy/cruisePolicy/challengeVerdict/backtrackTarget/riskFlags），但前端只展示 latest 的 iteration/engine/stopReason
3. `workflow` 对象包含 `challengeVerdict`、`backtrackTarget`、`cruisePolicy`、`maxIterations`，前端只作为文本行展示
4. GUIDE 第八节声明"详情页展示 gate policy、cruise policy、challenge verdict 和 backtrack target"和"详情页展示最新 cruise run 的 iteration、engine 和 stop reason"——数据已有，展示不够结构化
5. Challenge 裁决类型：PASS / PASS_WITH_CONCERNS / FAIL_SPEC / FAIL_DESIGN / FAIL_ACCEPTANCE / FAIL_PLAN / FAIL_CODE / FAIL_LOG / FAIL_LEARNING — 需要颜色区分
6. Cruise stopReason 类型：pass / max_iterations / human_required / continue — 需要颜色区分

### Open Questions
1. Challenge/Cruise 展示区放在哪个位置？
   - 建议：Challenge verdict + backtrack 放在 Status Overview section（与 Risk Flags/Blockers 同区），Cruise run 放在独立 section（在 Methodology & Learning 之后）

### Assumptions
1. 前端可直接读取 spec.workflow 和 spec.cruiseRun 的所有字段
2. blocker 卡片中的 challenge/backtrack 文本行可以移除（信息升级到结构化区域后不再需要）

### Confirmed Requirement
1. Challenge verdict 用颜色标签展示：PASS→绿、PASS_WITH_CONCERNS→橙、FAIL_*→红
2. Backtrack target 在 Challenge verdict 旁边展示（仅 FAIL_* 时有意义）
3. Cruise run 展示：cruise policy、max iterations、最新一轮详情（iteration/engine/verdict/stopReason）
4. Cruise stopReason 用颜色区分：pass→绿、max_iterations→橙、human_required→红、continue→蓝
5. blocker 卡片中的 challenge/backtrack 文本行移除（信息已升级到结构化区域）

## Innovate Options

### Option A：合并到 Status Overview
把 Challenge verdict + Backtrack + Cruise run 全部合并到现有 Status Overview section。

- 优点：信息集中，不新增 section
- 缺点：Status Overview 已经有 Risk Flags + Blockers，再加 Challenge + Cruise 会过载；Challenge 和 Cruise 是不同关注点（裁决 vs 修复循环）
- 匹配度：中

### Option B：Challenge 归 Status Overview，Cruise 独立 section（推荐）
Challenge verdict + Backtrack 放在 Status Overview（与 Risk Flags/Blockers 同区，都是"当前状态"），Cruise run 独立一个 section（修复循环是动态过程，不是静态状态）。

- 优点：分区合理——状态概览看"现在怎样"，Cruise section 看"修复过程"
- 缺点：多一个 section
- 匹配度：高

### Rejected Options
- Option A：Challenge 和 Cruise 关注点不同，不应合并

### Selected Option
**Option B：Challenge 归 Status Overview，Cruise 独立 section**
