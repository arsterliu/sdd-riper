## Technical Design

Selected Option / ADR:
Option B：Confirmed Requirement 用 label 字段格式 + Research Gate label 字段。ADR-001：结构化 Confirmed Requirement 采用 `Label: value` 格式而非子标题，与 Design 模板字段格式一致，复用 `missingLabels()` / `labelValue()` 检查。

Requirement Traceability:
- Intake Requirement → Confirmed Requirement 5 要素 → validate 检查 → riskFlags 信号提取 → Design Method 路由
- Research Gate → validate 检查 → classifyIssue 路由 → FAIL_SPEC 回溯

Impact Scope:
- Spec 模板（standard/lite）：Confirmed Requirement 区域增加 5 个 label 字段 + Research Gate 2 个 label 字段
- validate.js：新增 CONFIRMED_REQ_REQUIRED 常量 + validateConfirmedRequirement() + validateResearchGate()
- workflow.js：riskFlags() 增加结构化字段提取路径 + classifyIssue() 识别 Research Gate issue
- spec-index.js：completionState.research 调整
- challenge.js / status.js / _spec-creator.js：提示和检查更新
- SKILL.md / GUIDE.md / protocols/subagent-dispatch.md：文档更新

Context / Boundary:
- 不改变 Spec frontmatter 结构
- 不改变 Design 模板结构
- 不改变 Execute Log 结构
- 不改变 Learning Record 结构
- micro 模式不受影响

Domain Model:
无数据模型变更。所有变更都在 Spec 文本内容和 validate/workflow 逻辑中。

Architecture View:
```
Spec Template (standard/lite)
  └─ Confirmed Requirement section
       ├─ Scope Boundary:          ← 新增 label
       ├─ Irreversibility:         ← 新增 label
       ├─ Impact Radius:           ← 新增 label
       ├─ Dependencies & Constraints: ← 新增 label
       └─ Acceptance Intent:       ← 新增 label

  └─ Research Gate fields (在 Confirmed Requirement 之前)
       ├─ Research Reviewed By:    ← 新增 label
       └─ Research Reviewed At:    ← 新增 label

validate.js
  ├─ CONFIRMED_REQ_REQUIRED = ['Scope Boundary', 'Irreversibility', 'Impact Radius', 'Dependencies & Constraints', 'Acceptance Intent']
  ├─ validateConfirmedRequirement(specPath, mode, archiveReady, issues)
  │   ├─ 提取 Confirmed Requirement section 内容
  │   ├─ 检查 5 个要素非空（missingLabels）
  │   └─ 非 archive-ready 时仅 warning，archive-ready 时阻断
  └─ validateResearchGate(content, gatePolicy, archiveReady, issues)
      ├─ 检查 Research Reviewed By / Research Reviewed At
      ├─ manual 策略禁止 auto-gate
      └─ 非 archive-ready 时仅 warning，archive-ready 时阻断

workflow.js
  ├─ riskFlags(content, crSection)  ← 签名变化
  │   ├─ 从 crSection 的 Irreversibility label 提取 irreversible flag
  │   ├─ 从 Impact Radius label 提取 public-api flag
  │   ├─ 从 Dependencies & Constraints label 提取 security/billing/migration flags
  │   └─ 结构化字段全部为空时 fallback 到全文扫描
  └─ classifyIssue(issue)
      └─ 新增：/Research Reviewed By|Research Reviewed At/i → FAIL_SPEC
```

Data Model / Schema:
无变更。

Data Migration / Backfill:
已有 spec 的 Confirmed Requirement 是自由文本，不需要数据迁移。宽松期策略确保旧 spec 不阻断。

Interface Contract:
- validate.js 新增导出：validateConfirmedRequirement, validateResearchGate, CONFIRMED_REQ_REQUIRED
- workflow.js 的 riskFlags 签名变化：`riskFlags(content)` → `riskFlags(content, crSection)`，crSection 可选（undefined 时 fallback 到全文扫描）
- spec-index.js 的 completionState.research 判定逻辑变化：从检查 section 非空变为检查结构化要素非空

API Protocol:
无外部 API 变更。

State / Concurrency:
无状态变更。

Failure Modes:
- 旧 spec 的 Confirmed Requirement 无结构化要素 → riskFlags fallback 到全文扫描，validate 仅 warning（宽松期）
- Research Gate 字段缺失 → 非 archive-ready 时 warning，archive-ready 时阻断
- labelValue() 提取多行值时遇到下一个 label → 已有逻辑正确处理（break on next label）

Security / Permission:
无安全影响。

Observability:
- validate 输出新增 issue 类型：'Confirmed Requirement missing required fields: ...'、'Research Reviewed By is empty.'、'Research Reviewed At is empty.'
- sdd next 的 BLOCKERS 列表会显示这些新 issue
- sdd status 的 Research 行会反映结构化要素缺失

Performance / Capacity:
- riskFlags 增加一次 labelValue() 调用（5 个要素），开销可忽略
- validate 增加一次 missingLabels() 调用，开销可忽略

Compatibility / Rollback:
- 向后兼容：旧 spec 的自由文本 Confirmed Requirement 不阻断（宽松期）
- 回滚：删除模板中的 5 个 label 字段和 2 个 Research Gate 字段，删除 validate 中的新检查函数，riskFlags 签名回退
- riskFlags 的 fallback 逻辑确保回滚后行为不变

Test Strategy:
- 单元测试：validateConfirmedRequirement() 对空要素、部分要素、全部要素的检查
- 单元测试：validateResearchGate() 对 manual/auto/advisory 三种策略
- 单元测试：riskFlags() 从结构化字段提取信号 + fallback
- 单元测试：classifyIssue() 识别 Research Gate issue
- 集成测试：sdd validate --archive-ready 对新模板 spec 的完整检查
- 集成测试：sdd validate 对旧格式 spec 的宽松期行为

Risks / Trade-offs:
- **过度结构化风险**：5 要素可能变成"填空游戏"。缓解：要素内容可以是多行自由文本，不限制格式；且宽松期策略允许渐进采用
- **Research Gate 增加流程负担**：standard/lite 多一个 gate。缓解：auto 策略下 auto-gate 可自动通过（需 Gate Evidence）；advisory 策略下非归档时仅 warning
- **riskFlags 双路径复杂度**：结构化优先 + fallback 增加代码复杂度。缓解：fallback 是现有逻辑不变，新路径是增量代码
