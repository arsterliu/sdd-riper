## Learning Record

Source Spec: mydocs/specs/v4.11-cruise-no-spec-crash.md
Trigger: PASS_WITH_CONCERNS challenge verdict
Observed Problem: `sdd cruise` 在无活跃 Spec 项目上抛裸 TypeError（cruise.js 直接访问 state.authorizedActors.length），而 workflow.analyzeSpec 的无-Spec 早返回对象缺少 authorizedActors/authorizedScopeDigest/authorizedRiskSnapshot/activePlanDigest 字段；同文件其他消费者（next.js/challenge.js）都有防御，唯独 cruise.js 漏了。
Root Cause: 多个命令消费同一个 analyzeSpec 返回对象，但无-Spec 早返回路径与有-Spec 路径的返回形状不一致；新增消费者时按有-Spec 形状直接取字段，没有对齐检查。审核还发现同类残留：migration-required 项目 cruise --record-run 绕过 discover_spec 守卫命中 appendRun 防御性 throw（修复前已存在）。
Decision Rule: 任何「早返回/快捷路径」的返回对象必须与其正常路径字段形状逐一对齐（缺的字段补空值），而不是让每个消费者自行防御；新增命令消费共享状态时，先用无数据项目实测一遍空路径。发现守卫绕过组合（如 --record-run + migration-required）时不默认扩 scope，记录到 Learning 由后续任务闭环。
Applies When: 给 analyzeSpec/analyzeProject 等共享状态函数增加新字段或新消费者时；为 CLI 命令添加新 flag 组合时。
Does Not Apply When: 单一消费者私有的内部对象（形状不跨模块共享）；一次性脚本。
Recommended Action: 为共享状态函数建立「所有返回路径同形状」的约定并加回归测试断言空路径字段存在性；残留的 record-run 绕过问题可开后续 micro 任务：将 cruise.js 守卫条件扩展到 migrate_autonomy_config，或在 appendRun 处降级为引导输出。
Evidence: mydocs/specs/v4.11-cruise-no-spec-crash.md（AC-001/AC-002 全部 PASS）；tests/workflow.test.js 新增 3 个回归测试；challenge 子代理临时目录实测 7 场景记录于 Challenge Summary。
