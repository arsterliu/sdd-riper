## Technical Design

Selected Option / ADR: 采用“独立视觉 Context 引导层”。以 `ui-impact` 和 `visual-context-intent` 记录一次性意图选择；以只读发现结果辅助补问；仅经用户确认后复用现有 `visual-evidence.json` 严格合同。拒绝将候选材料、批准和严格证据混入同一制品。
Requirement Traceability: 对应 Requirement 中的统一 Context 来源、自动发现分类、最小化补问、前端一次选择、纯后端跳过、仅在承诺视觉验收后阻塞，以及 Figma 不形成特殊工作流。Figma MCP 获取器、网络访问、浏览器截图与 diff 不属于本期。
Impact Scope: Spec 创建/Intake 引导、Spec 模板、视觉命令、Context 只读扫描、validate/next/workflow 状态投影、Skill 与用户文档；既有 `visual-evidence` 合同解析保持权威且不改变 schema v1。
Context / Boundary: 输入仅来自 `context-source` 指向的本地真实目录。PNG/JPG/WebP/SVG/PDF/Markdown/TXT 与 URL 文本均作为候选材料；URL 只记录引用，不联网读取。输出是稳定的发现报告与缺口问题，不能替代用户确认。
Domain Model: `ui-impact` 为 `yes|no`，表示 SDD 已确认是否影响用户界面；`visual-context-intent` 为 `not-applicable|not-required|direction|fidelity`。发现报告包含 material、candidate、gap、question 四类只读对象，候选均标识为推断。严格合同继续由 `visual-evidence: required` 与 v1 manifest 表示。
Architecture View: `discover`/Intake 根据项目 Profile、affected-units 或一次 UI 影响问题确认 `ui-impact`；前端任务调用选择入口写入 intent；`visual discover` 调用纯发现模块扫描 Context 并输出报告；用户确认方向/高保真后显式调用已有 `visual init` 创建严格合同；validate/next 仅在严格合同 required 且不完整时阻塞 Plan。
Data Model / Schema: 三个 Spec 模板新增空的 `ui-impact`、`visual-context-intent`。新发现模块返回内存对象，不默认落盘：`materials[{path,kind}]`、`candidates[{kind,materialPath,confidence}]`、`gaps[{code}]`、`questions[{code,prompt}]`。路径字段均为相对 Context 的规范化路径。
Data Migration / Backfill: 无迁移。旧 Spec 缺少新字段时按兼容状态处理，不新增 blocker；新 Spec 由 SDD 在 Intake 写入一次选择。
Interface Contract: 新增 `sdd visual select <dir> --spec <path> --ui-impact yes|no [--intent not-required|direction|fidelity]`；`ui-impact no` 记录 `not-applicable`，`yes` 必须提供 intent。新增 `sdd visual discover <dir> --spec <path>`，只读打印发现、推断、缺口和下一步。既有 `visual init` 保持显式启用 required 的写入边界。
API Protocol: 不增加网络 API。Figma URL、原型 URL 与普通 URL 在发现报告中统一为 `reference` 候选。未来 Figma MCP 获取器另立 Spec，并将结果写入同一 Context 边界。
State / Concurrency: `visual select` 只更新目标 active Spec 的两个字段；`visual discover` 不写入。沿用现有 active Spec realpath 检查；没有共享锁或异步任务。
Failure Modes: Context 不存在、越界或链接逃逸时发现命令输出稳定安全诊断；空 Context 在 not-required 时不报错，在 direction/fidelity 时报告缺口但不自动启用 required；无 `ui-impact` 的新前端 Spec 在 Plan 前提示完成一次选择。
Security / Permission: 扫描必须限制 Context realpath、递归深度、条目数与文件大小；默认只用路径、扩展名、文件名与受限文本元数据，拒绝二进制解析和远程访问。不得把 URL 内容、凭据、批准人或基线自动写入合同。
Observability: 发现输出使用稳定诊断码、材料计数和候选/缺口摘要；`next` 显示 ui-impact、intent 和严格合同状态，便于用户判断为何需要补充。
Performance / Capacity: 默认有限深度和数量，按规范化相对路径排序；超限只返回明确诊断，不继续扫描。
Compatibility / Rollback: 旧 Spec 与纯后端 Spec 保持无视觉门禁行为；移除/清空新字段即可回到旧行为，且不影响已经 required 的 visual evidence 合同。
Test Strategy: TDD 覆盖选择状态矩阵、前端/后端与混合任务判定、空 Context 非阻塞、资料候选与未知用途、稳定只读、越界/超限保护、确认后严格合同衔接和旧 Spec 兼容；CLI 集成测试覆盖 select/discover；全量 Node 测试回归。
Risks / Trade-offs: 文件名推断必然不完全准确，故只产出候选与问题；引入两个前置字段增加模板复杂度，但能使“是否影响 UI”和“是否做视觉验收”可审计且避免把普通任务误阻塞。Figma 实际读取延后，换取本期离线、无授权依赖的可用闭环。
