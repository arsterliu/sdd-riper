## Design Note

Approach: 采用“宽输入、严语义”的小步设计。AC Coverage 的 `Test:` 字段仍表示一个项目相对测试文件路径；parser 只对不改变语义的表面格式做规范化，例如剥离一层完整包裹的 Markdown inline code。对分号/逗号分隔的多路径、明显命令式内容或叙述性证据，不尝试拆分、执行或猜测主文件，而是在 gate 校验中给出明确诊断：`Test` 必须是单一项目相对文件路径，完整命令或测试集合应写入 `Command:` / `Verification:`。不可逆风险 guidance 只增强用户可见停机说明，继续要求当前用户对该不可逆动作作出独立授权。

Impact Scope: 主要影响 `src/core/workflow-gate-facts.js` 的 AC Coverage 字段解析、`src/core/spec-state.js` 的 L3 测试路径存在性诊断、`src/commands/next.js` 的不可逆风险 guidance，以及 `tests/workflow-gate-facts.test.js` / `tests/commands.test.js` 中对应回归。若文案需要同步，则更新 `REFERENCE.md`、`SKILL.md` 或 `templates/execute-log.md` 的 `Test:` 字段说明。

Interface / Data Impact: CLI 外部行为变化限于更宽容地接受 ``Test: `tests/foo.test.js` `` 这类单一路径写法，以及对非法 `Test:` 值输出更准确的阻断原因。不会新增持久化数据结构，不迁移历史归档制品，不改变 `Challenge Evidence`、archive authorization、E2E SKIPPED、scope/Plan/risk digest 的存储或校验格式。`sdd next` 增加不可逆风险停机提示，不自动授权、不自动继续。

Compatibility: 现有合法 `Test: tests/foo.test.js` 保持不变；缺失测试文件仍 fail-closed；多路径和命令原本会以“文件不存在”失败，变更后仍失败但原因更准确。历史归档制品保持只读，不因当前 parser 容错而自动重写。若已有测试断言旧错误文案，需要改为断言新诊断语义而不是取消阻断。

Risks: 最大风险是容错 helper 过度聪明，误把命令或测试集合当成合法路径，从而弱化 L3 证据。缓解方式是只允许完整 inline code span 剥离，其他复合语义全部 fail-closed。另一个风险是不可逆 guidance 被理解为普通授权刷新即可越过停机；文案必须明确“当前用户、当前不可逆动作、独立授权”，并不得暗示 Plan approval、Challenge 或旧授权可替代。

Test Strategy: 先写红灯回归：inline code 单一路径当前失败、多路径/命令当前诊断误导、不可逆 `NEXT_ACTION` 缺少 guidance。实现后运行 `node --test tests/workflow-gate-facts.test.js tests/commands.test.js`；根据影响补充 `tests/autonomy-workflow.test.js` 或 `tests/state-matrix.test.js`；最终运行 `npm test`、`node bin/cli.js validate . --archive-ready` 和 `git diff --check`。测试断言重点放在“仍阻断非法证据”和“诊断指导正确”，而不是仅匹配完整文案。
