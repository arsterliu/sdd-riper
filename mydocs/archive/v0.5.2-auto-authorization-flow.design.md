## Technical Design

Selected Option / ADR:
选择方案 A：保留 task_authorization 与 plan_activation 两个事件。首次人类确认 auto 时，主 Agent 自动建立覆盖 main、worker、research-reviewer、challenge-reviewer 的任务授权；Plan 经 Agent 审批后，主 Agent 自动建立绑定当前 Plan 摘要的 plan_activation。该方案消除正常路径的二次人工确认，同时保留 Plan 生成后才可绑定精确摘要的审计边界。
Requirement Traceability:
需求要求 auto 在范围、风险和 Plan 不变时连续推进，并要求归档、范围扩大、新风险、不可逆操作、平台权限、Profile 摘要确认和 E2E SKIPPED 继续人工停机。方案通过保留 resolver 的摘要比较和专属 stop reason 实现这一点。
Impact Scope:
变更集中在授权命令 / 状态推导、工作流下一步提示、生成的 Agent 规则、控制台投影、测试和说明文档。supervised 与 human 的 Plan 人工批准规则不变。
Context / Boundary:
本设计治理的是 SDD 制品中的自主执行授权，不负责身份认证，也不改变外部平台权限。`human:<name>` 仅为审计声明；实际外部权限仍必须单独确认。
Domain Model:
任务授权表示当前用户对确定 scope 与 risk 的持续授权；Plan 激活表示主 Agent 已在该授权下核对并绑定精确 Plan 摘要；授权仅在二者均新鲜时对 Plan 后自动执行有效。
Architecture View:
`autonomy authorize` 负责记录初始任务授权；Plan 审批完成后的自动编排负责调用 / 写入 Plan 激活；`autonomy-state.resolve` 统一计算新鲜度和 stop reason；`next`、Cruise、控制台与生成规则只消费该状态，避免各自推断授权。
Data Model / Schema:
继续使用现有 Autonomy Control 事件字段：scopeDigest、riskSnapshot、planDigest、authorizedActors、authorizedBy、authorizedAt 与 authorizationEvidence。无需迁移旧事件；旧 Spec 保持原有“缺少激活则停止”的可读语义，新流程仅自动补齐合规激活。
Data Migration / Backfill:
不回写归档或旧 Spec。活动中的旧 auto Spec 仍须使用现有命令完成一次有效授权 / 激活，避免将历史聊天内容推断为新授权。
Interface Contract:
首次 auto 授权后的宿主 Agent 指引必须明确：自动调用任务授权并包含允许角色；Plan 通过 Agent 门禁后自动激活，且不可向用户索要额外 Plan 批准。若 resolver 返回 scope_changed、risk_changed 或其他专属 stop reason，必须停止并请求相应的人类授权。
API Protocol:
保留 `sdd autonomy authorize` 和 `sdd autonomy activate-plan` 的参数校验与审计输出。可新增受控的工作流帮助动作或提示，但不得提供跳过摘要校验、任意 actor 或伪造 human 授权的接口。
State / Concurrency:
所有授权写入继续经 `.sdd-autonomy.lock` 串行化，并在写入时重新读取目标 Spec 与 expected digest。自动激活应只在 task_authorization 对当前 scope / risk 新鲜、Plan 为 Agent 审批且三个 expected digest 全部匹配时成功。授权状态与 Plan 门禁必须共用严格的单行标签事实解析，空批准字段不得跨行读取相邻标签而被误判为已批准。
Failure Modes:
摘要不匹配返回过期 / 漂移状态，不写入激活；授权不存在时返回 task_authorization_required；范围或风险变化返回对应 stop reason；自动激活失败时提示 Agent 诊断原因，不能退化为请求用户批准旧 Plan。
Security / Permission:
不会扩大 Agent 的外部权限。reviewer 授权限定为只读角色，实际 Challenge Evidence 仍记录具体 `subagent:<id>` / `external-agent:<id>`；归档、平台权限和不可逆操作继续要求当前用户显式授权。
Observability:
`sdd autonomy inspect`、`sdd next`、Cruise ledger 与控制台应区分“正常的自动 Plan 激活待执行”和“需要人类重新授权的 stop reason”，避免将前者呈现为用户确认请求。
Performance / Capacity:
仅增加少量 Spec 读取与单个原子事件追加，对 CLI 性能无显著影响。
Compatibility / Rollback:
保持事件 Schema 兼容，不变更旧制品。若出现回归，可撤销自动编排，仅恢复原有手动激活行为；已有摘要校验、锁与专属停机点不受影响。
Test Strategy:
使用 Node 单元与 CLI 集成测试验证：首次 auto 授权角色集合、空 Plan 批准字段不被跨行误判、Agent Plan 审批后无人工停机的自动激活、Plan / scope / risk 改变均失效、reviewer 自动启动前的角色许可、专属人类停机点及旧 Spec 兼容性。相关生成配置 / Skill 文本也须有同步性测试或快照断言。
Risks / Trade-offs:
自动编排减少一次人工询问，但依赖宿主 Agent 严格遵守指引。保留独立激活事件增加少量记录开销，却换取明确的摘要绑定证据与更低的兼容风险。
