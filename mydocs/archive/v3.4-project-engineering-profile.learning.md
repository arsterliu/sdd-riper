## Learning Record

Source Spec: mydocs/specs/v3.4-project-engineering-profile.md
Trigger: 两轮独立 Challenge 发现 BUGFIX，最终以 PASS_WITH_CONCERNS 进入 Learning Check。
Observed Problem: 存储代码可能先沿未验证的目录 junction 递归创建外部目录再拒绝；漂移检查曾把任意 human evidence 当作整个 role/relation 的固定依据，并可能恢复 relation 而遗漏其 evidence，产生悬空引用或误报。
Root Cause: 把“目标最终位于根内”误当成“创建路径的每一步都安全”，并把 human confidence 当成独立布尔标记，而没有将人工事实、证据、证据 owner、端点和已确认 root 建模为一个需要整体复核的语义束。
Decision Rule: 对不可信路径执行写入时，必须逐级验证既存父目录 realpath 后再单层创建，禁止用 recursive mkdir 穿越未经验证的目录；漂移时只能原子保留具有正确语义类型、路径仍可解析、owner 与端点有效且 saved/detected root 对应的人工事实与其全部证据，随后重新 canonicalize 再比较。
Applies When: 内容寻址制品存储、项目内锁/指针/附件目录、可人工修正的检测事实、human override 或人工关系需要跨次检测保持时。
Does Not Apply When: 路径完全由进程控制且所有祖先已在同一可信事务中创建；或人工输入只是备注，不参与机器判断和漂移合并时。
Recommended Action: 新增任何存储目录前加入“已有目录逃逸且外部零写入”测试；新增任何 human fact 类型时同时覆盖有效保留、证据缺失、错误 evidence kind、owner 失效、endpoint/root mismatch 与规范化顺序。当前非阻断测试债务是为 endpoint root mismatch 和 evidence owner 失效各增加专门反例，现有代码已有防护但后续修改不得删除。
Evidence: tests/profile-security.test.js 的 escaping profiles junction 用例先 RED 后证明外部零写入；tests/profile-drift.test.js 的无关/失效 role evidence 与 relation evidence 用例先 RED 后 GREEN；第三轮 Challenge 为 PASS_WITH_CONCERNS。
