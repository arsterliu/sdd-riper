## Technical Design

Selected Option / ADR:
选择“扩展现有版本前缀模型”：继续使用 `vN.M-task`，新增 `vN.M.P-task`，并把 version 定义为迭代 / 交付批次聚合键。拒绝引入 revision 或全局 spec-id，因为用户明确认为 revision 管理复杂，且当前并行模型更适合“同版本不同任务”。

Requirement Traceability:
AC-001 覆盖两段 / 三段版本创建；AC-002 覆盖 `version + task-name` 唯一性；AC-003 覆盖命令与索引解析一致性；AC-004 覆盖 agent 创建 Spec 前人工确认规则。

Impact Scope:
影响 CLI Spec 文件命名校验、版本解析、latest/source spec 选择、archive/reopen/new-learning 的文件名推断、console spec index 展示，以及 README/GUIDE/SKILL/AI 配置生成文案。不改变 docs root、目录结构、命令参数名称或已有 `vN.M` 文件。

Context / Boundary:
边界内：Spec version 解析和创建门禁文案。边界外：目录分组、revision 历史管理、自动生成 version、自动推断 task-name、迁移已有文件名。

Domain Model:
`version` 是迭代 / 交付批次标识；`task-name` 是该版本下的子任务标识；唯一键为 `version + task-name`。两段版本的 patch 视为 `0`，只用于排序和比较，不改变展示值。

Architecture View:
`lib/common.js` 应成为通用解析来源，暴露版本格式判断与文件名解析能力。CLI 创建、archive/reopen、console index 等模块复用同一语义，避免多处分散正则产生行为漂移。测试覆盖 CLI 行为和 common/spec-index 解析。

Data Model / Schema:
不新增 frontmatter 字段。文件名继续承载 version + task-name：`<version>-<task-name>.md`、`<version>-<task-name>.design.md`、`<version>-<task-name>.execute.md`、`<version>-<task-name>.learning.md`。

Data Migration / Backfill:
不迁移历史文件。旧 `vN.M-*` 文件继续可读；新 `vN.M.P-*` 文件可创建并被命令识别。

Interface Contract:
`sdd discover <dir> --task-name <name> --version <vN.M|vN.M.P> --requirement <text>` 保持接口不变。无效版本报错应说明支持 `vN.M` 或 `vN.M.P`。重复创建应说明同一 version 下 task-name 必须唯一。

API Protocol:
无网络 API。console 内部 JSON 中 `version` 对三段版本展示完整值，例如 `v1.3.6`。

State / Concurrency:
并行开发通过相同 version 下不同 task-name 并存实现。CLI 只阻止同 version + 同 task-name 的重复 Spec，不阻止同 version 下不同任务。

Failure Modes:
若某模块仍使用旧正则，可能出现 discover 创建成功但 console/archive/reopen 无法识别的断裂。测试需要覆盖这些路径。若 agent 指南不够强，仍可能静默创建错误 version/task-name。

Security / Permission:
无权限边界变化。仍需避免把用户未确认的输入写入任务控制面。

Observability:
CLI 输出继续打印 Spec / Design / Execute Log 路径。错误信息增加唯一键语义，有助于用户理解并行版本下的冲突原因。

Performance / Capacity:
正则和排序变化对性能影响可以忽略。

Compatibility / Rollback:
兼容旧两段版本。回滚方式是恢复版本正则为两段，但不会破坏已存在三段文件内容；只是旧代码无法识别三段文件。为降低风险，所有解析改动集中到公共函数。

Test Strategy:
使用 `node:test`。先添加失败测试，再实现：`tests/commands.test.js` 覆盖 discover、archive/reopen 和生成文案；`tests/common.test.js` 覆盖版本格式、文件名解析、latest/source 选择。最后运行 `node --test tests/*.test.js`。

Risks / Trade-offs:
保留平铺目录会让同一版本下任务很多时列表变长，但这是本次低风险改动的合理取舍。目录分组可作为未来独立任务处理。
