## Learning Record

Source Spec: mydocs/specs/v4.6-test-fixture-consolidation.md
Trigger: Execute Step 3 因 Windows 的 CRLF/LF 差异记录为 DEVIATED_MINOR。
Observed Problem: 直接运行 `commands` 与 `state-matrix` 时，fixture 用 LF 标记定位生成的 Markdown 标题，但工作区受 Git 换行转换影响产生 CRLF，导致 `Innovate Options` 等标题未被识别。
Root Cause: 测试 fixture 的文本替换边界假设输入为 LF，而 Windows 工作区生成/读取的文本可能为 CRLF；这与本期 helper 或生产行为无关。
Decision Rule: 当仅测试进程中的 Markdown fixture 因 CRLF/LF 边界而不能表达既有断言时，可在临时目录创建只包装 `fs.readFileSync` 字符串返回值的 LF 归一化前置文件；二进制读取必须原样返回，且不得修改生产代码、测试断言、制品内容或 Git 配置。
Applies When: Windows 工作区的现有 Node 测试使用字面 LF 标记处理由模板或 fixture 生成的文本，且先以未归一化运行复现相同边界失败后。
Does Not Apply When: 生产读取路径、字节/二进制验证、真实外部输入、可通过修复本期代码解决的失败，或尚未先复现并定位根因的普通测试失败。
Recommended Action: 先运行 `sdd debug` 记录失败和根因；使用 `apply_patch` 在临时目录创建前置文件，仅对该次测试命令设置 `NODE_OPTIONS=--require=...`，验证后立即删除文件，并在 Execute Log 记录该环境前置。
Evidence: 未归一化的 `node --test tests/commands.test.js tests/state-matrix.test.js tests/workflow-gate-facts.test.js` 失败；`node bin/cli.js debug . --error "...CRLF..."` 完成根因记录；加载前置文件后同组 192/192 与全量 503/503 通过。
Related ADR: Option A — 窄横向基础层。
