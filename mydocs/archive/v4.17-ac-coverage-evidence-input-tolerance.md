## Summary
改进 AC Coverage 结构化证据的输入容错与用户可见诊断：对 `Test:` 中常见的 Markdown inline code 包裹进行安全规范化；对多路径、命令或叙述性内容给出明确 fail-closed 诊断，提示迁移到 `Command:` / `Verification:`；同时为不可逆风险的 `NEXT_ACTION` 补齐清晰停机指引。治理语义保持严格：归档门禁、Challenge Evidence、防伪写入、授权 digest、E2E SKIPPED 与不可逆风险停机均不得被宽松解析削弱。

## Intake
requirement: 改进 AC Coverage 结构化证据的输入容错和诊断：Test 字段接受 Markdown code span 并规范化为单一路径；对多路径或命令内容给出明确错误，提示放入 Command/Verification；保持归档门禁、Challenge Evidence、授权 digest 等治理语义严格；为不可逆风险 next action 增加清晰 CLI 指引。
goal: 在不放松治理语义的前提下，让 SDD 对人类书写格式更宽容、对错误诊断更明确。
constraints: 模式使用 lite；自治模式 supervised；输入层可以规范化常见格式，但归档门禁、Challenge Evidence、防伪、授权 digest 和不可逆风险停机语义不得弱化。

## Requirement Review
用户明确要求创建并推进 Spec，目标是“格式要求更宽松但治理语义不放松”。本任务不是放宽归档判定，而是修复人类书写格式与机械校验之间的摩擦：单一路径外层的 Markdown code span 属于可安全规范化的表面格式；多路径和命令内容代表不同语义，不能被 `Test:` 字段猜测为证据集合，应给出清晰错误并指导用户把完整命令放入 `Command:` 或 `Verification:`。

本任务还覆盖一个相邻治理缺口：当前 workflow 能产出 `NEXT_ACTION=request_irreversible_authorization` / `STOP_REASON=irreversible_action_required`，但 `sdd next` 没有像 archive、human gate、auto plan activation 那样输出明确 guidance，导致 Agent 容易误用普通授权或继续推进。

## Findings
1. exact Project Profile revision 已读取：`sdd-riper` 是主仓库 Node 单元，测试命令事实来自 `package.json` 的 `npm test`；本任务绑定 `affected-units: sdd-riper`，不涉及 fixture 单元。
2. `workflow-gate-facts.acCoverageRecords()` 目前直接把 `Test:` 后的字符串 `trim()` 存入 `record.test`，没有剥离 inline code，也没有分类多路径或命令内容。
3. `spec-state.acCoverageContractIssues()` 当前将 `record.test` 直接 `resolveProjectPath()` 后用 `fs.existsSync()` 检查，因此 `` `tests/foo.test.js` ``、`tests/a.test.js; tests/b.test.js`、`pnpm test ...` 都会退化成“文件不存在”。
4. 已有 Learning `v4.5-visual-verification-protocol-evidence-consolidation` 明确记录：AC Coverage 的 `Test:` 字段只应保存单一真实测试文件，完整回归集合应写入 `Command:` 或 `Verification:`；本任务应保留这条规则，但让错误诊断更可理解。
5. `workflow.js` 会在检测到 `irreversible` risk flag 且未到归档授权阶段时设置 `request_irreversible_authorization`；`next.js` 目前没有该 action 的专门 guidance 输出。
6. `v2.4-reviewer-authorization-hints` Learning 提醒：新增统一门禁提示时必须覆盖所有用户可见出口，不能只改主路径。本任务至少覆盖 `sdd next` 输出，并通过回归固定。
7. `v4.3-structured-readiness-projections` Learning 提醒：结构化审计语法变化必须同步校验 parser、模板/文档和投影边界；本任务只做兼容性输入规范化和错误诊断，不迁移历史归档制品。

## Assumptions
1. 本任务不引入 `Tests:` 多值字段；多路径仍不作为合法 `Test:` 证据，以避免改变 L3 归档门禁语义。
