## Learning Record

Source Spec: mydocs/specs/v1.0-ai-config-managed-block.md
Trigger: PASS_WITH_CONCERNS Challenge；用户指出已有 agent 配置不应被覆盖，应追加/合并。
Observed Problem: 生成宿主 agent 配置时，如果把 SDD-RIPER 说明当成整文件模板，`--force` 会删除项目已有规则；如果只 append 又会重复累积。
Root Cause: 项目级 agent 配置同时承载用户/团队规则和 SDD-RIPER 接入规则，不能用文件所有权模型处理；SDD-RIPER 只拥有自己的 thin bootstrap 区块。
Decision Rule: 对宿主 agent 配置、IDE rules、Copilot instructions 这类共享配置文件，默认使用 marker-managed block upsert：首次追加，后续只替换 marker 内内容；`--force` 也不得扩大为整文件覆盖，除非存在单独且显式危险的覆盖选项。
Applies When: 初始化或升级会写入已有项目配置文件，且该文件可能包含用户自定义规则、团队规范或其他工具配置。
Does Not Apply When: 文件是 SDD-RIPER 独占产物（例如新建 Spec/Design/Execute Log 模板）或用户显式请求整文件替换。
Recommended Action: 生成内容保持 thin bootstrap + hard guardrails，把详细流程交给 skill/CLI/README/GUIDE；测试必须覆盖 create、merge、update/idempotence、force 不覆盖和至少一个自定义内容保留断言。
Evidence: 本任务将 `src/commands/_gen-ai-configs.js` 改为 `<!-- sdd-riper:start -->` / `<!-- sdd-riper:end -->` managed block upsert；`npm test` 112/112 通过；Challenge 返回 PASS_WITH_CONCERNS，提示残缺 marker 可后续加强但不阻塞。
