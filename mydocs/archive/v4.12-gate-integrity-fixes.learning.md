## Learning Record

Source Spec: mydocs/specs/v4.12-gate-integrity-fixes.md
Trigger: PASS_WITH_CONCERNS challenge verdict; BUGFIX_ESCALATED in Execute Log
Observed Problem: 三个门禁命令的数据完整性缺陷：challenge --record-result 字符串 replace 注入与缺标签假成功；AC 编号 \d+ 与 \d{3} 不对称导致声明成功但覆盖永远缺失的归档死锁；cruise --record-run 在 migration-required 项目绕过守卫裸堆栈。执行中另暴露：首版 cruise 守卫漏了 !state.specPath 条件，误伤 legacy 配置但有活跃 Spec 的场景（tests/commands.test.js:1973 回归失败后按 Plan 原意修正）。
Root Cause: 1) String.replace 第二参数为字符串时 $ 序列是替换模式——所有把用户可控文本塞进 replacement 的调用都必须用函数形式。2) 同一契约（AC 编号）在两侧用不同宽度正则解析。3) 扩展守卫条件时只考虑了新分支，没有验证旧分支组合不受影响。
Decision Rule: 任何含用户文本的 .replace 一律函数形式 function(){return ...}；写入前校验目标标签行存在、缺失显式报错不写文件。同一契约的多处正则必须同宽并在一处定义。扩展条件守卫时先跑相关回归测试再继续（本次被既有测试 1973 拦住，证明回归网有效）。Plan 的 Touched Files 应直接列出平行实现的全部文件点，而不是靠「同名逻辑点」事后解释。
Applies When: 写入 Markdown/模板制品的任何 CLI 命令；跨文件共享的编号/格式契约；给已有守卫扩展新条件时。
Does Not Apply When: 纯内存对象替换（无持久化）；内部常量拼接。
Recommended Action: 残留关注可开后续任务：challenge 标签探测感知代码围栏结构；多行 summary 的单行 label 契约明确化或支持折叠；覆盖记录 \d{1,6} 与声明 \d+ 完全对齐（≥7 位记录也标 malformedId）。
Evidence: mydocs/specs/v4.12-gate-integrity-fixes.md（AC-001..004 全 PASS）；npm test 721 tests/716 pass/0 fail；challenge 子代理 fixture 实测记录（executedBy 注入、围栏假行误判、cruise 三路径）。
