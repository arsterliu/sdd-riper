## Learning Record

Source Spec: mydocs/specs/v1.0-learning-recall-and-risk-signal.md
Trigger: DEVIATED_MINOR in Execute Log — 把 riskFlags 改为扫"动作区"时，原 Design 未预见到模板字段名本身会污染关键词扫描。
Observed Problem: 若直接对 Plan+Design 章节做关键词扫描，standard Design 模板的固定字段名会让每个 standard spec 都误报：标签 "Security / Permission" 命中 security、"Data Migration / Backfill" 命中 migration/backfill、"Data Model / Schema" 命中 schema——与是否真有风险动作无关。
Root Cause: 模板化 Markdown 的"结构"（字段标签）与"内容"（填入值）混在同一文本里；按关键词扫描时，标签词被当成了内容信号。这与"扫动作区而非叙述"是正交的另一层噪音：叙述噪音来自 Research，标签噪音来自模板骨架。
Decision Rule: 对模板化/带固定标签的 Markdown 做关键词或信号扫描时，先剥离每行的 `Label:` 前缀、只对填入的值扫描；不能直接对含标签的原文匹配。判断风险/状态应基于用户实际填写的内容。
Applies When: 实现 riskFlags、validate、detector、lint 等"从带固定字段名的模板产物提取信号/风险/状态"的逻辑时。
Does Not Apply When: 扫描的是自由文本（无固定标签骨架），或确实需要把标签存在性本身当信号时。
Recommended Action: 提供 `stripLeadingLabels` 这类预处理，对 Plan/Design 等结构化区先去标签再扫；为"模板标签不得触发信号"补回归用例（每个 standard spec 默认应 RISK_FLAGS=none）。
Evidence: src/core/workflow.js（actionText + stripLeadingLabels）；tests/workflow.test.js AC-004；本仓库 `sdd next .` 对本 meta-spec 输出 RISK_FLAGS=none。
