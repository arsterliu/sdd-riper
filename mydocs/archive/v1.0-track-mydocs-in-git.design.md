## Technical Design

Selected Option / ADR: 采用细粒度 ignore：移除 `.gitignore` 的 `/mydocs/` 全目录忽略，新增 `mydocs/runs/` 忽略，允许 SDD Markdown 文档产物进入 git。
Requirement Traceability: AC-001 覆盖 mydocs root 不再全局 ignore；AC-002 覆盖 runs 继续忽略；AC-003 覆盖当前文档进入 git 状态；AC-004 覆盖测试和归档门禁。
Impact Scope: 修改 `.gitignore`；新增/纳入 `mydocs/` 下 specs、design、logs、learnings、archive 等 Markdown 制品。不会修改 CLI 运行逻辑。
Context / Boundary: 本次只处理当前 docs root `mydocs/` 的版本控制策略，不改变 `.sdd-config` 的 DOCS_DIR，也不改变 archive 命令行为。
Domain Model: SDD 文档制品是项目事实记录，属于版本化内容；runs 是运行账本，属于本地动态执行痕迹。
Architecture View: Git ignore 规则从“整个 mydocs 不可见”变成“mydocs 可见，runs 子目录忽略”。SDD CLI 继续读写同一路径，git 只改变可追踪性。
Data Model / Schema: `.gitignore` 删除 `/mydocs/`，增加 `/mydocs/runs/`。Markdown 文档无 schema 变更。
Data Migration / Backfill: 现有 ignored Markdown 文件会在 git status 中变为 untracked，需要 `git add mydocs` 纳入提交。已 tracked 的 archive index 保持原路径。
Interface Contract: CLI 命令、文件路径和配置不变。
API Protocol: 无 API 变化。
State / Concurrency: 无并发状态变更。
Failure Modes: 如果 ignore 过宽，会继续遗漏文档；如果 ignore 过窄，会纳入 runs 噪声。通过 `git check-ignore` 和 `git status` 验证。
Security / Permission: 文档可能包含执行事实；本项目需求明确要求纳入 git。仍避免纳入本地运行账本和临时缓存。
Observability: `git status --short --untracked-files=all` 可见待提交文档；`git check-ignore` 可验证 runs 仍被忽略。
Performance / Capacity: 文档量较小，对仓库体积影响可接受。
Compatibility / Rollback: 如需回滚，可恢复 `/mydocs/` ignore 并从 git rm --cached 移除文档。
Test Strategy: 运行 `git check-ignore` 验证 ignore 行为，运行 `npm test` 和 `sdd validate . --archive-ready` 验证项目状态。
Risks / Trade-offs: 纳入历史 SDD 文档会增加提交内容，但换来完整审计链和跨环境同步。
