## Summary
让 `sdd review-execute` 默认对比工作区（模型 B：每个 spec 归档后才提交），使 Axis 2（Code Diff Scope）能看到本 spec 尚未提交的全部改动；`base..HEAD` 分支模型降级为 `--diff-base` 显式可选项。

## Intake
requirement: review-execute 默认对比工作区（模型B：归档后才提交），base..HEAD 降级为可选
goal: Review 主轴 Axis 2 能看到未提交改动（含未跟踪新文件）
constraints: 不改变 review prompt 结构；分支模型仍可用；不让 SDD 接管 git

## Requirement Review
现状 `review-execute.js` 的 Axis 2 走 `resolveDiffBase()` 自动找 `origin/main`/`merge-base`/`HEAD~1`，再执行 `git diff <base> HEAD`（第 116、120 行）。这隐含假设"工作已 commit 在分支上"。但本项目已定模型 B：归档后才提交，Review 跑在 archive 之前，本 spec 的改动全在工作区，因此 `base..HEAD` 看不到任何东西。

## Findings
- `resolveDiffBase()`（39-67 行）：分支模型的基准解析，是当前默认路径。
- 第 116 行：`diffBase = resolveDiffBase(projectDir, opts.diffBase || storedDiffBase || '')`——CLI `--diff-base` 与 frontmatter `diff-base` 都喂给它。
- 第 120 行：`git diff diffBase HEAD`——只比已提交历史。
- `discover` 会在 frontmatter 自动盖 `diff-base`（= discover 时的 HEAD，本例 0fc118f）。模型 B 下这个值≈上次归档提交，但默认路径不该依赖它。
- ⚠️ `git diff HEAD` **不含未跟踪文件**；SDD 工作常新建文件（新命令/新 spec），必须额外用 `git ls-files --others --exclude-standard` 纳入，否则仍漏。
- demo 测试项目非 git 仓库，现有 review-execute 测试拿不到 diff；新测试需自建临时 git repo。

## Open Questions
- 无（commit 时机=B1：人/host 提交，archive 不自动 commit，已定）。

## Assumptions
- 模型 B 下 spec 进行期间 HEAD 不动（不中途提交），故 `git diff HEAD` 等价于"本 spec 全部改动"。
- `git diff --no-index -- /dev/null <file>` 在 Windows 的 git 上也识别 `/dev/null` 特殊符（用于渲染未跟踪文件为新增 diff），退出码 1 需捕获。

## Confirmed Requirement
1. 默认（无 `--diff-base`、无显式分支请求）时，Axis 2 = 工作区已跟踪改动（`git diff HEAD`）+ 未跟踪文件内容，且为非侵入式（不动 index/工作区）。
2. 传 `--diff-base <ref>` 时回到分支模型 `git diff <ref> HEAD`，Diff source 标 `<ref>..HEAD`。
3. Diff source 标签默认显示 `working tree`。
4. 非 git 仓库 / 无改动时输出 `(no git diff)`，不崩；500 行截断保持。
5. review prompt 结构、其余轴、输出 label 不变。

## Plan
1. 改 `src/commands/review-execute.js`：抽出 `workingTreeDiff(projectDir)`（`git diff HEAD` + `git ls-files --others --exclude-standard` 逐文件 `git diff --no-index -- /dev/null <f>`，全程 try/catch、非侵入）。
2. 在 `run()` 里分流：`opts.diffBase` 显式存在 → 分支模型（沿用 `resolveDiffBase`+`git diff base HEAD`，source=`<base>..HEAD`）；否则 → `workingTreeDiff`，source=`working tree`；空结果回落 `(no git diff)`/`unavailable`。
3. 500 行截断逻辑移到合并后的 diff 文本统一处理。
4. `tests/commands.test.js` 增 AC-001~005 用例（自建临时 git repo）。
5. `node --test` 全绿；跑一次 `node bin/cli.js review-execute .` 对本仓库工作区自检（dogfood）。
