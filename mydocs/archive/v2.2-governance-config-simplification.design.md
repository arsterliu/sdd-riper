## Technical Design

Selected Option / ADR: 选择“强制清理旧字段”方案。只保留 `APPROVAL_POLICY`、`CRUISE_ENABLED` 和 `--driver`，删除旧 `GATE_POLICY`、`CRUISE_POLICY`、`--engine`、`auto-gate`、裸 `subagent` 和项目级 `MODE` 兼容入口。用户确认当前仍在快速迭代，保持 SDD 控制面干净比历史兼容更重要。

Requirement Traceability: AC-001/AC-002 覆盖 approval policy 和旧 approval 输入拒绝；AC-003 覆盖 independent reviewer evidence；AC-004/AC-005 覆盖 cruise enabled 和 driver-only 参数；AC-006 覆盖文档、模板、Console 和 init 输出。

Impact Scope: 影响 `lib/common.js`、`bin/cli.js`、`src/commands/validate.js`、`src/commands/cruise.js`、`src/commands/init.js`、`src/commands/_gen-ai-configs.js`、`src/core/workflow.js`、`src/core/spec-index.js`、`src/core/cruise-run.js`、Console、templates、README/GUIDE/SKILL/TEAM-GUIDE 和测试。

Context / Boundary: SDD 是产物协议和门禁协议，不是宿主模型执行 runtime。本设计不让 CLI 自动判断宿主是否真的启用了 subagent，只校验 reviewer evidence 的可审计声明。宿主 agent 根据约定选择 `subagent`、`external-agent` 或 `human`。

Domain Model: 新概念为 Approval Policy、Independent Reviewer Evidence、Cruise Enabled、Cruise Driver。Approval Policy 只控制 Plan Gate。Independent Reviewer Evidence 只控制 Research Gate / Challenge。Cruise Enabled 只控制是否生成修复循环。Cruise Driver 只控制输出适配哪类宿主循环。

Architecture View: `lib/common.js` 作为新配置读取层，向上只提供新 getter。`validate.js` 消费 approval/reviewer 语义。`workflow.js` 和 `spec-index.js` 暴露状态给 next/cruise/console。`cruise.js` 只负责 driver 参数和输出契约。文档和模板只推荐新语义。

Data Model / Schema: `.sdd-config` 新推荐字段为 `APPROVAL_POLICY`、`CRUISE_ENABLED`、`CRUISE_MAX_ITERATIONS`。Spec 字段保持不变：`Plan Approved By`、`Research Reviewed By`、`Challenge Executed By` 等仍写在 Spec 中。新值格式为 `agent:<id>`、`human:<name>`、`subagent:<id>`、`external-agent:<id>`。

Data Migration / Backfill: 不做历史兼容迁移。旧字段不再读取；如果项目仍写 `GATE_POLICY`、`CRUISE_POLICY` 或旧 approval/reviewer 值，validate/CLI 应暴露为无效或按新默认值处理，而不是静默映射。

Interface Contract: CLI 只支持 `sdd cruise --driver <driver>`。`sdd challenge --record-result --executed-by` 接受可审计 reviewer 值。`sdd init` 新输出更少配置。错误信息使用 approval/reviewer/cruise enabled 术语。

API Protocol: 不再有旧参数/旧配置优先级。缺省值为 `APPROVAL_POLICY=agent`、`CRUISE_ENABLED=true`、`CRUISE_MAX_ITERATIONS=5`、mode 默认 micro；mode 升级必须通过 `--mode` 或 Spec frontmatter 明确表达。

State / Concurrency: 无并发状态变更。run ledger 仍追加 JSONL；新记录只写 `cruiseEnabled`/`driver`，Console 不再依赖旧 `engine` fallback。

Failure Modes: 主要失败模式是旧入口残留继续被新任务生成或用户复制；文档和代码术语不同步导致用户误解；测试夹具继续使用旧值导致行为被误保留。通过拒绝旧值的红灯测试和文本扫描降低风险。

Security / Permission: 本任务不改权限模型。`human:<name>` 只是审计声明，不做身份认证。不得将 `auto-gate` 作为 approval 或 reviewer，因为它不是可审计执行者身份。

Observability: Console 展示应从 `gatePolicy/cruisePolicy` 迁移为 `approvalPolicy/cruiseEnabled/maxIterations`，并继续显示 run ledger 的 latest run、driver、stop reason。

Performance / Capacity: 配置读取和 validate 逻辑均为本地文本解析，无性能风险。

Compatibility / Rollback: 不保留历史兼容。若新语义出现问题，通过当前任务继续修复新控制面，而不是恢复 `GATE_POLICY`、`CRUISE_POLICY`、`--engine` 或 `auto-gate`。

Test Strategy: 先在 `tests/commands.test.js` 和 `tests/common.test.js` 写红灯测试覆盖新配置、新 reviewer、拒绝旧 approval/reviewer、拒绝 `--engine`、忽略旧 `CRUISE_POLICY`、忽略项目级 `MODE` 和 init 输出。实现后运行 targeted node test，再运行 `npm.cmd test` 全量验证和 `git diff --check`。

Risks / Trade-offs: 不新增 producer/implementer 字段，意味着 CLI 只能校验 reviewer 声明格式，不能严格证明 reviewer 与实现者不同。这是为了减少字段和配置项的权衡；真正执行者选择由宿主约定负责。
