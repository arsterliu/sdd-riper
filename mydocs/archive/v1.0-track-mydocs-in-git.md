## Summary
当前任务处于 Plan approved，准备进入 Execute。目标是取消 `/mydocs/` 的全目录 ignore，并将现有 SDD 文档产物纳入 git 管理。范围包括 specs、design、logs、learnings、archive、context 等文档目录；运行时噪声如 runs 账本可继续忽略。验收将通过 git ignore 检查、git status 和测试/validate 证明文档可被版本化且项目门禁仍通过。

## Intake

### Requirement
requirement: mydocs 不再被 git 忽略，需要将现有 mydocs 文档和归档产物纳入 git 管理。
goal: 让 SDD Spec、Design、Execute Log、Learning、Archive 等项目文档可随代码版本化和同步。

### Constraints
constraints: 保留项目现有 SDD 门禁；避免纳入临时缓存、runs 账本或其他明显运行时噪声，除非当前 ignore 规则已经允许。

### Scope
本次修改 `.gitignore` 对 mydocs 的规则，并把现有 `mydocs/` 下的 SDD 文档产物纳入 git。保留明显运行时噪声和临时数据的忽略规则，例如 `mydocs/runs/` 可继续作为本地 cruise ledger。

### Risks
一次性纳入历史文档会增加提交体积和 diff 噪音；如果把 runs/临时上下文纳入，可能把本地运行记录误提交。若只移除 `/mydocs/` 而不补充细粒度 ignore，运行时账本可能出现在待提交列表中。

### Initial Acceptance Hints
- `.gitignore` 不再包含 `/mydocs/` 全目录忽略。
- `mydocs/specs`、`mydocs/design`、`mydocs/logs`、`mydocs/learnings`、`mydocs/archive` 下的 Markdown 文档可被 git 发现。
- `mydocs/runs/` 等运行账本不应被误纳入。

## Research

### Requirement Review
用户明确要求“mydoc 可以不用忽略了，纳入 git 管理”。结合当前项目已经把 archive index 提交但正文归档文件被 ignore 的状态，需求应理解为 docs root `mydocs/` 的 SDD 文档产物需要进入版本控制。

### Findings
`.gitignore` 当前第 17 行为 `/mydocs/`，导致新创建和归档的 Spec/Design/Execute Log/Learning 正文文件被忽略；上一任务归档正文文件存在于本地但未随提交进入 git。`mydocs/archive/index.md` 已是 tracked 文件，说明项目已经有部分 docs 进入 git 的需求。

### Open Questions
是否纳入 `mydocs/runs/` 这类 cruise ledger 运行时账本？本次按用户目标“文档和归档产物”处理，继续忽略 runs，避免运行噪声进入版本库。

### Assumptions
`mydocs/` 下 Markdown 制品是项目事实记录，应随代码版本化；`mydocs/runs/` 是运行账本，可由本地执行生成，不作为默认提交对象。

### Confirmed Requirement
移除 `/mydocs/` 全目录 ignore，改为细粒度忽略 `mydocs/runs/`，并将当前存在的 SDD 文档产物纳入 git 待提交集合。

## Innovate Options
Option A: 直接删除 `/mydocs/` ignore，纳入所有 mydocs 内容。Pros: 最符合“mydocs 纳入 git”。Cons: runs 账本和未来临时上下文可能产生噪声。
Option B: 删除 `/mydocs/`，新增细粒度 ignore 保留 `mydocs/runs/`。Pros: 文档制品进入 git，同时避免 cruise ledger 噪声。Cons: 如果未来有其他运行时目录，需要继续维护 ignore。
Option C: 保留 `/mydocs/` ignore，仅 `git add -f` 当前归档文件。Pros: 变更最小。Cons: 后续仍会反复被 ignore，不符合用户“mydocs 可以不用忽略”的要求。
Selected: Option B。Rejected: Option A 可能纳入运行噪声；Option C 没解决根因。
