## Learning Record

Source Spec: mydocs/specs/v1.0-sdd-doctor.md
Trigger: BUGFIX in Execute Log（doctor check2 正则误报）
Observed Problem: doctor 的 check2 用 `vendored/superpowers/<第三段>` 当作 skill 名，把散文里提到的 `LICENSE` / `SYNC.md` / `.upstream-commit` 也当成 skill，判定它们「未在 SKILL.md 接线」，产生 3 处误报，首次运行即 RESULT: FAIL。
Root Cause: 用「路径形状（第三段）」推断「语义（这是一个 skill）」。但同一前缀下既有目录（真 skill）又有文件（LICENSE 等），纯正则只看形状、无法区分语义，于是把文件误当 skill。
Decision Rule: 从自由文本 / 路径正则提取「某类结构化实体」时，如果同一模式会同时命中异构对象（目录 vs 文件、真引用 vs 散文提及），必须再加一个权威判别来过滤，不能只靠正则形状。
Applies When: 写静态扫描 / lint / 自检类逻辑，需要从自由文本或路径中提取结构化实体（skill、模块、引用、依赖等）时。
Does Not Apply When: 提取源本身已是结构化数据（如 JSON / 表格列 / frontmatter 字段），形状即语义、不存在异构混入。
Recommended Action: 提取后用硬判据过滤——文件系统判型（`fs.statSync().isDirectory()`）、白名单，或把匹配限定到结构化区域（如只扫触点表格行）；并同时写「应通过」与「应失败」双向测试锁定行为。
Evidence: doctor 首次运行报 3 处 FAIL 误报 → check2 增加 isDirectory 过滤后 RESULT: OK 退 0；测试 57/57 绿，含 doctor 的 PASS（真实仓库）与 FAIL（注入悬空引用）双向用例。
Related ADR: Innovate 选项 A（独立 doctor 命令，不并入 status）
