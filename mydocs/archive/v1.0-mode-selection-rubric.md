## Summary
新增 advisory 的 mode 判定 rubric（`protocols/mode-selection.md`），确立"默认 micro、standard 够格才用"，并在 SKILL.md 与 `discover` 输出中引导，治理 standard 被当默认档滥用的问题。不改变 `--mode` 行为。

## Intake
requirement: 提供 mode 判定 rubric：默认 micro 兜底、standard 够格才用，减少 standard 被滥用
goal: discover/SKILL 能引导按影响面与风险选档，standard 需正当理由
constraints: 不强制改变现有 --mode 行为；rubric 为 advisory；doctor 不得出现悬空引用

## Requirement Review
现状：mode 完全靠人手填 `--mode`，`init.js` 代码默认 standard，`SKILL.md:76` 也写"otherwise default to standard"，协议层无判定门槛。结果 standard 成了"拿不准就选"的默认档，被稀释。需要一个 advisory rubric 把默认拉回 micro、standard 须有正当信号。

## Findings
- 选档信号已有现成来源：`workflow.js` 的 `riskFlags`（security/billing/migration/public-api/irreversible）与 Mode Policy 表的"cross-module/irreversible/high uncertainty"。rubric 可直接复用这套语汇，不引入新概念。
- 落点三处：①新 doc `protocols/mode-selection.md`（protocols/ 已被 install-skill COPY_ENTRIES 覆盖，且 doctor 会校验 SKILL 对它的引用存在）；②SKILL.md Mode Policy + Setup 引用；③`_spec-creator.js`（discover 实际入口）打印 advisory。
- `discover` 已有 `shouldSuggestCodeMap` 这类 advisory 先例，新增 `modeAdvisory` 与之并列即可。
- 约束"不改 --mode 行为"=不动 `init.js`/`discover` 的默认值代码，仅文档+提示层。代码默认仍 standard 与 rubric"默认 micro"存在张力，本期作为 advisory 容忍并记为后续项。

## Open Questions
- 无（信号集复用 riskFlags + Mode Policy；落点与是否改默认值均已定）。

## Assumptions
- advisory 提示+rubric 文档足以引导人/agent 选档；无需强制校验或自动改档。
- doctor 的现有"referenced path exists / COPY_ENTRIES 覆盖"检查足以防止悬空引用。

## Confirmed Requirement
1. 提供 `protocols/mode-selection.md`，内容含三档 rubric：默认 micro、升级信号表、standard 须由具名信号或 3+ 信号叠加才用，并列反模式。
2. SKILL.md 在 Mode Policy/Setup 引用该 rubric，措辞从"default to standard"改为"default micro，按信号升级"。
3. `discover` 输出打印 `[MODE]` advisory 行（指向 rubric）；当档位为 standard 时追加更重的确认提示。
4. `sdd doctor` 通过，无悬空引用。
5. 不改变 `--mode` 的解析与默认值行为。

Reason: 落点与信号集在 Research 已确定，单一实现路径（doc + 文档引用 + advisory 提示），无需方案比选。
