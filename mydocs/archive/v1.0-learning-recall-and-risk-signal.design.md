## Technical Design

Selected Option / ADR: 选项 1——复用 per-spec `.learning.md` 为唯一真相源做词法相关性召回，项目级用 `sdd learnings` 实时聚合（不落新文件）；riskFlags 收窄到动作区扫描。否决 PROJECT.md 双真相源（漂移）与 embedding 召回（违反确定性/无依赖原则）。

Requirement Traceability: CR1→recallLearnings(AC-001/002)；CR2→learningBrief 改造；CR3→sdd learnings(AC-003)；CR4→riskFlags 动作区+正则(AC-004/005/006/007)；CR5→纯 Node/回归(AC-008)。

Impact Scope: 改 `src/core/learning.js`、`src/commands/review-execute.js`、`src/core/workflow.js`；新增 `src/commands/learnings.js`、`bin/cli.js` 注册一行；新增 `tests/learning.test.js`、`tests/workflow.test.js`、扩 `tests/commands.test.js`。不改沉淀格式/archive/模板/其余命令。

Context / Boundary: 属"workflow 引擎的 advisory 信号生成"边界。引擎只读 artifact、纯计算、确定性、不调模型；输出供 review/cruise 消费。learning 沉淀（写入/校验）不在本次边界。

Domain Model: Learning = {path, mtime, title, appliesWhen, decisionRule, observedProblem}。Query = 当前 spec 的若干章节拼接文本。Recall = score(Learning.matchSurface, Query) 降序。RiskSignal = 在 ActionText(Plan+Design) 上的关键词类别命中集合。

Architecture View:
- `learning.js`：`tokenize(text)`→去标点/小写/去停用词/去≤2字符 token 的集合；`matchSurface(learning)`→拼 appliesWhen(权重×2)+decisionRule+observedProblem+title；`scoreOverlap(queryTokens, surfaceTokens)`→交集计数(appliesWhen 命中加权)；`recallLearnings(dir, query, limit)`→对全部 learning 打分，max(score)>0 则按分降序(同分 mtime)取 top-N，否则回落现有 mtime 排序；`buildLearningIndex(dir)`→返回结构化数组供聚合视图。
- `review-execute.js::learningBrief(dir)`→读当前 spec(Intake+Confirmed Requirement+Plan) 作 query，调 recallLearnings(dir,query,5)，每条前缀相关度(score 或 relevance:high/low)。
- `learnings.js`→无 --for：buildLearningIndex 打印项目级清单；带 --for/默认活跃 spec：recallLearnings 打印 top-N。
- `workflow.js::actionText(projectDir, specPath)`→抽 Plan+Technical Design/Design Note 章节，并经 `stripLeadingLabels` 去掉每行的 `Label:` 前缀；`riskFlags(text)` 不变签名，调用方传 actionText；actionText 为空→回落整篇。
- **stripLeadingLabels 是必要环节（Execute 期发现）**：standard Design 模板的字段名本身含风险关键词（"Security / Permission"→security、"Data Migration / Backfill"→migration、"Data Model / Schema"→schema），若不剥离标签会让每个 standard spec 都误报；只扫填入的值才正确。

Data Model / Schema: 无持久化结构变更。召回/聚合为内存计算；无新文件写入（`sdd learnings` 仅 stdout）。停用词为内置小常量数组。

Data Migration / Backfill: 无（不改任何已存盘格式，历史 `.learning.md` 直接可被新召回读取）。

Interface Contract:
- 新 CLI：`sdd learnings [project-dir] [--for <spec-path>]`，stdout 文本视图，无副作用。
- `learning.js` 新增导出 `recallLearnings`、`buildLearningIndex`；`listLearningFiles` 签名/行为保持。
- `workflow.riskFlags` 签名不变（入参语义由"全文"变为"调用方决定的文本"，调用方改传 actionText）。

API Protocol: 不适用（本地 CLI/库函数，无网络协议）。

State / Concurrency: 无共享可变状态；纯函数读文件。并发无关。

Failure Modes:
- learning 目录缺失/空→召回返回空、`sdd learnings` 提示无记录。
- spec 无 Plan/Design（早期）→ actionText 空→ riskFlags 回落全文（保守，宁可多报）。
- query 为空→召回回落 recency。
- 单个 learning 文件读失败→跳过该条（try/catch），不影响整体。

Security / Permission: 仅读项目内 markdown，无新权限面、无外部输入执行。riskFlags 改动反而降低误报噪音，提升风险信号可信度。

Observability: `sdd learnings` 与 review-execute 的 Learning Brief 显式打印相关度，便于人判断召回质量；riskFlags 结果仍出现在 next/cruise 的 RISK_FLAGS 行。

Performance / Capacity: 采用**方案 A（实时全量聚合，无缓存/无索引）**。learning 本质有界（每 spec 一条提炼记录，~1–3KB）；数十~数百条全量读+分词为 O(N×tokens)，实测毫秒~百毫秒级，对交互式 CLI 无感。护栏：召回只读 Learning Record 段（`extractSection` 行数上限），读取天然有界；单条读失败跳过。**明确的升级路径（方案 B，YAGNI，暂不实现）**：当真实项目 learning 超过数百条且实测 `sdd learnings`/召回变慢时，在 `archive` 这一**单一写入路径**上把该条的 Applies When 摘要增量 append 进 `learnings/index.jsonl`，`sdd learnings` 改为读该索引 + 实时扫少量未归档活跃条。召回真相源永远是 per-spec `.learning.md`，故 A→B 平滑、不返工、不引入双真相源漂移。否决带 mtime 失效的持久缓存（失效逻辑易出 bug）。

Compatibility / Rollback: 纯增量+回落设计，向后兼容；resume 计数不受影响。回滚=还原 learning.js/review-execute.js/workflow.js 三处 + 删 learnings.js 与 cli 注册行。

Test Strategy: 单元 `tests/learning.test.js`(相关性优先 AC-001、零重叠回落 AC-002) 与 `tests/workflow.test.js`(动作区扫描 AC-004、真阳性 AC-005、词界 AC-006、空回落 AC-007)；集成 `tests/commands.test.js`(sdd learnings 两形态 AC-003、全回归 AC-008)。用临时目录构造可控 learning 集与 spec 文本。

Risks / Trade-offs: 词法召回弱于语义，质量依赖 Applies When 写作（接受，靠回落与显式相关度缓解）；riskFlags 收窄可能漏报只在叙述未落 Plan/Design 的风险（用空回落 + 真实风险终会落到 Plan/Design 缓解）。
