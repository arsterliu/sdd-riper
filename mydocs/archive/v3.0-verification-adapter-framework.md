## Summary
v3.0 reopen patch：把 `verify init` 从 Provider/配置双锁与等待合并收缩为项目级单锁、非阻塞 fail-closed 模型。
锁外完成只读 preflight；锁内覆盖读取、修改、校验和原子写入；调用者在并发失败后稍后重试。
同步删除 Provider 锁、`INIT_CONFLICT` 与并发合并承诺，并更新 Design、测试、GUIDE 和 Execute Log。

## Intake

### Requirement
`verify init` 是低频、显式、项目配置类命令，不支持同一项目并发执行；用单一项目锁和调用者重试替代双锁、等待和自动合并。

### Constraints
- 保留临时文件与原子替换，避免不完整 JSON。
- 只允许项目根目录 `.sdd-verification.json.lock`，不得创建 Provider 级锁。
- 锁冲突立即返回 `SDD_VERIFY_INIT_LOCKED` / exit 2，不等待、不合并、不自动重试。
- 只有配置写入与解锁都成功后才输出 `configured` / exit 0。
- 解锁失败以 `INIT_UNLOCK_FAILED` 为控制结果，并保留可能同时发生的主事务错误诊断。
- 持续锁定只能在确认无活动 init 后人工删除空锁目录，禁止按时间自动清理。

### Scope
修改 `src/commands/verify.js` 的 init 锁模型；收缩 `tests/verification-cli.test.js` 并发矩阵；同步当前 Spec、Design、GUIDE 与 Execute Log。`verify run`、Provider Schema、Adapter、Run 和 readiness 不在本次行为变更范围。

### Risks
写入成功但解锁失败时调用者可能误以为配置未变；因此诊断必须提示先检查配置。锁残留会阻断后续 init，但自动判断陈旧锁可能误删有效锁，必须保持人工确认。

### Initial Acceptance Hints
锁存在时命令必须在一次获取尝试后立即失败；失败不得改变既有配置。主事务失败必须释放锁并允许后续重试；解锁失败必须稳定 exit 2 且不得输出 `configured`。

## Research

### Requirement Review
用户明确要求删除已归档 v3.0 中为并发合并引入的双锁复杂度，回归单项目单写者模型。该变更是既有接口内部并发语义收缩，不改变 Provider 配置格式或 `verify run`。

### Findings
当前实现先获取 `.sdd-verification.<provider>.lock`，再等待最多 5 秒获取 `.sdd-verification.json.lock`；测试要求不同 Provider 并发合并、同名并发恰好一个成功，并暴露 `INIT_CONFLICT`。GUIDE 同样宣传双锁和两个恢复路径。原子写入 helper 已独立存在，可在单锁事务中继续使用。

### Open Questions
none

### Assumptions
只读 workspace/package/Playwright config 文件 preflight 在锁外完成，但不得读取、解析或缓存共享 `.sdd-verification.json`；preflight 通过后单次非阻塞获取项目锁。项目级并发失败由调用者稍后显式重试，不提供 CLI retry 参数。

## Innovate Options
Option A（选择）：锁外 preflight + 单一项目目录锁非阻塞获取；锁内完整读改写事务。优点是最小、明确、可审计；代价是不支持并发合并。

Option B（拒绝）：单锁覆盖 preflight 与事务。语义同样安全，但无必要延长锁持有时间。

Option C（拒绝）：保留 Provider 锁或配置锁等待。可提高并发成功率，但与低频显式配置命令的设计原则冲突，并扩大测试与恢复状态空间。

## 目标摘要
v3.0 reopen patch：把 `verify init` 从 Provider/配置双锁与等待合并收缩为项目级单锁、非阻塞 fail-closed 模型。

## 最终方案
采用单一项目级目录锁的 fail-fast 初始化事务。只读 preflight 在锁外；单次获取 `.sdd-verification.json.lock` 成功后执行完整读改写，任何并发调用立即失败并由调用者稍后重试。

## 关键约束
Node.js 同步文件系统 API；目录创建 `mkdirSync` 作为跨进程非阻塞互斥；原子 rename 保持现状。

## 坑点与风险
不同 Provider 的同时 init 也会失败，降低并发吞吐但显著减少状态空间。写入成功而解锁失败存在不确定提交感知，通过稳定诊断和“先检查配置”恢复指引处理。
