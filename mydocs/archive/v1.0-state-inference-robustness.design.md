## Technical Design

Selected Option / ADR: 选项 2「分层确定性排序」。ADR — Context：`findLatestSpec` 以文件 mtime 为主轴选活跃 spec，git checkout/clone/touch 重置 mtime 后选错。Decision：改为 status 过滤 → 单一非归档直接返回 → 多个按 (date, 版本号) 排序 → mtime 仅兜底。Alternatives：显式 active 指针（否决：引入需维护的新状态）、git 时间（否决：依赖 git + spawn + 复杂）。Consequences：单活跃场景零 mtime 依赖、根因即除；多活跃用确定性启发式；无新状态；向后兼容。
Requirement Traceability: CR1(status 过滤)→ 过滤 archived；CR2(单一即定)→ 单候选直接返回；CR3(date>版本>mtime 排序)→ 比较器；CR4(无非归档回退)→ fallback 现逻辑；CR5(无新状态)→ 不加配置/字段。对应 AC-001/002/003/004。
Impact Scope: 修改 `lib/common.js` 的 `findLatestSpec`（重写选取逻辑 + 新增不导出的内部 helper）。受影响调用方（行为应改善、不应回退）：`validate.resolveSpec`、`workflow.analyzeProject`、`resume.js`、`review-execute.js`、`debug.js`、`new-learning.js`。不改任何调用方接口。
Context / Boundary: `findLatestSpec(specsDir)` 只负责「默认活跃 spec 选取」；显式 `--spec` / `--name` 路径不经过它，不在本设计范围。
Domain Model: N/A（纯文件选取逻辑，无领域模型）。
Architecture View: 调用链 commands(resume/next/challenge/cruise/review-execute/debug/new-learning/validate) → resolveSpec/findLatestSpec → 返回 spec 路径。findLatestSpec 是这条链的根，单点改造即可惠及全链路。单函数重构，无需 C4 容器图。
Data Model / Schema: 候选 = specs 目录下 `vN.M-<task>.md`。每个候选的判定字段：文件名解析出的 (major, minor, task)、frontmatter `status`、frontmatter `date`、文件 mtime。排序键元组：(status≠archived 优先, date 降序, major 降序, minor 降序, mtime 降序)。
Data Migration / Backfill: N/A。不改产物格式，无需迁移。现有模板 frontmatter 已含 `date` 与 `status`；缺失时按 Failure Modes 保守处理。
Interface Contract: `findLatestSpec(specsDir)` 签名与返回语义不变（返回最可靠的活跃 spec 绝对路径，或 ''）。新增内部 helper（不导出）：读 status、读 date、构造排序键。向后兼容：无非归档候选时回退现有全量逻辑。
API Protocol: N/A（无网络/RPC）。
State / Concurrency: 无共享状态；纯函数读取文件系统快照，不涉并发。
Failure Modes: frontmatter 缺 status → 视为非归档（保守，倾向 active）；缺/非法 date → date 比较退化，落到版本号再到 mtime；文件名不匹配 → 跳过（现逻辑）；空目录 → 返回 ''（现逻辑）；statSync 失败 → mtime=0 兜底（现逻辑）。
Security / Permission: N/A（本地只读文件）。
Observability: 无新增日志；findLatestSpec 是底层工具，诊断由调用方输出承担。
Performance / Capacity: 比现逻辑多读候选的 frontmatter（status/date）；spec 数量通常很小（<数十），且仅对候选读取，开销可忽略。
Compatibility / Rollback: 向后兼容（签名/返回不变、无非归档时回退、不改产物格式、不加配置）；Rollback：纯函数内部改动，`git revert` 单文件即可回滚，无状态残留。
Test Strategy: 单元（tests/common.test.js）——① 单一非归档 spec：即使另有 mtime 更新的 archived spec 仍选非归档；② 多非归档 date 不同：选 date 最新，且用 `fs.utimesSync` 把目标 spec 的 mtime 设旧（模拟 git checkout）验证不被 mtime 误导；③ date 相同：选版本号最高；④ 全 archived / 空：回退或返回 ''。再跑全套测试确认依赖方行为不回退。
Risks / Trade-offs: 多个非归档 spec 并存时仍依赖 date/版本启发式（非绝对语义）；缓解：单活跃为主流场景已彻底解决，多活跃的精确选择留作后续「显式 active 指针」增强（已在 Innovate 记录）。
