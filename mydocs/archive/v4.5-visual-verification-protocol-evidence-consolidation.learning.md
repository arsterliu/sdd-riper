## Learning Record

Source Spec: mydocs/specs/v4.5-visual-verification-protocol-evidence-consolidation.md
Trigger: BUGFIX in Execute Log
Observed Problem: AC Coverage 的 Test 字段写入了分号分隔的多个测试路径，工作流解析器将其当作一个不存在的路径，阻断 completion-verification。
Root Cause: 将“完整回归集合”的叙述性证据误写入只接受单一文件路径的结构化 Test 字段，未在写入后立即运行 next 验证日志语法。
Decision Rule: Execute Log 的每条 AC Coverage 必须只在 Test 字段填写一个实际存在的主测试文件；其他联合回归文件只能写入 Command 或 Verification 说明，并在完成全量回归后先运行 next 再声明完成。
Applies When: 为标准 Spec 追加含多个测试文件的 AC Coverage、全量回归或修复记录时。
Does Not Apply When: Test 字段明确支持测试集合、通配符或多路径结构的制品格式。
Recommended Action: 追加 Execute Log 前逐条确认 Test 值是单一路径；执行 node bin/cli.js next . 作为 completion-verification 前的格式门禁。
Evidence: 2026-08-09 的 node bin/cli.js next . 报告多路径 Test file not found；修正为单一路径后该问题消失，全量测试仍为 491 通过、0 失败、5 跳过。
