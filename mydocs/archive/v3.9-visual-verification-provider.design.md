## Technical Design

Selected Option / ADR:
ADR-001：新增独立 `playwright-visual` adapter 和独立视觉 Run 命名空间，而不扩展既有 `playwright-test` 或 e2e Run schema。前者仅处理已批准 fidelity 合同的截图/diff；两类 Provider 共享受控进程、附件复制、路径校验和工作树检测等基础设施。选择理由是视觉结论以场景而非 AC 为单位，不能伪装为现有 e2e Run；独立存储保持既有 gate 行为和历史 Run 完全兼容。

Requirement Traceability:
- 严格 fidelity 合同、批准基线与场景：读取既有 `visual-evidence.json` v1，不改写其来源、批准或基线。
- 可重复截图、diff 和证据：由 `playwright-visual` 将受控 fixture 产生的当前截图与批准基线比较，并写入不可变 Run 与附件。
- 非阻塞默认：未启用合同、direction 合同或未配置视觉 Provider 返回 not-applicable/未配置状态，不进入普通 Plan 或 e2e 门禁。
- 人工控制：基线创建、替换和批准始终在 Provider 外完成；运行过程只读基线。

Impact Scope:
新增 visual Provider capability、项目视觉配置 parser、差异比较器、视觉运行命令、独立 visual run store 与结果白名单投影、visual contract 的运行状态读取、测试 fixture/Reporter 协议、文档和测试。既有 `mydocs/runs/verification/`、`verify run`、`playwright-test`、普通 e2e AC、visual Context 发现和 archive 语义不改变。

Context / Boundary:
视觉合同是人工验收资料，只有场景 id、route/state 描述、视口、来源和批准基线；它不是可执行脚本。项目内视觉配置是唯一可执行映射来源，路径必须位于 Provider package root。fixture 才能处理认证、seed、导航、等待稳定和截图。Provider 只启动固定 adapter/Playwright 流程、读取受控附件并比较；不接受来自 Spec、Context 或 CLI 的 URL、命令、选择器、环境变量或任意测试路径。

Domain Model:
- VisualContract：既有 schema v1 的 fidelity 合同与人工批准基线。
- VisualProvider：`.sdd-verification.json` 中 adapter 为 `playwright-visual` 的受控 Provider。
- VisualExecutionConfig：项目内 `sdd.visual.config.json`，声明 schema、映射、阈值和掩码。
- VisualScenarioBinding：scenario id 到固定 Playwright 文件、标题、项目和 fixture 协议的映射。
- VisualComparison：单场景的基线摘要、当前截图摘要、变化统计、结论和附件引用。
- VisualRun：既有不可变 Run 的版本化 visual 摘要及通用 PASS/FAIL/BLOCKED gate 结论。

Architecture View:
```text
Spec + visual-evidence.json (人工批准场景/基线)
                    │
                    ▼
sdd verify visual --spec <active-spec>
                    │  仅解析受控 Provider 与静态配置
                    ▼
playwright-visual adapter ──► 固定 Playwright test / fixture
                    │                    │
                    │              current screenshot attachment
                    ▼                    ▼
visual comparator ◄── approved baseline in Context
                    │
                    ▼
visual run-store / shared attachment-safety helper / readiness projection
```

Data Model / Schema:
- 保持 `visual-evidence.json` schemaVersion 1 不变。fidelity 场景仍要求批准 baseline，且 baseline realpath 必须在 Context 内。
- 新增项目内 `sdd.visual.config.json` schemaVersion 1。顶层只允许 `schemaVersion`、`scenarios`；每个场景 binding 只允许固定 `testFile`、`testTitle`、`project`、`threshold` 与 `masks`。`testFile` realpath 必须在 packageRoot 内；`project` 必须属于 Provider 白名单；阈值为有限非负比例；每个掩码只能是静态像素矩形 `{x,y,width,height}`，四项均为非负整数且宽高大于零，不能使用选择器或运行时表达式。
- binding key 必须与合同 scenario id 一一对应；合同出现未绑定 id、映射出现重复/越界路径、或测试未产出同 id 的当前截图时，运行 BLOCKED。
- Visual Run 使用独立 schemaVersion 1，存放在 `mydocs/runs/visual/<run-id>/`；其 targets 是 scenarioIds 而非 AC ids。它保留既有通用状态、代码状态、工作区和受控附件格式，并在 workspace 中记录 manifest、lockfile、Playwright config 的摘要；`visual` 摘要记录每场景 id、基线/当前内容摘要、变化像素数/比例、实际掩码和掩盖像素数、阈值、结论、受控附件引用和稳定诊断。不得持久化原始命令、任意环境变量或网页正文。

Data Migration / Backfill:
无历史数据迁移。旧视觉合同继续可 inspect；没有视觉 Provider 的项目不产生视觉 Run。新配置和 visual Run 都是新增、可删除的制品；删除 Provider 配置后仅使后续视觉执行不可用，不影响 `mydocs/runs/verification/` 的历史 e2e Run、`mydocs/runs/visual/` 的历史视觉 Run 或已批准基线。

Interface Contract:
- 新增 `sdd verify visual <project-dir> --spec <path>`；只接受活动 Spec 路径，不提供 URL、命令、截图路径、阈值、掩码或任意测试选择器参数。
- 命令只在 `visual-evidence: required`、fidelity 合同 ready、Provider 与静态映射都有效时启动；direction/未启用合同返回稳定 not-applicable 结果且不写 Run。
- 项目测试通过受控 fixture/Reporter 协议附加 `scenarioId` 和 current screenshot；adapter 使用静态 binding 校验关联，不信任自由文本附件名。
- 基线更新不属于命令接口；只有人工更新 Context 文件和合同批准字段后，新的运行才会读取它。

API Protocol:
沿用现有受控 process gateway 与 Playwright Reporter 握手。新增 `visual-gate` capability 和 visual Reporter event/attachment 元数据；adapter 只从已解析的静态配置派生固定测试文件与 project。每次调用生成 nonce、临时 staging 和不可变 visual run id；事件/附件在写入 visual Run 前进行 schema、路径、大小与脱敏校验。附件安全复制逻辑提取为共享 helper，但 e2e Run 的 schema 与目录不变。

State / Concurrency:
视觉运行使用独立 staging、一次性 visual run id 和 `mydocs/runs/visual/` 原子提交，不修改合同或基线。运行期间记录工作树指纹；若运行改变工作树，仍提交一条无截图附件、带 `WORKTREE_MUTATED` 诊断且 freshness 为 stale 的 BLOCKED Run。相同 Spec 的并发运行允许产生不同 Run，但每个 visual Run 只能原子提交一次，附件内容地址化且拒绝覆盖。

Failure Modes:
- 未启用合同或 direction：not-applicable，不写 Run。
- fidelity 合同、Provider、静态映射、批准基线或 scenario 关联缺失：BLOCKED，给出稳定诊断。
- 可识别的浏览器缺失：在满足最小运行证据条件时提交 BLOCKED Run；早期启动/握手失败按其原始故障分类，不能伪装成浏览器缺失。
- 截图缺失、附件越界、工作树变化、当前截图无法关联、比较器输入无效：BLOCKED。
- 截图与比较成功但任一场景超阈值：FAIL；所有场景在阈值内才 PASS。

Security / Permission:
Provider 只允许 registry 注册的 `playwright-visual` adapter、固定 Node/Playwright 版本范围、受限工作区与 package root、白名单环境和静态配置路径。基线必须经 Context realpath 校验；当前/diff 只从 staging 复制；所有链接逃逸、绝对路径、命令注入、未知 schema 字段、未批准基线和不受控附件一律拒绝。Provider 永不联网、安装浏览器、下载字体、更新基线或写人工批准。

Observability:
CLI 输出 provider id、visual run id、总体结论和每场景稳定诊断码。Visual Run 投影显示基线摘要、变化统计、阈值、附件引用和 provider/config/contract/workspace digest，并对 Provider、adapter manifest、lockfile、package manifest、Playwright config 与代码状态逐项 freshness 校验，支持事后追溯但不泄露敏感环境或任意页面内容；普通 e2e Run 投影不变。

Performance / Capacity:
初期仅 Chromium、声明场景和静态测试文件；按唯一 testFile 去重执行。限制场景数、附件数/大小、diff 图尺寸和诊断长度。视觉比较在本地 staging 完成，超出受控时间或资源预算时 BLOCKED，不自动重试或扩大环境权限。

Compatibility / Rollback:
`playwright-test` 的 manifest、`verify run`、`mydocs/runs/verification/`、既有 Provider config 和 visual-evidence schema v1 保持可用。`playwright-visual` 是 opt-in：移除其 Provider 或 `sdd.visual.config.json` 即停止未来视觉执行；历史 visual Run、附件和合同不被覆盖。若新 visual Run/摘要不可读，visual readiness 失败关闭为 BLOCKED，不回退为 PASS。

Test Strategy:
- Unit：视觉配置、binding、阈值/掩码、差异统计、状态分类、Run visual 摘要白名单与路径/链接拒绝。
- Integration：只接受 ready fidelity；方向/未启用合同不写 Run；Provider、场景、基线、fixture 附件和工作树异常均产生稳定结论。
- E2E：使用仓库内最小 Playwright fixture，在 Chromium 下生成相同截图得到 PASS、修改受控像素得到 FAIL、浏览器不可用得到可审计 BLOCKED。
- Regression：断言普通 `verify run` 与 `playwright-test` 未受影响；旧 visual-evidence schema v1 可继续 inspect；禁止网络、自动批准与任意 CLI/browser 输入。

Risks / Trade-offs:
独立 adapter 增加了配置和 fixture 接入成本，但换来 e2e 与视觉语义隔离、可审计阈值和安全执行边界。像素 diff 的环境敏感性通过固定 Chromium、静态 fixture、显式掩码/阈值和 BLOCKED 语义控制；不以放宽阈值、自动更新快照或下载运行环境来掩盖不稳定。
