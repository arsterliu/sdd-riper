## Design Note

Approach: 采用“协议名稳定、解释层清晰”的方案。JSON、CLI、Run 和源码继续使用 `baseline`；README、GUIDE、TEAM-GUIDE 优先称其为“当前 Spec 的目标 UI 图（baseline）”，REFERENCE 同时保留精确字段定义。Agent 真源在 SKILL 与 `src/core/ai-config-rules.js` 中增加一致的材料可比性判断：若最新设计 PNG 能绑定明确 scenario、route/state、viewport，且尺寸、数据、字体和资源足够稳定，则推荐 `fidelity`；否则推荐 `direction`。旧页面截图明确为可选 Context，不作为严格验证前提。选择记录为 ADR：采纳 Option B，拒绝只改人类文档造成的行为漂移，也拒绝运行时字段重命名带来的迁移成本。
Impact Scope: 修改 README.md、GUIDE.md、REFERENCE.md、TEAM-GUIDE.md、SKILL.md、`src/core/ai-config-rules.js`、`protocols/sdd-riper-one.md`、`protocols/sdd-riper-one-light.md` 与直接相关治理测试；随后通过现有生成器刷新 AGENTS.md、CLAUDE.md、`.cursorrules`、`.github/copilot-instructions.md` 的受控区块。安装验证发现静态 REFERENCE.md 未被 Skill 安装清单复制，因此经用户追加授权，将 `src/commands/install-skill.js` 与对应安装测试纳入最小 BUGFIX。仅做与 v4.10 视觉术语和引导直接相关的增量，不吸收当前工作树中的其他未提交重构。
Interface / Data Impact: 不修改 `visual-evidence.json` schema、`baseline.path/status`、CLI 参数和输出、Visual Run、Provider 配置、错误码或历史制品。对外变化仅是文档与 Agent 指令语义：baseline 被解释为当前 Spec 冻结的目标 UI PNG；旧页面截图可选；`direction` / `fidelity` 推荐依据变得可观察。
Compatibility: 现有 active/archive Spec、Context baseline、digest、Run 和测试夹具保持原样可读，不迁移、不回写。精确参考继续使用 `baseline`，避免用户误以为新增了 `targetImage` 字段。托管文件只刷新 marker 内区块，marker 外项目文本必须保持字节不变；第二次生成必须幂等。Skill 安装仍是静态文件复制，不新增动态生成：仅让安装清单与 package 发布清单一致地包含 REFERENCE.md；不改变额外文件检测或清理语义。
Risks: 最大风险是“目标 UI 图”措辞被误读为 Agent 可自动选择、创建或批准图片，或忽略 fidelity 的尺寸和稳定状态前提；通过人工认可、严格合同、Provider、权限与 stale 规则的并列说明及静态治理测试防止。第二个风险是覆盖当前工作树已有未提交改动；执行时只应用窄补丁，禁止 reset/checkout，并在每步复核 diff。安装 Codex Skill 属于工作区外平台写入，必须单独取得权限。
Test Strategy: 先在 `tests/visual-evidence-guidance.test.js` 与必要治理测试中增加失败断言，覆盖人类指南、SKILL、集中规则源、两份协议和四个生成区块：当前 Spec 目标图定义、旧截图可选、direction/fidelity 可比性、禁止 baseline 管理和人工门禁。实现后运行文档/治理/生成幂等定向测试，再运行 visual contract、diff、readiness、run-store 回归，确认 runtime 行为未变；最后运行全量测试、内部链接检查、`git diff --check` 与安装 Skill fingerprint 检查。
