## Learning Record

Source Spec: mydocs/specs/v1.5-spec-version-policy.md
Trigger: Challenge PASS_WITH_CONCERNS and Execute Log BUGFIX entries.
Observed Problem: 当任务标识允许同一 task-name 出现在多个 version 下时，archive、reopen、new-learning、validate 和 challenge record-result 等命令若先把 `vN.M[.P]-task` 归一化为纯 slug，会把用户显式指定的版本丢掉，并可能把操作写到更高版本的同名任务上。
Root Cause: 命令入口把“用户输入的 spec 引用”与“无版本 slug 查找”混为一谈；旧 helper 只表达“按 slug 找最高版本”，没有表达“按 version + task-name 精确查找”的语义。
Decision Rule: 凡是 CLI 接收 spec-name、--name、--spec 或其他任务引用，必须先判断输入是否包含 `vN.M-task` 或 `vN.M.P-task`；包含版本时必须按 `version + task-name` 精确解析，不得先 normalize 成 slug；只有未包含版本的旧式 slug 才允许回退到最高版本兼容行为。
Applies When: Spec 命名允许两段/三段 version，且同一 task-name 可能跨 version 并存；命令会移动、重开、写入门禁、绑定 Learning 或校验指定 Spec。
Does Not Apply When: 命令明确只操作当前 latest active spec，且没有接收任何显式 spec 引用参数。
Recommended Action: 使用公共解析函数（如 `parseSpecRef` / `findSourceSpecByRef`）统一处理 spec 引用；为每个写入型命令补跨版本同名任务回归测试，断言显式版本只影响目标 Spec。
Evidence: tests/commands.test.js 覆盖 archive/reopen/new-learning/challenge record-result 的 `v1.3.6-tri` 与 `v1.4-tri` 并存场景；`node --test tests\*.test.js` 通过 130 项。
