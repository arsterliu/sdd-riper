## Technical Design

Selected Option / ADR:
采用单一项目级目录锁的 fail-fast 初始化事务。只读 preflight 在锁外；单次获取 `.sdd-verification.json.lock` 成功后执行完整读改写，任何并发调用立即失败并由调用者稍后重试。
Requirement Traceability:
AC-001 对应单锁与幂等重试；AC-002 对应事务失败释放和原配置保护；AC-003 对应解锁失败与双错误优先级；AC-004 对应删除双锁语义并同步制品。
Impact Scope:
修改 `src/commands/verify.js` init 分支、`tests/verification-cli.test.js`、GUIDE 和当前 SDD 制品。`verify run` 与 `src/verification/` 合同保持不变。
Context / Boundary:
消费项目允许多个调用者尝试 init，但 SDD 不支持同一项目并发执行。互斥粒度是整个 `.sdd-verification.json`，不是 Provider。
Domain Model:
`InitLock` 仅表示项目配置事务所有权，路径固定为 `.sdd-verification.json.lock`；不存在 ProviderLock、等待者或合并者状态。
Architecture View:
`静态 preflight（只读 workspace/package/Playwright config，不读取共享配置） → try mkdir project lock → load current .sdd-verification.json → replace provider → validate → write temp → atomic rename → remove lock → configured`。锁冲突直接走 `INIT_LOCKED`。
Data Model / Schema:
`.sdd-verification.json` Schema 不变；锁是项目根目录临时空目录，不进入配置或持久化制品。
Data Migration / Backfill:
无需配置迁移。升级后遗留 `.sdd-verification.<provider>.lock` 不再被运行时读取；用户可在确认无旧版 init 进程后人工清理。
Interface Contract:
CLI 参数不变。并发时稳定输出 `[SDD_VERIFY_INIT_LOCKED]`、exit 2；不区分 Provider、不等待、不合并。成功仅在写入和解锁均完成后输出 configured / exit 0。
API Protocol:
无新协议。错误码保留 `INIT_LOCKED` 与 `INIT_UNLOCK_FAILED`，删除 `INIT_CONFLICT`。
State / Concurrency:
preflight 不持锁，且不得读取或缓存 `.sdd-verification.json`。事务锁使用一次 `mkdirSync`：成功即独占，`EEXIST` 立即 `INIT_LOCKED`。共享配置的读取、解析、修改、校验、临时文件写入和 rename 全部只在持锁后执行；所有事务结束都尝试解锁。调用者负责稍后重试。
Failure Modes:
`INIT_LOCKED`：已有项目锁，立即 exit 2，并提示确认无活动 init 后再人工删除空锁目录；禁止按时间自动清理。`INIT_UNLOCK_FAILED`：配置可能已经写入，exit 2、不得输出 configured，并提示先检查配置。主事务错误与解锁错误同时发生时，解锁错误为控制结果并附带原始事务 code/message。其他 preflight/事务错误保持原 code。
Security / Permission:
单锁 fail-closed，拒绝自动清理陈旧锁，避免误删仍有效的互斥。临时文件 `wx` 与原子 rename 防止部分 JSON；锁确保读改写不会并发交错。
Observability:
`INIT_LOCKED` 明确“不支持同项目并发，请稍后重试”；持续出现时给人工恢复步骤。`INIT_UNLOCK_FAILED` 明确“配置可能已写入，请先检查 `.sdd-verification.json`”。
Performance / Capacity:
init 低频且不支持并发；锁外 preflight 缩短持锁时间。无等待、轮询、退避或自动重试。
Compatibility / Rollback:
Provider 配置与 CLI 参数兼容；并发成功语义有意收缩。删除 Provider 锁与 `INIT_CONFLICT`，不提供 alias 或 fallback。
Test Strategy:
测试严格收缩为六类：正常与幂等初始化、锁存在 fail-fast、事务失败且释放锁并保护原配置、解锁单独失败稳定诊断、事务与解锁双失败时解锁错误优先且保留原错误、失败后重试成功。使用真实 CLI 子进程和受控 fs 故障注入；再运行关联与全量回归。
Risks / Trade-offs:
不同 Provider 的同时 init 也会失败，降低并发吞吐但显著减少状态空间。写入成功而解锁失败存在不确定提交感知，通过稳定诊断和“先检查配置”恢复指引处理。
