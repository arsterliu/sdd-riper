## Technical Design

Selected Option / ADR: 采用 managed block upsert。AI 配置文件不存在时创建文件；存在时只追加或替换 `<!-- sdd-riper:start -->` 到 `<!-- sdd-riper:end -->` 之间的 SDD-RIPER 自管内容，不覆盖用户已有规则。
Requirement Traceability: AC-001 覆盖新文件创建；AC-002 覆盖已有文件追加；AC-003 覆盖幂等刷新；AC-004 覆盖 `--force` 不覆盖用户内容。
Impact Scope: 修改 `src/commands/_gen-ai-configs.js` 的写入策略和生成文案；补充 `tests/commands.test.js` 初始化行为测试。`src/commands/init.js` 可继续传入 `force`，但 AI 配置写入函数不再把 force 解释为全量覆盖。
Context / Boundary: 本次不改变 SDD Spec/Design/Execute Log 初始化目录，也不新增危险覆盖参数。生成内容保持 thin bootstrap，不复制完整 `sdd-riper` skill、README 或 GUIDE。
Domain Model: AI config file = 用户内容 + 可选 SDD-RIPER managed block。Managed block 是 SDD-RIPER 唯一可自动更新的区域。
Architecture View: `init.run` 调用 `genAiConfigs.run(projectDir, mode, force)`；生成器为每个目标文件构造 block 内容并调用 upsert helper。helper 负责判断 create/append/update，并返回 created/skipped/updated/merged 计数。
Data Model / Schema: Marker 常量为 `<!-- sdd-riper:start -->` 和 `<!-- sdd-riper:end -->`。Block 内包含标题、skill/CLI 入口、hard rules、docs root 与 mode。输出文件仍为 UTF-8 Markdown/文本。
Data Migration / Backfill: 已有无 marker 文件在下一次 init 时追加 marker block；已有 marker 文件在下一次 init 时刷新。无需批量迁移。
Interface Contract: CLI 命令不变。`sdd init <dir>` 对 AI 配置文件执行 create/append/update；`sdd init <dir> --force` 对 `.sdd-config` 仍按既有 force 行为处理，但 AI 配置文件仅强制刷新 managed block，不全量覆盖。
API Protocol: 无外部 API 变化。
State / Concurrency: 单进程同步文件写入；如果并发 init 同一目录，行为与现有文件写入风险一致，不额外处理锁。
Failure Modes: Marker 不完整时为避免误删用户内容，应按无完整 block 处理并追加新 block。若写入失败，Node 文件系统异常按现有 CLI 行为抛出。
Security / Permission: 保护用户已有规则，降低误删/覆盖风险；不引入外部网络或权限扩大。
Observability: CLI 输出区分 `[CREATE]`、`[MERGE]`、`[UPDATE]`、`[SKIP]`，便于用户知道发生了追加还是刷新。
Performance / Capacity: 文件很小，同步字符串替换成本可忽略。
Compatibility / Rollback: 如需回滚，可恢复旧的 `writeConfig` 全量写入逻辑。新 marker block 对现有 agent 工具是普通注释+Markdown 内容，向后兼容。
Test Strategy: 在 `tests/commands.test.js` 增加 init 相关单元测试，覆盖新建、已有无 marker、已有 marker、force 不覆盖和幂等计数/内容断言。运行 `npm test`。 
Risks / Trade-offs: Marker block 会在已有文件末尾增加少量内容；但相比覆盖用户文件更安全。生成的 thin bootstrap 信息少于旧版，需要依赖 skill/CLI 作为流程权威，这是符合本次产品边界的取舍。
