## Technical Design

Selected Option / ADR: ADR-001 — 最小共享 Gate Facts。新增内部事实收集层，但不将 `validate` 完全委托给 `spec-state`，也不把时态运行证据并入静态 Governance Contract。

Requirement Traceability:
- AC-001：共享事实层由 `spec-state` 和 `validate` 分别消费，职责不倒置。
- AC-002：普通 validate 的 warning/advisory 与 archive-ready blocker 显式分支。
- AC-003：同一 evaluation 内只产生一次 Provider readiness inspection；新 evaluation 重新检查。
- AC-004：活动、显式 archive 与缺省 location 的兼容分支保持既有 fail-closed 行为。
- AC-005：所有公开 CLI 文本、错误码和命令语义保持兼容。

Impact Scope: 主要修改 `src/core/spec-state.js`、`src/commands/validate.js` 和新增的内部 gate-facts 模块；按需调整 `src/verification/readiness.js` 的调用边界，并新增/扩展 state matrix、命令和 gate-facts 测试。不会修改 Console/Web、Visual、Provider 执行、Run Store、path 基础设施或 fixture 体系。

Context / Boundary: Gate Facts 是一次制品评估的内部只读事实，不是公共 API、持久化 schema 或跨请求缓存。它只描述当前 snapshot、位置、必需制品状态和可选的当次 readiness 结果；命令文案、warning 严重度、exit code 和 UI 投影仍属于各消费者。

Domain Model: `spec-state` 是 workflow gate/router 的权威消费者；`validate` 是制品诊断消费者。Provider readiness 是有时效性的外部证据，活动制品必须 fail-closed，只有显式 archive 位置可以走既有兼容分支。

Architecture View:
```text
Spec snapshot + project inputs
            |
            v
  internal Gate Facts collector --(at most one)--> Provider readiness inspection
            |                                      
      +-----+-----+
      |           |
      v           v
spec-state     validate
route/blocker  normal diagnostics or archive-ready presentation
      |
      v
next / status / resume / index consumers
```
`spec-state` 从 Gate Facts 派生 phase、next action、challenge target 和权威 workflow blockers。`validate` 用相同事实保留普通模式的 warning/advisory；仅 archive-ready 汇入权威 blocker，且保留既有输出顺序。

Data Model / Schema: 内部 `GateFacts` 是不可变的短生命周期对象，包含 `location`、`mode`、Research/Design/Acceptance/Plan/Completion/AC Coverage 的规范化结果，以及可选 `providerReadiness`。其字段不写入 Spec/Run，不导出为 CLI JSON 契约，不跨 evaluation 保存。

Data Migration / Backfill: 不迁移数据。历史 snapshot 继续由现有 reader 解析；没有 `location` 的调用方维持活动制品路径。显式 `location === archive` 的现有兼容规则原样保留。

Interface Contract: 新模块仅暴露内部收集/派生接口，输入为当前 snapshot、projectDir 和当次依赖，输出为冻结的事实值。collector 不负责输出文本，不接受或保存跨调用 cache，不改变 readiness adapter 的错误形状。消费者不得根据缺省字段推断 archive。

API Protocol: 不新增或删除 CLI 命令、参数、JSON schema、标签、错误码或顺序。普通 `validate` 继续报告制品级 warning；`validate --archive-ready` 继续以权威 workflow blocker 决定归档结果。

State / Concurrency: 每次 `specState.evaluate()` 创建独立的 evaluation context，并将唯一一次 readiness inspection 传给 blocker 和 facts 派生。context 在函数返回后丢弃；并发或下一次 evaluate 不共享 freshness，避免时态证据陈旧。

Failure Modes: readiness 缺 Provider、配置/运行异常、覆盖不足或 freshness 不足时，活动制品继续 fail-closed。collector 不吞掉或降级异常；`validate` 仍按当前命令模式映射为既有诊断或 archive-ready 失败。若共享事实不可构造，保留现有错误路径而非推断通过。

Security / Permission: 保留 Provider allowlist、Workspace trust、历史 artifact 读取和 archive 显式位置边界。不得通过缓存、缺省 location 或普通 warning 分支绕过活动制品的 Provider readiness。

Observability: 不新增面向用户的日志或 telemetry；维持当前 CLI 输出。测试使用可计数的 readiness double 证明同次调用次数和跨 evaluation 新鲜度。

Performance / Capacity: 目标是消除每次 evaluation 内确定的一次重复 readiness inspection。不得以长期缓存换取性能；调用次数减少不能改变 Run freshness 的可见性。

Compatibility / Rollback: 以命令回归和状态矩阵冻结普通/归档验证分支、活动/归档/缺省 location 和历史 reader 行为。若出现输出或 gate 回归，可撤回 Gate Facts 消费并恢复原调用路径，不需要数据回滚。

Test Strategy: 先在 `tests/workflow-gate-facts.test.js` 建立 readiness 单次调用、重新 evaluation 和 facts 一致性的红灯测试；扩展 `tests/commands.test.js` 保护普通 warning 与 archive-ready 输出；扩展 `tests/state-matrix.test.js` 保护 archive/active/缺省 location。实现后运行相关测试、`npm.cmd test` 与 `git diff --check`。

Risks / Trade-offs: 新增内部模型会增加一层结构，但其职责严格限于事实收集，换取消除双权威和重复 I/O。把更多诊断下沉会降低重复更多，但会破坏普通 validate 的兼容语义，故明确拒绝。
