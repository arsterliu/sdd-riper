## Summary
为 SDD 增加自检命令 `sdd doctor`，静态校验 SKILL.md / INTEGRATIONS.md / install-skill 之间的接线一致性，在发布前捕获悬空引用（D1 同类漂移）。lite 模式，纯新增、只读、向后兼容。

## Intake
requirement: 新增 sdd doctor 命令：对 SDD 自身做接线一致性自检——检查 SKILL.md / INTEGRATIONS.md 引用的 vendored 与 protocols 路径是否都存在、INTEGRATIONS 声明的触点是否都在 SKILL.md 里，发现悬空引用即报错并以非零退出，防止 D1 式文档/资源漂移。
goal: 让 SDD 能自检自身接线，杜绝悬空引用进入发布

## Requirement Review
- 歧义：「接线一致性」边界——本次锁定 SKILL.md / INTEGRATIONS.md / install-skill.js 三者间的引用，不扩展到 README/GUIDE 的所有 .md 链接（避免范围膨胀）。
- 隐含假设：检查基于静态文本扫描，doctor 自身不执行任何被检查的脚本。
- 风险：正则提取引用易漏报/误报；需用明确的路径前缀模式并配测试。
- 外部依赖：无新增依赖（commander 已在）。

## Findings
- `install-skill.js` 的 `COPY_ENTRIES` 是固定清单（含 `protocols`、`vendored`），决定 agent 环境能拿到哪些文件；SKILL.md 引用的路径若不在被复制目录内，agent 侧会悬空（D1 同类）。
- SKILL.md 引用 7 个 `vendored/superpowers/<skill>/` 与 `protocols/adr.md`、`protocols/subagent-dispatch.md`。
- INTEGRATIONS.md 触点表声明 7 行 `vendored/superpowers/*` 路径与对应 skill。
- D1 历史问题正是「INTEGRATIONS 宣称的接线 SKILL 未实现 / 引用路径不存在」——doctor 应能在发布前逮到这类漂移。

## Open Questions
- 输出格式与退出码：逐项 PASS/FAIL 文本 + 有 FAIL 即退出码 1（已在 Confirmed Requirement 固化）。
- 是否检查 README/GUIDE 的 .md 链接：本次不做，列入后续。

## Assumptions
- doctor 在包根（与 `install-skill.js` 的 `PACKAGE_ROOT` 同源）运行，读取仓库内文件。
- 引用路径以 `vendored/superpowers/...` 和 `protocols/...` 这类明确前缀出现，可用正则稳定提取。

## Confirmed Requirement
新增 `sdd doctor [project-dir]`，对 SDD 自身接线做静态自检：
1. SKILL.md 引用的 `vendored/superpowers/*` 与 `protocols/*` 路径都存在；
2. INTEGRATIONS.md 触点表的 `vendored/superpowers/*` 路径都存在，且对应 skill 名在 SKILL.md 出现；
3. SKILL.md / INTEGRATIONS.md 引用的顶层目录（protocols、vendored）都在 install-skill 的 `COPY_ENTRIES` 内（防 agent 环境悬空）。
任一检查失败：打印失败项并以退出码 1 结束；全部通过：打印 OK 并退出 0。

## Innovate Options
- 选项 A（选中）：独立 `src/commands/doctor.js` 命令。职责单一、可单独在 CI / 发布前调用、不干扰现有命令。
- 选项 B（否决）：并入 `sdd status`。否决理由：status 面向单个项目的产物健康度，doctor 面向「SDD 自身发布物一致性」，受众与触发时机不同，混合会稀释两者语义。
