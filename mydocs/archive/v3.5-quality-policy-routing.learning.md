## Learning Record

Source Spec: mydocs/specs/v3.5-quality-policy-routing.md
Trigger: Execute Log 中两次 BUGFIX；独立 Challenge 首次返回 FAIL_CODE，后续安全审计又发现默认 selector 的读取顺序与项目内链接兼容问题。
Observed Problem: quality plan 的 `--spec` 可指向 `<docs-root>/specs` 外的伪造 Spec；修复显式路径后，默认选择仍可能在 containment 前读取外部目录链接候选的 frontmatter，且将逻辑与真实根混用会误拒绝解析到项目内的 docs root 链接。
Root Cause: 把通用 selector 当作安全解析器使用；它为排序读取候选 frontmatter，而 Command 边界尚未验证候选的 lexical 与 realpath。后续只用一个 real root 比较逻辑输入路径，忽略了允许项目内链接时“逻辑根”和“真实根”必须分别判断的事实。
Decision Rule: 任何接收或默认选择 Spec、Profile 或其他任务制品路径的命令，必须在首次内容读取前分别确认逻辑路径位于预期逻辑根内、解析后的真实路径位于对应真实根内。默认枚举也必须逐个验证候选再读取元数据；发现任一可选候选逃逸时 fail-closed。允许链接时必须成对维护 lexical root 与 realpath root，不能用其中一个替代另一个。
Applies When: 新增或修改含 `--spec`、`--name`、默认“最新制品”选择、目录扫描、frontmatter 排序或任何会读取项目制品的本地 CLI/API 时。
Does Not Apply When: 路径不是用户或项目制品可控的输入，且内容在同一受控事务中刚被创建、无链接或重解析风险；即使如此，跨越信任边界时仍应重新评估 containment。
Recommended Action: 在 Command 边界实现安全选择器或为通用选择器提供读取前 guard；测试至少覆盖相对 traversal、绝对外部路径、外部 file link、外部 directory link 下的默认选择、以及解析到项目内目标的 docs root/specs link。测试应直接断言外部内容没有被读取，而不只断言最终错误码。
Evidence: tests/quality-cli.test.js 中的 traversal/absolute 路径、显式 file symlink、默认 directory junction “读取前拒绝”与项目内 docs-root link 回归；两次 Execute Log BUGFIX；最终独立 Challenge PASS_WITH_CONCERNS（subagent:v35_archive_challenge），其 concern 已由本 Learning Record 回应。
