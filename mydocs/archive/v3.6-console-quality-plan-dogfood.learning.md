## Learning Record

Source Spec:
mydocs/specs/v3.6-console-quality-plan-dogfood.md
Trigger:
执行期间发生 BUGFIX：浏览器截图与正式 E2E 断言发现 1280px 常见桌面宽度下态势板主视区被压缩。
Observed Problem:
项目轨、Profile 摘要、两列 workspace 和固定高度同时存在时，Spec 态势板只剩 544px 可用宽度与不足 150px 的可见高度；列标题和多任务比较不再是首屏主视图，违背方案 A 的信息优先级。
Root Cause:
响应式切换仅以整个 viewport 的 1180px 为阈值，而不是以态势板所在子列的实际可用宽度为阈值。1280px viewport 扣除 340px 项目轨后，仍错误保持“态势板 + 详情”两列，导致主视图落入局部滚动的最小宽度以下。
Decision Rule:
当一个页面同时保留固定项目轨和宽列态势板时，响应式断点必须依据主视图的剩余空间设定；主视图不足可读宽度时优先将详情移到下方，而不是继续压缩表格列或状态卡。对需要横向比较的态势板，先保证主视图可读，再让详情采用顺序堆叠。
Applies When:
本地 Console、管理后台或工作流看板在同一屏幕中同时存在固定侧栏、宽列清单和辅助详情，并且用户优先任务是横向比较全量状态时。
Does Not Apply When:
详情本身是首要工作对象、没有固定侧栏、或者主视图天然是单列卡片而非宽列比较表时；此时应按对应任务的阅读优先级单独设计断点。
Recommended Action:
先用实际目标 viewport 的浏览器断言记录主视图 clientWidth / clientHeight，再以现有单列布局作为最小修复路径调整断点；修复后重新执行正式 Provider E2E，并保存截图附件，不以静态 CSS 检查替代可用性证据。
Evidence:
正式 Run `20260729133819082-945e344fe066` 在 1280px 断言中记录态势板宽度为 544px 并 FAIL；Debug 后将既有单列断点从 1180px 调整到 1680px，正式 Run `20260729133918680-1082c6adf109` fresh PASS，包含截图附件。

## Supplemental Learning

Trigger:
独立 Challenge 在已通过功能与 E2E 的 Console 投影中发现父目录相对路径泄漏。
Observed Problem:
阻塞 Quality Plan 的 `source.profile.revision`、`declaredAffectedUnits` 或 `effectiveAffectedUnits` 可以保留 `../` 或 `..\\` 输入；若只使用面向诊断文本的绝对路径脱敏器，浏览器 JSON 仍会得到原始相对路径。
Root Cause:
将“消息脱敏”误当成“路径安全投影”。旧 sanitizer 仅识别绝对 POSIX / Windows 路径，未识别父目录相对路径；而 Quality 的阻塞分支有意保留 source 以供只读解释。
Decision Rule:
任何可能进入浏览器 JSON 的自由文本或路径样字符串，都必须在服务器投影边界拒绝或替换绝对路径和父目录相对路径；不得假设上游被阻塞就不含用户可控文本。对于共享 diagnostics / evidence sanitizer，补充新路径模式时必须同时执行其原有 Console projection 回归，确保脱敏增强不改变 gate 身份或合并语义。
Applies When:
Console、API read model、日志摘要或验证证据把原始 Spec、配置、异常或 planner source 的字段投影给浏览器时。
Does Not Apply When:
字段从受限枚举或已验证的不可变内部标识生成，且不会携带用户提供的路径片段；即便如此，仍应在边界保持白名单投影。
Recommended Action:
先以真实投影函数写入 `../` 和 `..\\` 的失败测试，确认泄漏路径；再在最窄的共享 presentation sanitizer 中加入脱敏规则，随后运行受影响投影测试、完整回归和正式 Provider E2E。
Evidence:
独立 reviewer `subagent:challenge_review_v36` 于 2026-07-30 记录 FAIL_CODE。修复前 `tests/console-projection.test.js` 的新场景显示父目录路径原样进入 `result.source`；修复后聚焦 22/22 PASS、全量 350 tests 通过，并由正式 Run `20260730024318336-db2a8b77b448` 复验。
